## 1. 核心理念：释放人与物的价值

**物间的核心理念是「释放人与物的价值」。**

物间以人们已经拥有、使用、共同使用或与其有实际联系的实体物品为起点，借助 AI 理解物品的知识、能力与状态，理解人的需求、习惯、经历和关系，帮助人们**兑现、创造、延续和传递**物品的价值。

物间同时关注：

- **物如何更好地服务人：** 用好原有功能，发现潜在用途，探索和实现新的能力。
- **人如何让物更符合自己：** 让物品融入个人需求、使用方式、创意、习惯和生活经历，成为「我想要的样子」。
- **人如何通过物连接其他人：** 家庭共同使用、协作和关怀；赠送、共享、借用和故事传递，让物品价值在人与人之间继续发挥作用。

**人与人的价值能够由这一理念自然延伸出来，但物间的产品边界是「通过物品、物品经历或共同物品任务所实现的人际价值」**；不据此扩展为通用聊天、泛社交平台或全面的人际关系管理。

物间追求的是**有效价值**，不以更多使用次数、更多 App 打开次数、更多消费、更多数据录入或更长聊天作为价值本身。一件急救物品长期不用、关键时刻能找到并正确使用，同样体现价值。

**一句贯穿产品的工作表述：**

> 以物为起点理解物与人，根据人的真实需求和关系发现价值机会，借助 AI、知识与工具实现价值，并将实际使用、创造、经历和传递中的可靠反馈积累下来。

### 1.1 坚持的设计取向

1. **已有物品优先：** 先发掘用户已有物品能够实现的目标、用途和组合；确有缺口时再考虑新增购买。购物行为不是产品存在的目的。
2. **人先有目标：** AI 不为了提高活跃度替用户制造任务。用户可以从现实目标开始，也可以从一件物品或一段经历开始。
3. **低管理负担：** 不要求先录入完整库存才能得到帮助；状态缺失时只问真正影响当前任务的关键问题，允许逐渐深化管理。
4. **理解人服务于用好物；理解物服务于人：** 二者相互促进；不能用购买记录或一次表达武断定义用户。
5. **价值有结果：** 模型提出建议、系统生成卡片、工具返回成功都不自动等于价值实现。应尽量保留用户确认、行动证据及实际效果；情感记录本身也可以是一种有效结果。
6. **真实与可控：** 区分官方资料、用户报告、模型推测、真实设备观察、模拟实验；涉及跨人共享、实际控制、敏感操作必须按权限处理。

## 2. 稳定的认知主线：理解物 → 物与物 → 物与人 → 人与人

这是**产品认识现实世界的逻辑**，不是用户必须按顺序经历的四个页面、四个 Agent 或四个开发阶段。

| 认知层次 | 要理解的核心问题 | 典型的实际价值 |
| --- | --- | --- |
| **① 理解物** | 这件物品是什么？什么型号/版本？具有哪些功能、材料、结构、状态、约束以及尚待发现的能力？ | 正确使用、指导、排障、维护；为后续创造提供可靠基础 |
| **② 物与物** | 物品之间如何组合、替代、互补、协作？怎样发现原本没有想到的可能性？ | 用已有资源完成目标、创造组合新用途、减少遗漏与重复购买 |
| **③ 物与人** | 这件物品对谁有价值？这个人的需求、偏好、技能、经历与具体情境是什么？怎样把物品变成他想要的样子？ | 个人化使用、创造性改造、数字分身、生活记录、个人意义 |
| **④ 人与人** | 人如何围绕同一件物品共享知识、资源、责任、帮助、经历和心意？ | 家庭协作、长辈关怀、赠礼流转、故事与关系价值传递 |

**双向理解：**

- **从物理解人：** 物品、使用经历和自愿记录可能提供理解用户的线索；必须保留已确认事实与推断的区别。
- **从人重新理解物：** 知道用户具体目标后，才能判断一件物品的哪些功能、组合或改造对他真正有用。
- **从物连接人与人：** 同一件物品可涉及购买者、拥有者、使用者、维护者、家人、赠送者和接收者，其知识、服务和故事需要按关系及授权延续。

四个认知层次彼此贯通、持续互相反馈；不会将一个用户请求强行限定在单一层次。

## 3. 四种价值释放方式：兑现、创造、延续、传递

沿用早期《物品智能服务｜产品说明书 V0.1》的价值逻辑，并纳入后续对创造性改造、数字分身和情感意义的深化讨论。

**它们是解释功能为什么存在的四种价值释放方式，不是互斥的价值分层、固定开发顺序或四个导航。** 同一功能可服务多种价值，不能为追求分类整齐而割裂真实任务。

| 价值方式 | 核心含义 | 代表功能 | 如何判断价值是否真正发生 |
| --- | --- | --- | --- |
| **兑现已有价值** | 更充分地使用物品原本具备的功能、知识及服务 | 物品识别、说明书、问答、分步操作、排障、场景化使用 | 用户正确使用、解决问题、完成实际目标 |
| **发现与创造新价值** | 发掘未使用的功能，发现物与物组合、替代用途，探索并实现用户期待的新功能 | 创意引擎、跨物品组合、个性化配置、REA 与可授权设备接口、实践反馈 | 方案新颖且有用；条件可核验；在可执行时形成真实成果 |
| **延续、保护和积累价值** | 让物品更长期可用，减少遗忘损耗；让个人使用方式、经验、故事和意义随时间积累 | 维护与生命周期、轻量提醒、长期 Context、个人习惯、数字分身、图文故事与记忆 | 物品持续服务用户；经验可复用；个人意义被真实保存或使用 |
| **共享与传递价值** | 让物品、知识、使用能力、帮助与精选经历在不同人之间继续发挥作用 | 家庭共享、协作任务、长辈关怀、借用、赠礼、社交故事传递 | 另一位使用者获得了有用的帮助、资源或意义；协作/传递真实完成 |

### 3.1 必须保留的交叉关系

- **「创造它」也是「成为我的」。** 通过 REA、软件、配件或实物组合，把物品改造为符合个人需要的样子，既是创造价值，也是深度个人化。
- **数字分身不是单独一类价值。** 它是物品身份、个人表达、获准记忆、交互与行动能力的综合形式，可以服务兑现、创造、积累及家庭传递。
- **生活故事不是脱离物品的内容平台。** 故事既可保留个人情感意义，也可以成为理解人、改进服务、连接家人及赠礼的授权 Context。
- **家庭管理不是仅仅管理任务。** 其核心是让物品知识、使用能力与关怀在不同人之间有效流转。
- **维护管理是支撑价值的机制。** 不鼓励为了维护准确库存而增加用户负担。

## 4. 统一产品机制：多种入口，共同的价值实现循环

物间应支持用户从**现实需求、具体物品、创意改造、生活记录、家庭事务、赠送分享**等不同情境自然开始；这里列的是**用户意图类型**，不预设六个一级导航。

每个意图通过共享的任务和物品系统进入同一条可接续的价值实现循环：

```text
用户提出意图或在具体情境中触发
        ↓
确认相关的人、物品、目标和权限
        ↓
取得必要的物品知识、人的 Context、关系与实际状态
        ↓
识别当前价值机会，选择匹配的服务/创造/协作方式
        ↓
调用专业能力、知识或工具；必要时询问与授权
        ↓
执行、展示可追溯结果，接收用户或设备验证
        ↓
将确实发生、可纠正且有权限保存的经验与经历返回 Context
        ↓
为下一次使用、创造、关怀与传递提供更可靠的基础
```

**重要：** 这是统一的逻辑闭环，而非每个简单问题都必须走完整 Agent 循环。单物品问答可以走快速、短路径；需要多步创造、设备探索、授权或跨用户协作时才进入长任务。

### 4.1 典型跨功能旅程

| 旅程 | 从哪里进入 | 连续发生的事情 | 释放的价值 |
| --- | --- | --- | --- |
| **陌生物品初次使用** | 拍照、扫码、输入型号、上传说明书 | 确认具体型号 → 获得可靠使用指导 → 用户反馈 → 记录必要经验 | 兑现 + 延续 |
| **已有物品完成现实目标** | 「周末去烧烤」「我想做拼豆」 | 知道目标与约束 → 寻找已有物品 → 组合/替代/缺口判断 → 完成准备 | 兑现 + 创造 |
| **旧物变成我想要的样子** | 物品详情或自然语言创意 | 理解物品与个人需求 → 寻找新用途/接口/组合 → 验证条件 → 授权实践 → 记录结果 | 创造 + 个人化 + 延续 |
| **物品的数字分身** | 具体物品或自由对话 | 建立自愿选择的形象与表达 → 使用真实物品知识及获准经历 → 帮助操作/交互 → 随经验变化 | 兑现 + 创造 + 个人意义 |
| **生活中的一段故事** | 记录文字、照片、经历 | 记录真实事件 → 关联物品与人物 → 决定是否供记忆检索 → 后续适当使用 | 积累个人意义，必要时支持传递 |
| **家人一起用** | 家庭空间、物品详情或求助对话 | 授权共享物品 → 家人获得对应指导 → 创建/接手事项 → 反馈与确认 | 兑现 + 传递 + 关怀 |
| **有故事的礼物** | 物品详情或赠送入口 | 选择物品与愿意传递的故事 → 收礼预览与确认 → 实物取得/认领 → 新经历独立积累 | 传递 + 情感意义延续 |

一项任务可以跨多个入口和页面进行，但不能因切换页面而失去同一任务、物品或必要 Context；相关服务必须遵守当前用户权限。

## 5. 完整功能体系：功能为价值服务

以下是**应保留的完整产品能力范围**；功能范围 ≠ 本轮交付承诺 ≠ 已上线清单。设计新功能须明确它服务什么用户需求、对应什么价值，以及如何与现有能力衔接。

| 能力域 | 产品应当提供什么 | 价值重点及连通要求 |
| --- | --- | --- |
| **F1 物品进入与身份** | 手动录入、照片/条码辅助、商品链接和说明书、可授权订单信息候选导入；确认型号、版本、持有状态、位置与归属 | 作为所有价值的起点；购买记录≠实际持有；商品通用知识≠个人物品状态 |
| **F2 单物品理解与服务** | 准确说明书、规格与功能问答；初次使用、配置、操作、故障排查、保养售后、步骤续接；图片/语音等适合的交互 | 兑现已有价值；答案有依据，用户能完成任务；指导失败能够接续或交接 |
| **F3 目标驱动与物与物组合** | 围绕真实生活目标调动已有资源、寻找互补与替代方案、判断缺口、形成可执行计划 | 兑现+创造；不等同随意生成跨品类创意；首先真实满足用户目标 |
| **F4 创造力与新玩法** | 探索单物品/多物品新用途；社区案例、原理类比、约束核验、选择后深化、真实尝试与反馈 | 创造价值；重视新颖性、实用性、实现条件和实际反馈，不能靠生成数量证明质量 |
| **F5 设备探索与改造** | 官方接口/协议优先；有授权的软件研究可考虑 REA；设备能力发现、注册、适配、权限、调用与状态回读 | 创造+个人化；软件逆向线索≠实物能力已获验证；对非联网物品不虚构远程控制 |
| **F6 个性化与数字分身** | 个人偏好及习惯、物品特定形象与表达、基于真实知识的对话、获准的关系记忆、工具支持下的行动能力 | 让物品成为「我的」；不把分身简化为昵称和语气，也不强制每件物品独立运行 Agent |
| **F7 故事与生活记忆** | 文字、照片、事件、物品及人物关联；故事章节、记忆确认/纠正/遗忘、可选的后续回忆与分享 | 积累个人意义；故事是理解人的来源之一，但不将推断擅自变成事实 |
| **F8 维护、生命周期与购后服务** | 到货/首次使用衔接、保修与售后凭证、物品状态、维护与耗材、低打扰提醒、退出与流转 | 延续和保护价值；深度管理为可选能力；外部数据接入须有合法接口及授权 |
| **F9 家庭空间与关怀协作** | 个人/家庭物品空间、身份与角色、按件授权、共享知识、任务分工、处理进度、长辈简化操作、家人求助 | 人与人之间通过物的协作和照顾；创建任务≠对方已读≠真实完成 |
| **F10 社交、赠礼与流转** | 赠送/借用/转交、选择性寄语与故事快照、收礼预览、独立认领、归属与后续经历、授权可见范围 | 传递价值；私人故事与记忆不随实物默认转让；非通用社交网络 |
| **F11 统一 Agent 与任务能力** | 统一入口感知、目标识别、任务状态与恢复、相关知识和工具选择、分阶段结果展示、授权与验证、反馈积累 | 贯穿全部价值；简单任务不能被复杂工作流拖慢 |
| **F12 数据、身份、权限与可信度** | 物品/人/关系/任务/能力/经历的一致身份；来源与证据状态；真实多账号隔离；可纠正、可撤销、可追溯 | 所有功能共同的基础，直接影响长期可靠性和人与人之间的信任 |

### 5.1 对数字分身、REA、创造力、家庭与社交的明确边界

- **数字分身：** 用户能感知具体物品的数字身份与个性，但内部不要求每件物品都有独立 Agent 进程。核心是知识、记忆、交互与能力的实际统一。
- **创造力：** 包含新用途、组合与改造；用户能从想法继续进入条件核验和可能的实际行动。未经验证的物理机制、接口与材料条件必须保留不确定性。
- **REA：** 是对有授权的软件目标开展分析和能力探索的候选工具之一，不是通用 IoT 协议，也不等于任何实体设备都可控制。
- **家庭：** 用户之间存在多种角色和按件授权；家庭管理员不默认获得所有私人购买记录、故事或记忆。
- **社交：** 首先围绕物品、赠礼、共同经历和分享形成真实关系价值；是否扩展公开社区、好友网络或物品流转市场尚未决定。

## 6. 对统一 Agent 与底层架构的已确认要求

### 6.1 已确定的是「产品层统一」，尚未确定的是「技术框架」

用户应感受到一个连贯的物间 Agent：不同入口能接续同一个任务、物品上下文和获准的个人经历。**统一 Agent 不意味着只能采用一个模型、一条超长 Prompt 或一个庞大的 LangGraph。**

后端可按任务复杂度组合：

- **快速路径：** 确定性读取 + 必要的检索/单次模型回答，适用于常见问答和低风险查询。
- **专业工作流：** 物品知识、创意、家庭协作、赠礼、记忆等业务能力具有清晰工具接口和独立校验。
- **探索型长任务：** 只有确实需要时才进入多回合模型、工具调用、REA 分析、人工授权、恢复和验证。
- **确定性业务动作：** 身份授权、共享、赠礼认领、设备高风险操作等，不交给模型自由写入。

**候选架构偏好（待技术实验验证）：** 统一任务协调层 + 共享 Context + 专业工具/Skills/工作流。是否继续用现有 LangGraph、是否引入其他框架，不作为已确认决定。

### 6.2 需要一致理解的核心领域概念

| 概念 | 不可缺少的含义 |
| --- | --- |
| **物品 Item** | 具体实物实例与商品型号/版本知识区分；物品状态可变化，来源须可核对 |
| **人 Person** | 真实用户身份、可授权的偏好及经历；不同用户不能仅靠演示角色区分 |
| **关系 Relation** | 人与物归属/使用/维护/共享；物与物兼容与组合；人与人通过物品的协作、赠礼及经历关联 |
| **任务 Task** | 用户真实目标、涉及的人物和物品、当前步骤、工具结果、等待确认与恢复状态 |
| **能力 Capability** | 商品原有、推测或新发现的功能；能力证据、适用版本、可执行工具、权限及验证状态 |
| **经历 Experience / Memory** | 故事、实际使用事件、尝试结果、原作者、来源、时效与授权范围 |
| **结果 Outcome（逻辑概念）** | 用户目标达成程度、反馈或设备回读；用于判断价值是否实现，不预设必须新建独立表 |

这些是**领域逻辑要求**，并不预设必须采取某一种数据库、知识图谱或多 Agent 方案。实际工程选择以数据一致性、安全、性能、迁移成本及真实验收为依据。

### 6.3 系统性的质量要求

- **知识正确性：** 「资料没有提到」≠「明确不支持」。不要虚构型号、操作步骤、售后政策和物理条件。
- **上下文相关性：** 每个任务只取必需信息，不把所有个人故事和说明书塞给模型。
- **权限隔离：** 共享物品知识不等于共享私密故事，家庭角色切换不等于真实身份认证。
- **状态真实性：** 用户自报、模型建议、模拟设备调用、真实设备回读与已验证的现实结果明确区分。
- **低延迟：** 常见基础问答应优先短路径与流式体验；复杂任务允许长时间，但必须有可理解的进度和终止/恢复机制。
- **可扩展性：** 陌生商品、不同类别物品、跨家庭身份和未来设备接入，不应依赖固定演示数据。
- **可修正性：** 长期记忆、持有状态、关系及工具结论可以纠正、删除或过期，不固化模型猜测。

---

## 7. 用户入口与信息架构：不预设六个一级导航

**已确认：** 用户的进入方式可以多元，功能入口应服务于目标达成、价值释放、任务连续性与易用性；功能完整并不要求每项功能都有同等级导航。

**待决策：** 首页信息架构、一级入口数量、Agent 是否常驻输入框/浮层、数字分身和创造力在物品详情中的呈现、家庭和社交独立入口的必要性。

已讨论的候选包括：

- **三主入口：** 首页／物品／人与关系；更简洁，但创意和生活故事可能难发现。
- **四主入口：** 首页／物品／生活故事／家人与分享，同时提供持续可达的统一 Agent；为优先测试候选，**尚非正式定案**。
- **现有多入口：** 保留独立创意、故事、家庭、社交等；功能可见性较强，但重复入口和任务割裂风险更高。

**决策方法：** 以真实用户任务进行导航查找、原型使用及跨模块旅程测试，比较任务完成率、首次选择是否正确、跳转/迷路次数、发现性和上下文连续性；不要凭视觉偏好或已有代码量决定。复杂结果的呈现可使用专门界面，用户不必先学习内部模块结构。

## 8. 功能完成与价值完成的区别

任何功能评审均需回答：

1. **用户希望完成什么实际任务？**
2. **与哪些物品、人、关系和约束有关？**
3. **主要在兑现、创造、延续或传递哪一种（哪些）价值？**
4. **Agent 使用了什么可靠的知识、Context 和工具？**
5. **用户是否真正得到结果？有什么证据、反馈或待确认条件？**
6. **这个结果能否在权限允许下改善下一次体验？**

不得把以下情况等同于完成：

- 有说明书上传按钮 ≠ 能理解该型号、可靠指导使用；
- 有多条创意文本 ≠ 创意可用、创新或已实现；
- 有昵称/头像 ≠ 有真正有帮助的数字分身；
- REA 发现软件行为 ≠ 已能控制真实硬件；
- 建立家庭事项 ≠ 对方看到、接手或真实完成；
- 生成赠礼链接 ≠ 已交付实物、完成授权的关系传递；
- 自动测试通过 ≠ 真实用户任务成功。

**成功标准以用户价值为中心。** 常见基本问答需同时关注答案正确性和响应速度；创造力需关注实际新颖性与可行性；家庭/赠礼需关注跨用户权限和任务完成；故事与分身需关注个人意义、真实性及自主控制。

## 9. 决策状态与后续变更原则

### 9.1 已经确认、应作为稳定基线

1. 核心理念：**释放人与物的价值**；可通过物品延伸到人与人的价值，但不泛化为全部人际关系。
2. 认知逻辑：**理解物 → 物与物 → 物与人 → 人与人**；四层互相作用，并非操作导航。
3. 价值释放方式：**兑现、创造、延续、传递**；可相互交叉，不机械归类。
4. 理解人为了更好地用好物，理解物为了更好地服务人，并通过物释放人与人的相关价值。
5. **创造物品新功能、重新定义其使用方式，是物品成为「我的」的重要形式**，不是与个人化割裂的独立目标。
6. 统一 Agent 和任务上下文是产品体验要求；多元进入方式可以共用物品、人、关系、能力、任务及经历的 Context。
7. 家庭管理、长辈关怀、生活故事、数字分身、创意、REA、赠礼和社交均属于完整产品范围；不能因当前工程阶段而从目标中被遗忘。
8. 功能必须对应真实用户价值；工程效果与演示效果必须分别验证。

### 9.2 仍在讨论或需验证，不能写成既定决定

- 一级导航是三、四还是更多入口，以及最终视觉与交互结构。
- 是否采用单协调 Agent + Skills、专业工作流或多 Agent 的具体实现；LangGraph、Pi、Mastra 等框架选择。
- 领域模型及存储层如何重构、是否需要关系图谱、用户账户方案及数据迁移路径。
- 创造力引擎的最终实现与数据源、REA 对各种真实硬件的适用范围。
- 未来接入淘宝/天猫订单、厂商设备协议及外部通知的实际授权和接口可行性。
- 公开社区、跨家庭社交网络、二手流转市场等更远期构想。
- 具体开发排期、比赛展示版本的功能取舍和商业模式。
