# 交互基础版本验证

本报告覆盖本轮交互重构，功能和接入契约见《交互基础版本与模块接口》。运行环境为 Windows、Python 3.12.2、Node 24.20.0 和本机 Edge。离线测试与浏览器使用独立临时数据库，不修改实际生活记录；没有调用收费模型、真实设备或外部发送服务。

## 工程结果

| 检查 | 实际结果 |
| --- | --- |
| `python -m unittest discover -s tests -v` | 50 项通过；包含原业务与 AgentScope SDK 回归、新双账号场景和迁移 |
| Pydantic 导出 OpenAPI、生成 TypeScript | 通过；生成文件由契约源生成 |
| `npm --prefix frontend run build` | 类型检查和 Vite 生产构建通过；主 JS 约 900 KB，后续可拆包优化 |
| 数据迁移 | 已验证无版本旧库及 0005 → 0006，物品 ID、资料、旧经历用途与完成提醒保留；外键检查通过 |
| 升级前备份 | 读取备份检查原数据与 `integrity_check`；Windows 上连接正确关闭，临时目录可清理 |

修复了新增入口上下文对旧聊天请求的兼容问题，并增加不启用物品分身时拒绝分身角色入口的回归。共享来源只开放获准的公开型号资料，旧私人来源不因家庭用品授权被开放。

## 真实浏览器操作

浏览器加载 FastAPI 提供的实际 Vite 构建，使用两个独立登录会话。界面操作产生真实 HTTP 请求和 SQLite 变更，未用前端假接口替代。模拟的是人物、持有关系和生活事件，不把它们作为实物验证。

| 使用旅程 | 实际核对 |
| --- | --- |
| 写一句话、浏览物品、返回物伴 | 草稿与聊天范围保留；百炼未配置时发送失败，草稿仍保留 |
| 从相册建档并加入家庭 | 上传真实测试文件，记录位置，分身默认关闭；另一账号能看共同用品及授权照片，不能看私人介绍 |
| 从物品记回忆、到回忆墙编辑、刷新 | 同一记录更新，无重复副本；默认不允许 AI 参考 |
| 选择故事赠礼、预览、另一账号接受 | 私人介绍不填入礼物；仅所选故事转移，保留原作者，新持有人控制后续，接收不自动开放 AI 用途 |
| 野餐事项、勾选、邀请接受、分工 | 进度立即保存，接受后分配负责人；另一账号报告进度，刷新后双方一致；准备完成不冒充活动完成 |
| 家人处理提醒 | 反馈保存为报告完成，保温壶继续保持暂停使用 |
| 指导事项与售后说明 | 已确认步骤保存后进入下一步，售后草稿取实际物品和检查记录，可编辑，不自动发送 |
| 好友主页与旧方案 | 心愿按本人开放范围呈现；旧版嵌套方案的文本继续可读 |
| 停止并重启服务 | 再登录后事项进度和回忆修改保留在同一数据库 |
| 1440×960、390×844、大字版 | 四栏、详情、事项清单、家人提醒可访问；16 份场景截图检查未出现横向溢出，无浏览器页面异常 |

接口回归另覆盖家庭邀请接受与退出、只读授权、回忆多物同步和冲突、故事照片分享与撤回、AI 用途、重复反馈、并发版本冲突、清单撤回、未接手不得分工、他人负责条目不得代报、停用物品不得准备、心愿不进入库存、礼物取消与重复接受、计划与成功反馈对应。选择某家庭的提醒只能关联该家庭共同用品；送出物品后原作者仍能查看自己的旧方案，但不得把已无权使用的物品继续勾为准备。

## 验证边界

本次通过的是交互与业务基础版本，不是智能底座整体产品验收。真实百炼回答质量、自动生成复杂方案的质量、准确型号识别、浏览器麦克风实机体验、系统通知和实物设备效果未在本轮重新验收。既有 personalized、来源理解、创造、分身准确性和实机 REA 待办仍按原审计推进。
