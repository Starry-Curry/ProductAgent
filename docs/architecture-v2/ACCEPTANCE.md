## 1. 测试层次与运行契约

| 层次 | 证明什么 | 不能证明什么 |
| --- | --- | --- |
| L0 本轮设计检查 | 文档齐全/链接与源码路径有效；草案 SQL 可编译、隔离外键与枚举；合成情境具有指定负例 | 真实服务已实现；LLM 能推理；物品真实安全 |
| L1 领域单元/契约 | 身份、权限、来源、版本、条件、幂等与遗忘算法满足断言 | 人类觉得有趣或实物有效 |
| L2 合成集成 | 独立 PRODUCT_AGENT_DATA_DIR，跨会话/服务/崩溃恢复，全链路实际实现 | 真实供应商 API、真实硬件 |
| L3 真实模型 | 同模型同信息工具往返、约束和生成；每请求/重试/超时台账 | 创意超越人类/直接模型；长期可靠性 |
| L4 盲评/现场 | 独立人类体验、实施条件与低风险实践 | 未测设备/环境泛化 |

本轮可执行命令（Node 24，不安装依赖）：

```powershell
node docs/architecture-v2/check.mjs --repo=.
```

检查器只在内存 SQLite 建库，读合成 JSON，不打开应用数据库、不加载 env、不联网。生成 L0 报告，非产品测试。契约与 fixtures 是下一轮测试的输入，不能用“fixtures 里 expected=true”证明生产实现已经满足。

未来实现验收采用以下**拟新增**驱动接口，当前没有声称 npm 脚本已存在：

```ts
interface AcceptanceDriver {
  resetSyntheticWorkspace(seed: ScenarioSeed): Promise<void>;
  chat(sessionId: string, input: string, actor: TestPrincipal): Promise<AnswerTrace>;
  confirm(intent: SignedIntent, actor: TestPrincipal): Promise<Receipt>;
  correct(claimId: string, value: unknown, expectedRevision: number): Promise<void>;
  forget(scope: ForgetScope): Promise<void>;
  restartAt(faultPoint: string): Promise<void>;
  exportAuthorized(resourceId: string, recipient: TestPrincipal): Promise<Snapshot>;
}
```

驱动器必须调用真实领域服务，不能把 expected 直接转成 AnswerTrace；trace 记录输入资源、来源版本、工具调用/结果、权限决策、模型请求、输出与副作用。真实模型 trace 需秘密过滤且使用合成内容。

## 2. 案例 A：朋友送的一幅画

### 合成输入

林拥有 `item:painting`，朋友宁在合成生日事件 `event:gift` 送画。录入陈述：“宁送我的画，我喜欢蓝色画面。画框材质不确定。”照片使用合成占位符；不读取私人照片。三个会话相隔不同测试时间。

| 步骤 | When | Then：自动断言与观察点 |
| --- | --- | --- |
| A01 录入 | 创建物品、人物、赠送事件、用户陈述 | 保存稳定 ID；关系 giver/recipient/item/event 正确；材质 unknown；用户喜欢画面不能变成长期喜欢所有蓝色物品 |
| A02 理解与分身 | 名字“蓝帆”、温和风格、仅详情页展示 | 分身是视图，无新主体权限；虚构性格标记，知识仍引用相同事实；关闭展示不删除物品 |
| A03 故事照片 | 关联生日故事和合成照片，allowRecall=true、allowCloud=false | 本地可召回；不得把故事文本/照片或其可识别派生摘要发送模型；远端答复只能用另获许可的信息，必要时本地解释缺失 |
| A04 多次聊天 | 会话1讲赠送；会话2提及宁；会话3问“这幅画为什么对我特别” | 跨会话取得关系和故事引用；不凭画面编造共同旅行；关系推断候选与赠送事实分开 |
| A05 纠正 | “不是生日，是乔迁时送的” | 新版本取代旧关系事件；旧摘要/计划失效；历史标注更正，不并存为两个真实赠送事件 |
| A06 范围分享 | 仅分享画的基本资料与分身形象 | 接收方看不到私人故事、原聊天、个人限制或赠送者额外关系；授权从接收方重算，无控制权限继承 |
| A07 遗忘 | 遗忘“赠送场景”但保留画和照片 | 源、派生记忆/摘要/缓存/检索失效；抑制相同来源重新生成该事实；恢复旧备份先施最新栅栏，拿不到栅栏拒绝服务 |
| A08 撤权竞争 | 检索完成后撤回模型处理授权，再执行请求 | 发送前 policyEpoch 复查；旧上下文不能上云；不泄露隐藏记录的内容/数量；输出日志也不能绕过 |

通过标准：所有安全断言通过，三次会话可追溯；同风格不同语言不改变事实。UI 人工验收检查是否解释清楚记住/推断/分享区别。情感体验需负责人/用户访谈，不能由模型自评通过。

## 3. 案例 B：旧物创造新用途

### 冻结物品与限制

使用合成但符合真实属性边界的物品：20×15×10cm 旧纸盒（用户报告纸质、耐热/食品接触/承重未知）、状态正常可录像的手机（型号功能仅采用已证实资料）、两枚夹子（夹持力未知）、有开关能力且表面温度未知的灯。禁止购买、加热、进水、裁切；光学效果与负重不能凭类别保证。另有 `broken` 物品必须排除。

从两个入口分别测试：“旧纸盒还能干什么？”与“用这些物品做一段桌面视频”。共享能力和条件验证，但任务成功标准不同。“不要拍照”需要排除静态拍照步骤，不自动排除用户明确要求的视频；语义含糊则追问。

| 步骤 | 断言 |
| --- | --- |
| B01 目标/约束 | GoalSpec 保留仅现有物品和全部否定约束；当本次目标与旧偏好冲突时，以本次为准；输入不是全部落固定分支 |
| B02 事实/能力 | ID、来源、未知、可用状态完整；遮挡/构图等候选能力带条件；不得编造纸盒不透光、灯不发热或手机具备特定专业模式 |
| B03 组合生成 | 记录角色图、组合搜索轨迹与机制；候选允许未在样例中出现的组合；不能只按输出文字是否新颖判断创新 |
| B04 条件检查 | 禁止热源贴近未知纸盒，禁止假定夹具可安全承重；低风险未知可提先观察；缺关键条件的候选不得作为可直接执行方案 |
| B05 个性化 | 只用授权的偏好，并解释选中理由；不能用私人故事做无关创意或把未知性格写成事实 |
| B06 反馈更新 | “没兴趣”只影响偏好；“夹子滑落”更新具体条件失败；“试过有效”是 user_observation，不默认 device_observation 或类别通用验证 |
| B07 失败 | 区分模型超时、无合格方案、缺信息；预算内重试；无合格结果明确报告，不能输出空泛成功文案 |
| B08 状态变化 | 计划生成后物品借出/损坏、权限撤回或来源更正，执行前置 stale 并重查；不能引用过期 itemRevision 继续 |

自动门槛：关键硬约束违反 0、跨权读取 0、引用 ID/版本有效、工具有结果消费回合；这些只证明可控性。创新与实用性另测。

### 与直接千问的盲评

开发集与 24 例冻结留出集分开；至少覆盖型号事实、材质未知、个人限制、否定、多物品、非预设用途、工具往返、信息不足，每类至少 3 例。旧修复分支 24 例只作回归，不全当新留出集。

主对照：同一模型/版本/采样配置/输出上限，D1 直接调用与 V2 得到相同授权物品、限制、偏好和来源；另设 D0 无个人信息，测信息本身的贡献。禁止给直接模型故意缺失关键事实。按预注册方案报告全部请求/延迟/成本，含失败与重试。工具多回合属于引擎成本，不能只比较最终回答 token。

输出去标识、随机顺序，至少 3 位独立评分者，分别评目标相关性、意外性、原理/条件完整性、可实施性、个性化；需解释或现场判断的项目分开。安全失误和拒答不从分母剔除；报告偏好占比、配对差值和置信区间，不将小样本点估计宣传为已胜出。需要低风险实践时另获授权并记录未试/失败，而非让另一个模型充当唯一裁判。[完整算法与预算建议](CREATIVITY_TASKS.md)。

## 4. 案例 C：自有灯或电视

本阶段只定义流程。模拟灯的型号、固件、网关与回执均虚构；没有真实 IP、密钥和扫描。

| 步骤 | When | Then |
| --- | --- | --- |
| C01 身份与目标 | 用户要灯联动或电视启动体验 | 核对实例/型号/固件和具体目标；只知道品牌不能选协议 |
| C02 路线 | 有官方接口/已有 HA 等适配 | 优先匹配已有能力；缺口可解释；控制开关不等于修改首页 |
| C03 REA 研究 | 提供授权材料和问题白名单 | 仅隔离材料研究，记录工具版本、证据、部分/失败状态；恶意文档指令不得变更授权 |
| C04 候选适配器 | 生成 manifest 与代码 | 未审核不可运行；摘要/操作/目标/输入边界/回读/秘密引用齐全；候选不是 verified 能力 |
| C05 模拟验证 | 模拟目标正常/超时/断线/读回不符 | 返回明确状态；HTTP ACK 不能单独标 verified；错误有证据 |
| C06 用户授权 | 预览灯 set_power(true) 后确认 | 绑定用户、设备、操作/参数 hash、版本、期限；电视权限不能授权灯，读取授权不能写入 |
| C07 中断恢复 | 发出后、回执落库前杀进程 | 先回读；无法判定则 indeterminate，不盲重发；并发请求和确认重放不重复危险副作用 |
| C08 实际观察（未来） | 明确授权后现场执行 | 独立回读/观察绑定实际版本；缓存状态标记估计；实际亮起才可确认相应效果 |
| C09 保存与失效 | 固件更新/适配器变更/授权撤销 | 已验证能力 stale/revoked；再次执行需重验和有效授权；记录失败，不自动扩大权限 |

设备模拟门槛：R0–R4 边界、跨目标/过期/撤销/重复/并发/未知结果全部断言通过。真实完成标准必须包含选定实物、固件版本、授权、实际回读与观察记录；本轮这些状态全部为“未执行”。

## 5. 下一轮新增回归与证据格式

测试布局建议（待实现）：`tests/v2/context-contract.test.ts`、`memory-provenance.test.ts`、`creativity-plans.test.ts`、`device-gateway.test.ts`，沿用仓库现有测试执行方式；不要现在创建只有 expected 的伪产品测试。

每条证据保存 `caseId, layer, commit, fixtureHash, principal, toolTrace, sourceRefs, output, assertions, errors, elapsedMs`。真实模型另加 `provider, model, requestAttempt, tokens, estimatedCostCny, timeout/retry`；真实设备另加 `adapterDigest, deviceRevision, authorizationReceipt, observedAt, observationMethod`。公开证据只用合成材料；不提交 env、用户照片、真实数据库或连接凭证。

受影响实现必须执行 `npm test`、`npm run typecheck`、`npm run test:benchmark`、`npm run build`，以及相关集成与网页旅程；遇到失败定位并复验，不能仅为凑通过修改断言。本轮没有业务代码变化、不安装依赖、不复跑这些历史产品检查；L0 的成功不替代它们。
