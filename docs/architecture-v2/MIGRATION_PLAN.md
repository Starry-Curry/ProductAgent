| 阶段 | 实现范围 | 完成标准与失败时处理 |

| P4 数字分身产品化 | 有选择的形象/人格视图、故事与记忆授权、赠礼快照 | 案例 A 分享负例、交互偏好、成本与跨会话一致性通过；不常驻每物品 Agent |
| P5 设备探索 | REA 独立工作者、模拟设备、适配器审核/授权/回读 | 案例 C 模拟故障全过；选定真实设备后另获实际操作授权，不以模拟代替物理验收 |

P2/P3 的开发顺序可在 P1 后按用户价值调整，但来源/权限/失效的基础不得省略。每阶段都要更新四个根报告和技术决策，自动测试、独立分支提交推送，不自动合并。

正式多用户/家庭共享/私人设备接入还有独立前置关卡：替换 local-demo 主体来源，验证真实会话与成员授权。合成测试可以先走上述阶段，但不能因此把 demo actor 升为生产账号；身份接入不意味着复制故事中的人物成为账号。详见领域模型的身份边界。

## 4. 数据迁移与回滚的具体做法

1. **盘点而非接管私人数据**：开发使用合成工作区和 `PRODUCT_AGENT_DATA_DIR`；未来真实迁移先列版本、行数、引用与媒体哈希，不把内容写进公开报告。备份包括 SQLite 一致快照、媒体清单、迁移清单、当前权限/遗忘栅栏。
2. **稳定 ID 映射**：建立 `legacy(kind,id,workspace) -> v2 resourceId` 映射，映射文件包含版本和哈希。相同工作区重跑不重复生成；不同用户同名物品不合并。产品型号知识与物品实例分开；用户只说“纸盒”不能推断纸板厚度或食品级。
   P1 不写新表或映射文件，使用确定性带工作区的 legacy 资源 ID、内容寻址的不可变 claim ID 与授权投影快照；P2 才持久化映射和修订。现有 Item 无通用 revision、memory epoch 非全局权限版本，不能在只读适配阶段假装已经提供。工具提交前重新读源并重新授权，快照不一致即重算。
3. **先加后切**：P1 只读适配器；P2 增量建表与后台可续跑回填。源字段按已有证据导入为 `user_report` 等来源，旧 AI 文本保留原始来源和未证实状态，不全部洗成 accepted/verified。
4. **来源闭包**：导入物品、故事/人物、证据，再导入断言与关系；最后处理摘要、能力和计划。无法确定来源/授权的记录进入隔离清单，不默认公开，也不悄悄丢弃。
5. **校验**：计数、唯一 ID、类型/单位、跨工作区外键、媒体引用、权限、导出回读和重复回填一致性。差异清单必须可解释。模型不参与自动“修正”历史事实。
6. **切换写入**：每工作区单写者，以事务同时写权威新记录与必要旧投影/回执；若跨库存储不能原子提交，用可重放 outbox 和幂等映射，不做无追踪双写。以功能开关逐入口切换，记录实际数据版本。
7. **回滚不是覆盖文件**：切换前恢复一致备份；切换后先停止写入、收集新版本增量，能无损反向投影才回退旧入口，否则进入只读并前向修复。绝不覆盖切换后的用户新内容。
8. **遗忘优先于备份恢复**：在独立受控日志保存最小撤销/遗忘栅栏；恢复时先应用最新栅栏再开放读取。无法取得栅栏就拒绝开放旧快照。删除后的事实、分享权限、设备授权不能因回滚复活。
9. **何时删旧结构**：至少经过约定观察期、完整恢复演练、可导出且无入口依赖后再单独批准破坏性迁移；本 RFC 不授权删库、删字段、重置历史。

SQLite 活跃 WAL 库不能只复制主 `.sqlite` 文件当完整备份；采用一致备份接口或停止写入后的受控快照。[官方备份](https://www.sqlite.org/backup.html)、[WAL 说明](https://www.sqlite.org/wal.html)。真实迁移的备份保留期、删除承诺与家庭共享规则需先产品决定；不是本轮已运行的流程。

## 5. 本轮交付与后续操作

本分支只含架构/契约/检查夹具和协作记录；不包含 v1 生产补丁、运行缓存、数据库和凭证。提交后可通过 GitHub 本分支查看与讨论。后续代码从当时最新 main 建分支，以本 RFC 为设计依据，记录实际差异；不要从 RFC 分支直接把文档检查夹具当生产数据使用。
