# 技术决策记录

日期：2026-10-29。状态为“接受为本 RFC 设计”不等于生产已实现，也不授权整体框架替换或破坏性迁移。

## ADR-01：以共享知识契约连接功能，而不是再加一个万能聊天入口

**决定**：物品事实、个人认识、关系、能力、任务共用资源身份、证据、版本和权限契约。先实现只读 ContextBroker / ItemKnowledgeRepository，统一 Agent、创意和数字分身的输入。

**依据**：main 已有故事/记忆/知识/任务等模块；问题不是完全没有记忆，而是读取和验证依赖不同局部规则。v1 修复证明完整物品工具与工具后模型回合值得保留；不能据此证明已具备通用物理推理。

**替代**：继续在各入口补提示词/正则；立即建大型知识图谱。前者扩大割裂，后者先增加迁移负担。先用类型契约+SQLite 关系解决共同底座。

**反证门槛**：若 P1 接入后没有减少跨入口事实差异、未知丢失或权限重复代码，应缩小契约并重新测量，而不是继续增加抽象层。

## ADR-02：认识的可靠性与使用授权分开；来源可撤销

**决定**：`basis/status/evidence` 与 `grant/purpose/processor` 独立。accepted、高 confidence、官方出处、用户喜欢这个答案，都不等于物理验证或分享许可。关系记忆和能力有来源依赖；更正、遗忘、撤权使下游失效。

**替代**：一个 verified 布尔值；只靠“隐私/公开”标签；所有历史都放模型上下文。它们不足以区分用户报告、模型推断、实测、用途授权和私人聊天。

**代价**：需要版本、来源闭包与缓存失效测试。原始材料保留但要求遗忘某事实时，需抑制重新提取；备份恢复要先应用最新遗忘栅栏。见 [记忆设计](MEMORY_PERSONA.md)。保留期是待产品决定，不假装已承诺彻底删除第三方副本。

## ADR-03：创意和任务共用“功能角色搜索 + 条件验证”

**决定**：GoalSpec → 授权事实 → 候选能力 → 角色图组合 → PlanSpec → 条件/风险验证 → 用户选择 → 反馈。模型负责开放式假设与表达，代码负责约束、版本、权限、搜索预算和执行边界。

**替代**：扩充 recipes；纯大模型一次生成；无上限多 Agent 辩论。分别受覆盖范围、依据与可控成本限制。功能本体是组合语法，不是答案库；允许提出新机制，但须说明新机制的证据和未知。

**验证**：同信息 D1 直接千问与 V2 人类盲评，另设无个人信息的 D0 以区分信息收益和引擎收益。自动检查只证明约束/证据形式，不能证明惊喜或实际可行。[盲评与预算设计](CREATIVITY_TASKS.md)。

## ADR-04：统一运行核心 + 按需数字分身视图

**决定**：分身使用物品身份、风格配置和授权记忆视图；不为每件物品常驻独立模型，不复制完整用户画像。赠礼只复制明确选中的快照。

**替代**：每物品长期独立 Agent；所有分身共享完整聊天；仅换头像的无物品语义聊天。前两者增加成本/污染/泄露，最后一种不满足“我的物品”。

**验证**：同物品三次会话可追溯事实，风格不同不改变物理结论；访客看不到私人故事；分身关闭仍能维护物品知识。人格的虚构内容明确标记，不能制造用户从未经历过的共同回忆。

## ADR-05：保留 SQLite，按纵切增加结构

**决定**：P1 不建新业务表，P2 仅七个知识核心表；继续使用现有 stories/media 等。后续按真实需求增加投影。保留原 ID、迁移清单、一致备份和晚期写入的回滚方案。

**替代**：立即 PostgreSQL+图数据库+向量库；长期把所有新对象继续塞 workspace JSON。前者没有当前负载证据，后者不利于原子来源和依赖约束。SQLite 单写服务足够开始，不适合多主机共享文件并发写。[官方适用场景](https://www.sqlite.org/whentouse.html)。

**重议条件**：先定负载与 P95 锁等待基线；若需要多主机写、备份恢复窗口达不到要求或实测锁竞争无法改善，再比较 PostgreSQL。中文检索先测正确性，不默认向量检索能解决权限和事实问题。

## ADR-06：框架暂不替换；隔离运行接口后再做真实恢复实验

### 官方实现核对

Pi 仓库本轮查询的 HEAD 为 `e65b3b88c08412bb8ffbd21fb5dc5756064a6e5a`。文档来自该项目官方 agent/durable 包及 Cloudflare 官方说明；Git 主线与 npm 发布不必相同，实验必须锁具体包版本和 lockfile。上一轮 PoC 使用 Pi 1.4.0，不能当作当前全部实现的证明。

| 方案 | 实际提供什么 | 仍要由物间实现什么 | 采用范围、代价与现阶段判断 |
| --- | --- | --- | --- |
| 当前 LangGraph | 状态图、工具/模型节点；checkpoint 与中断/恢复。现有 SQLite checkpointer、动作/请求回执已接入 | 正确事实、业务记忆、授权、来源、创意算法、模型预算、外部副作用去重 | 继续保留；从 graph 中抽业务服务。既有检查点兼容与回归成本最低 |
| Pi Agent Core | 模型/工具循环、事件、转向与扩展钩子；适合动态工具交互 | 持久化、跨进程恢复、任务队列、业务审批/记忆/数据隔离与预算 | 可仅替换运行核心，保留 Next.js/DB/业务工具；需要重接消息、模型适配、事件和错误语义。不能把 Core 当作 durable |
| Pi Durable | 基于 pi-ai / Chord 的持久执行；Node.js + SQLite 存储可用，支持运行/任务/工具恢复策略；当前标为 experimental | Wujian 授权、幂等、遗忘、领域状态，崩溃后不确定副作用处理；并非 Core 加一张表就完成迁移 | 最值得做独立恢复 PoC；**不需要先迁 Cloudflare**。要验证 checkpoint 兼容、并发租约、重复模型计费和中途审批恢复 |
| Cloudflare Pi Harness | 在 Cloudflare Agents / Durable Objects 环境结合 Pi；DO 生命周期与 SQLite，官方文档约束 SDK 与可选 Pi peers | 身份、领域库/媒体搬迁、边缘与本地设备桥接、授权和成本策略 | 只有部署需求支持时再考虑。引入 Workers/DO 平台、状态迁移和本地设备网关，迁移范围最大 |

Durable 的安全重放工具标记不是业务许可。可重放读取与外部写入区别处理；非安全重放可能中断，安全标记错误仍会重复副作用。中断的模型尝试可能重新发起请求，因此计费预算须在提供方请求前独立预留，不因运行恢复清零。LangGraph interrupt 恢复也可能重跑节点内代码，需保留已有幂等和确认约束。

### 什么问题与框架有关

| 观察 | 归因结论 |
| --- | --- |
| 物品型号/未知未传给模型，来源和建议脱节 | 业务上下文和验证实现；换循环库不会自动修复 |
| 工具调用后没有足够模型回合 | 当前预算/流程配置；v1 已修复关键路径，不是 LangGraph 天生不能做 |
| 负向指令、硬编码路由和创意模板 | 业务认知流程；不是框架替换的充分理由 |
| 动态探索步骤多、长任务跨进程恢复困难 | 可能涉及运行核心抽象；需实测持久执行语义和开发复杂度 |
| 硬件写入、授权撤销、隐私遗忘 | 无框架替产品兜底；都需领域服务与恢复协议 |

### 独立 PoC 的实验矩阵

共用 `AgentRuntime` 接口、同一模型替身脚本和同一 SQLite 合成业务库；不使用框架自带 demo 代替物间情境。对照现有 LangGraph、Core+最小宿主恢复层、Durable；Cloudflare 仅在已有测试环境且有部署需求时参与，不为比较先迁云。

1. 同一纸盒读取工具 → 真实结果 → 模型答复；模型输出错误结构后修复一次；分页和工具失败。
2. 方案暂停待确认；进程终止、重启、权限已撤销；无有效 intent 不写；确认重放不能重复记忆写入。
3. **强制杀进程**于“模型已请求未保存”“工具完成未落回执”“设备已发出未回读”三处。重启后记录重复模型次数、读取次数、写入次数与不确定结果，不能把正常 close/reopen 当崩溃恢复。
4. 两进程竞争同一请求；过期租约回收；故障重试消耗累计预算；旧上下文遇到遗忘 epoch 变化时必须重取。

指标：行为断言通过率、重复副作用数（必须为 0 或明确不确定且不重试）、恢复后的权限正确性、持久状态可解释性、P95 延迟、代码/适配复杂度、依赖/运维成本。先离线，不用模型评分决定框架。上一轮 Pi PoC 只证明替身工具往返和正常关闭重开后的回执复用，没有中途 kill、写工具或 Cloudflare 验证。

**迁移提案门槛**：相同领域契约与故障集下，候选全部安全门槛通过；至少一个现有痛点获得可复现改善，且总迁移/运维成本可接受。若只是 API 更简短，不足以全量替换。通过后单独提出历史会话处理、回滚、包稳定性和线上观察方案，由负责人决定。

## ADR-07：REA 是受控探索工具，不是执行授权者

正式进入架构，先走官方/成熟适配器，必要时以 REA 研究缺口。证据、候选适配器、实测能力分开；生成的代码须沙箱和用户授权后经网关执行、回读。当前 REA 与应用 Node 版本有差距，使用独立工作者，不升级全局环境。替代方案是永不支持探索或让模型自由连接 shell/设备，前者失去产品方向，后者失去权限边界。[具体证据与兼容条件](DEVICE_EXPLORATION.md)。

## ADR-08：验收与研究分层，避免“自己证明自己”

本轮只有文档/DDL/夹具自检，没有新产品或模型效果结论。实现轮分别记录离线规则测试、模型行为、盲评、人类现场观察和设备实测。原始输入输出与费用可公开的合成证据进入 GitHub；秘密、私人数据库与固件/照片授权材料留在私有存储，不因要可复现就公开。

## 仍待产品负责人决定的少数问题

1. 记忆默认策略：仅明确记住，还是对低敏信息自动形成可撤销候选；首次如何告知模型处理范围。
2. 家庭共享/赠礼默认公开哪些内容，原材料、历史备份和删除保留期如何承诺；本文默认最小共享，30 天仅待议建议。
3. 下一轮先验证哪类创意目标、邀请哪些独立盲评者；是否允许实际低风险实践。技术建议先做可信上下文，再做创意盲评。
4. 第一台设备与单一目标是什么；允许何种观察/控制风险。REA 不自动授权刷机或改变启动链。

框架、数据库没有必须现在迁移的产品决定；有实验证据再提交选择。
