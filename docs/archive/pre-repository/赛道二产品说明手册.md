# 物品智能服务｜产品说明 

**天猫 AI 黑客松 · 智能日常**

> **核心理念：让用户已经拥有的物品，在需要时发挥更大的有效价值。**

## 一、产品为什么存在

**购买不等于价值实现。** 用户可能不会使用某件商品、不知道它隐藏的功能，或忘记自己已有的物品能在新场景里提供帮助；说明书、购买凭证、售后和家人使用经验也常常分散。我们的产品希望用 AI **既懂物品，也懂用户当前想完成的事**，让物品更容易被理解、调用、维护和分享。

四种价值：**兑现**原有功能（配置、使用、排障）；**发现**新用途（跨物品组合、合理替代）；**延续**物品价值（管理、维护、购后服务）；**传递**物品价值（家庭照料、赠送、共享）。因此，「管理、规划、关怀」是重要服务表现，但**单物品智能服务与目标驱动场景服务才是两条并列的直接价值路径**。

**有效价值**看用户是否真正完成目标、减少时间/金钱损失、降低操作和管理负担、改善家庭协作，而不是单纯提高使用次数、App 日活或购物额；「无需购买」也是正确结果。

## 二、产品是什么、用户怎么用

一个围绕**用户拥有或使用的实体物品**、结合可信商品知识与用户情境的 AI 智能服务 App/入口。原则上覆盖**几乎所有实体商品**：耐用品侧重深度指导与长期服务；食品、拼豆材料、日用品等侧重场景调用和低负担的余量/补货管理。无需每件商品运行独立 Agent，也不要求先录全家中物品。

**两条核心路径：**

- **从物品出发：**「我的咖啡机怎么清洗？」「妈妈的电饭煲怎么预约？」→ 找到准确型号和知识依据，解释、分步指导、核验或衔接家人/售后。
- **从目标出发：**「周末去烧烤，要带什么？」「想开始拼豆。」→ 结合已有物品和人数、地点、条件，发现组合与替代，形成准备清单与方案，识别真实缺口。**人先提出目标，AI 帮忙安排；不替人制造目标。**

物流、维护、补货、家庭协助等可形成有用的自然回访入口；节假日灵感优先在用户打开 App 后呈现，默认不频繁打扰。

## 三、希望具备的功能

| 功能域 | 用户能够得到什么 |
|---|---|
| **1. 物品空间与轻量管理** | 在授权和接口允许时导入淘宝/天猫购物记录，兼容手动、照片/订单截图、扫码/NFC 等补充入口；自动分类、搜索、去重、多件同款及纠错。区分耐用品/消耗品、购买者/使用者、自用/赠送、在用/闲置/退出，必要时轻点确认，精细库存可选。 |
| **2. 单物品 AI 智能服务** | 具体型号的说明书、功能/限制、首次配置、个性化使用、兼容与配件、清洗保养、故障排查；提供图文分步、语音/朗读、大字模式、拍照/截图辅助。**可探索现场视觉指导**：对齐真实按键/接口与说明书图示，必要时标注下一步；信息不足不猜测。 |
| **3. 用户目标与多物品场景** | AI 按用户目标匹配已有物品的功能、尺寸和兼容约束，发现跨品类组合、替代方案；给出计划、清单、不同选择、需要确认的物品和真实缺口；优先复用再补充购买。 |
| **4. 购物后连续服务** | 物流、签收、验收、首次使用；订单和保修凭证、售后入口及问题记录；未解决时整理型号、现象和已尝试步骤，生成可复制/导出的售后资料，是否外发由用户确认。 |
| **5. 维护、消耗与低打扰提醒** | 依据可信资料及用户确认处理保养/滤芯/保修，按购买节奏估计日用品补货；一键「已处理/还有/已用完/不提醒」，不把估计当真实状态。 |
| **6. 家庭协作与物品流转** | 个人/家庭空间按物品授权，支持老人指导、请家人协助、角色与权限、共享清单、赠送/借用/出售/归档；家庭管理员不默认查看私人订单。 |
| **7. 懂用户与可信交互** | 在当前任务需要时使用用户明确偏好、技能、预算、家庭、地理/天气等 Context；区分已确认/推断/未知。知识注明来源及型号版本；支持反馈「还是没解决」、人工回退、权限撤销及数据导出。 |

**共通结果闭环：** 理解目标/物品 → 获取有依据的知识与能力信息 → 组织建议或指导 → 尝试核验结果。条件允许时通过数字状态验证；否则采用用户确认，并区分「操作执行」「自报解决」「客观恢复」。危险操作停止指导并转专业服务。

## 四、关键产品原则与技术认识

- **低管理成本，高服务深度。** 商品记录只是候选拥有信息；拥有≠实际在家、可用或仍有余量。优先自动整理与任务时按需询问，不要求持续盘点。
- **知识必须能用于行动。** 候选的 **Product Pack（商品知识能力包）** 可整理准确型号/版本、说明书与图示、功能与限制、兼容、操作步骤及可验证条件；这是数据组织方式，**不意味着每件商品训练一个模型**。
- **可信、可控、隐私有边界。** 官方资料、经核验经验和推断分层；用户掌握分享、位置与家庭授权；敏感图像最小采集。本地处理/云端调用由延迟、算力、隐私和成本决定，**不预设本地 9B 模型为必选架构**。
- **模型及经验网络不先行决定产品。** 千问是当前候选模型底座；现场视觉、客观核验、小型能力评测值得探索。Experience Network、后训练、商家资料工具、社交网络与能力感知推荐属于后续候选，不是当前价值成立的条件。

## 五、下一阶段要验证什么

关键包括：商品与订单授权是否可用、如何以极低成本维护全品类物品状态；具体型号及兼容知识是否可靠；视觉定位和结果核验是否稳定；场景建议是否让用户实际完成目标；家庭权限、提醒打扰和端云隐私边界如何落地。

**有效价值的验证**优先比较「用户不使用本产品时怎样完成同一任务」：完成率和耗时、成功配置/解决问题比例、实际可复用物品与合理减少的购买、管理和确认耗时、无依据建议与误提醒、家庭协助效果。具体指标和阈值待用户测试确定。
