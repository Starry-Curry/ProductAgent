整体而言：我们的模型是基于 Qwen3.5-9B-Base 进行制作的，我们整个覆盖 CPT、SFT、RL 来做的，主打的是科学和工业。我们的尺寸是 9b，在同尺寸下我们是最好的，和更大的比我们快。
具体应用场景：

1. 科研设备：在一些冷冻电镜等科学设备上可以直接部署我们的模型，推理速度快，对硬件算力要求没那么高
2. 工业场景：在工业场景上，我们可以用于对时效性要求高的部分，例如工业安全的部分等
3. 通用场景：在边缘设备比如手机，平板，笔记本上部署多模态模型，协助进行简单的操作（大家可以理解为更智能的 小爱同学或者 siri 这种东西）
   具体而言，核心创新点集中在数据方面：
4. 数据合成：合成带有 cot，ocr 的数据进行专门能力的提点；还有一套管线是自动标注的，为了扩大工业数据集和 benchmark（涵盖 CAD，工业安全，建筑设计，平面设计，芯片设计，机械原理等）
5. 数据清洗：有一个自适应的数据清洗策略，保证对不同的数据集采用不同的清洗策略实现更优的清洗结果
6. 数据配比：我们的数据包含了许多领域，我们需要每个领域选择不同量的数据（核心就是解出来归一化的权重即可）
7. 数据验证：对于新的数据集，我们要验证一下这个数据集质量如何，现有的模型由于都是 overfit 的，所以不论怎么训基本都会掉点，所以要一个合理的验证策略来决定是否购买这个数据集
8. RL：RL 算法不是我做的，这是一个算法的创新，grpo 改的
   现在的demo：
   我和杨一这两天讨论了一下，感觉单独做某一个场景还是有些限制，所以想着不如做一个可以面向一类问题的工具类型应用
   我们设置的问题setting是：
   面对不会编程的普通用户，他们希望完成一些日常大量重复的、某种流程相对规范的工作（可能是科研上的一些检查、填表之类的工作，也可能是面向一些业务场景，比如快递填单、分类之类的任务）。这类任务特点是，需要一定智慧（否则可以用超小的专有模型完成），同时流程相对可规范化（避免本地模型智商不够）
   痛点在于：
   这些任务确实可以用云端大模型很好的解决，并且单次任务费用很低（可能几分钱），但是如果每天大量重复，次数上来了，api调用成本依旧还是很贵的，很多非学生或AI从业者可能也不想每个月花钱订阅vip。并且目前也没有一个比较好的工具，能全流程的帮用户弄好稳定的本地模型+工作流。同时大家目前的笔记本配置也基本足够部署一些模型大小4GB以下的模型了（比如我们qwen-3.5-9b 4bit量化）
   解决方案：
   一个图形化界面，用户首先用自然语言和云端模型交互，沟通清楚任务输入输出和需求，并且说清电脑硬件配置之类的，云端模型同步开始搭建工作流程和必要的脚手架，并且根据硬件与任务难度自适应选择本地部署的模型（首推我们的qwen-3.5-9b），然后给用户一个图形界面，可以监控任务自动完成进度，后端是已经部署完成的本地模型
   用户输入：自然语言描述的工作需求
   输出：本地部署好的模型+一个前端页面，自动完成用户特定需求（可能是每天大量重复执行循环）
   可以吹的亮点：
9. 推出qwen-3.5-9b自研智能体，科学、工业实际场景能力很强，并且基本可覆盖很多的任务以及硬件设备，完全由我们自主后训练，收到用户回流的数据之后，我们也同样有进一步训练更强模型的能力
10. 更优秀的模型压缩技术，让相同硬件可以承载更强模型，并且可以自动根据硬件配置和任务难度选择最适合的本地模型部署
11. 完整的云端规划+本地推理流程。我们的insight是，本地模型其实可以完成一些相对复杂的任务，但需要云端强大的模型先做工作流规划+搭建基础脚手架
