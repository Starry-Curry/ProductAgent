# 物间 2.0 本轮开发更新报告

日期：2026-10-17。面向项目负责人及后续开发审查者。事实依据：当前源码、基线 118e295 与提交 f058488 的差异、自动测试和独立副本验证。没有依据的历史变化明确不作推断；本次打包没有新增业务功能。

## 1. 本轮开发概览

目标是把同学交付的 Windows Demo 2.0 变成更可检查、更可信、更便于继续开发的工程：先补证据约束、执行记录、权限边界和测试，同时修复礼物故事作者、补充商品资料及有限组合。

最重要变化：以前模型拿到一个存在的引用 ID 就可能通过校验；现在只有与选定资料事实逐条一致的内容能显示。模型运行也从一次函数调用变为有阶段、证据快照和失败记录的过程。礼物故事开始区分“谁写的”与“现在由谁持有”。

整体处于本机可交互 Demo、第一批 P0 可靠性基础完成的阶段，尚不是完整真实 AI、多用户或设备接入产品。F1—F12 仍是目标体系，不能因存在入口就判定全部实现。

Git 分支 codex/p0-reliability；提交 f0584882769bd85a143b3756ff8e1db2845591c6；基线 118e295d6f513fc439daaa67870c4f186ac1df69。基线来自用户的 Windows 分发包；团队原仓库、更早开发历史无法核实。导出时没有未提交源码变更。

## 3. 重要技术更新

### 数据库与结构

修改前：业务以 SQLite JSON 工作区为主，赠礼故事文本缺少可靠作者传承。修改后：仍保留工作区，增量迁移到 v2，升级前使用 VACUUM INTO 留下包含已提交 WAL 的备份；新增迁移审计，记忆分作者/持有人/来源，旧来源未知显式标记。原因：避免为赶 Demo 破坏旧数据或虚构作者。效果：备份与幂等迁移有测试。限制：未迁移原用户库，仍不是完整关系模型、真实家庭账户系统或生产灾备方案。

### Harness 与工具步骤

修改前：只校验引用编号，执行过程难检查。修改后：按身份、检索、模型、验证、完成/失败记录事件并持久化；过期运行标 interrupted；回放重新验证已保存公共事实或显示失败阶段。原因：可定位错误、撤权后不泄漏旧记录。效果：模型错误、缺配置、权限变化有回归。限制：不保存私人问题和失败原文，不能完整复现原始模型调用；工具名是程序固定步骤，无自主写业务工具，更没有撤销现实动作的能力。

### 模型接口与事实验证

原有千问兼容适配器仍使用服务端 HTTP，本轮新增显式付费调用开关与受限实测脚本。没有实际请求千问。测试只证明 mock 成功、限流/截断/超时和无配置等分支工作。

ID-only → 精选原文提取约束，是为先阻断有引用的编造。七条离线基准中，五条错误断言从放行变为拦截，但一条正确改写被误拒。不能宣称已解决通用事实核验或提供任意操作步骤；回答是否真正解决用户问题仍需评价。

### Product Pack 与组合

只有鼠标资料 → 三类商品四个版本包，并增加音箱数量/型号、推车场景/载荷/食品接触等条件。来源为官方公开页面，绑定需人工确认。新物品 ID 也可触发候选，不只固定种子卡片。限制：覆盖少、规则固定、未实物试验、没有真人案例库，也没有实际模型创意验收。

### Context、记忆、家庭与礼物

新增偏好对象只由本人设置，默认不发送云端，纠错与未知状态可见；明确/推断/未知在结构上分离，但推断尚未实现。Gift 保存选择后的故事快照并保留原作者；Memory 持有权限独立，接收者后续故事不自动共享。

家庭分工和 A/B 类提醒原有逻辑保留，本轮主要以测试守住其边界。关怀仍使用示例设备信号；不使用设备不等于身体异常。没有设备接入或真实成员管理新增。

### 安全、异常和性能

显式 local-demo、仅 loopback、Origin/Host 检查使演示头不被误作可公开部署的账号。AI 记录采用哈希和公共事实，模型无业务写权限；这些不是完整安全审计。构建指定独立 tracing root，按原 lockfile 重装，没有顺便升级依赖。只测了本机轻量回归和页面，不存在并发吞吐、真实模型成本或真实用户价值统计。

拍照/OCR/扫码本轮未接入；图像上传仍只是档案展示。

真实模型调用：0。真实设备连接：0。商品事实来自已核对的公开官方资料；角色、设备信号、测试问答与业务数据均为虚构夹具。合成成功 trace 不得作为真实千问演示。

可复现限制/问题：

- 未配置 API：建物品、确认有效资料包再提问，返回不可用和失败记录，而非 AI 答案。
- 正确改写被拒：运行 test:benchmark，查看 benign-paraphrase；这是已知保守策略代价。
- 未提供匹配 pack：无法获得型号专属 AI 帮助；不能把任意物品名称当作已确认型号。
- Windows Edge 固定路径不存在时集成脚本无法启动浏览器；不影响领域测试，但需环境适配。
- 真实设备状态、跨设备认领、影音传递等没有可复现成功证据。

## 5. 目前的问题与风险

1. **阻碍核心演示：** 千问账号/地域/模型/额度与费用授权未完成，真实 AI 闭环尚无成功记录；严格提取策略也不能支撑丰富操作建议。
2. **发布前阻断：** 演示角色不是认证。不得把本机边界当作真实家庭权限；公开分享需独立账号、授权、token 生命周期与审计设计。
3. **数据可靠性：** JSON 聚合状态、历史作者恢复局限、缺生产备份恢复和高并发测试。已有迁移测试不代表生产迁移已获准。
4. **体验与产品：** 预设卡/有限关键词规划易被误解为通用 AI；部分真实组合只给待确认，不应宣称已完成任务；识物入口未接识别。
5. **外部依赖：** 无设备、商家、订单生态接口和实物测试样本，无真人创意案例评审。
6. **协作风险：** 本地仓库来自 ZIP，团队上游和其他同学后续更改未知；合并必须先比对，不覆盖同伴工作。
7. **资料缺失：** 指定的全维审查总任务书未交付，无法逐条证明已回应原报告；用户消息中的 P0/P1/P2 只作已知任务依据。

## 7. 给项目负责人的总结

**三个最值得关注的进展：** 第一，有引用也可能错的问题有了可执行的保守拦截；第二，服务现在留下阶段和证据，失败能检查；第三，赠礼记忆能保留作者与私人边界，而不是只复制文字。

**现在打开网站能体验的新内容：** 私人偏好设置与云端授权；为新增的指定型号物品核对有来源的组合条件；单物品服务的错误记录与回放；收礼时正确显示选中故事的原作者。

**有界面但未做实的部分：** 实际 AI 成功回答、自动识物、任意生活目标规划、真实设备关怀、跨设备家庭/赠礼和影音陪伴。既有清单、卡片和模拟角色虽然可操作，也不能包装成真实模型或真实设备。

**最需要负责人提供：** 总任务书原文、团队上游仓库与负责合并的人；千问地域/模型/额度和有限费用授权；三件实物与愿意参与验证的家庭场景。不要在聊天中发送密钥。

**如果现在参赛，最能拿证据说明价值的功能：** 围绕具体物品的本机家庭分工和处理记录，以及选择故事、确认收物、保留原作者、收礼后隐私隔离的赠礼闭环；再以有来源且检查限制的组合候选展示可扩展方向。真实 AI 需完成在线验收后才能作为已实现亮点。
