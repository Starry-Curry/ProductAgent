# 物间创造力 理解人与数字分身的开源研究

研究日期：2026 年 11 月 5 日。范围为公开资料、官方文档、论文、仓库及关键源码阅读；未安装新组件、改变产品架构、调用付费模型、创建外部账号或运行候选系统。以下为机制分析和待验证建议，不是接入结果或智能验收。

用户后续明确纠正了创意研究的重心：应围绕日用品跨用途、社区妙招与旧物再用。最新主方向、实际来源探针、数据库检查及宠物式分身参考见[生活创意与物品认识修订](2026-11-05_生活创意来源物品深度认识与宠物式分身修订.md)。下文科研创意方法保留为研究记录，不作为物间创意功能的主要实现路线。

本稿回答三件事：创意怎样产生并适配现有物品；系统怎样从相处中更好理解人；可选物品分身怎样把角色、经历与有用能力连接起来。优先考虑与现有 Python、AgentScope、百炼和 ReMe 基线的接续，工具按具体缺口选择，不把所有候选同时加入。

## 1 研究结论

成熟工作最值得学习的是信息与经验怎样形成判断：从真实记录取得依据，提炼有情境的认识，在当前问题中找回相关部分，让模型推理和使用工具，再根据反馈修正。形象、声音和动画是分身的另一部分，不能用它们替代正确记忆和任务能力。

物间可以先沿用现有主 Agent 与共同业务对象：增强物品能力和案例的认识；改进理解人的提炼、检索与纠正；让分身引用同一套获准知识和经历。视觉表达再按需要采用成熟模型或渲染能力。

目前值得优先评估的是 ReMe 的更完整记忆方法、Honcho 的理解人方法、STORM/SciMON 的研究与灵感机制，以及 AIRI 的表达层。Mem0 作为替代基线，Graphiti 作为关系与时间复杂度确实增长后的候选。该优先顺序是对物间的判断，不是项目的全球排名。

## 2 创造力如何增强

### 2.1 先认识能力与条件

知道物品名称不足以迁移新用途。应逐渐知道它支持什么动作、依赖何种条件、有哪些边界、当前实物是否正常，以及判断来自哪里。资料缺少的尺寸、材质、负载或控制能力保持未知。

[Text2Afford](https://aclanthology.org/2024.conll-1.27/)研究文本情境中的物品可供性，并指出被测语言与视觉语言模型在不常见用法上的不足。它是研究数据与评测工作，适合借鉴反例设计，不能当成直接认识全部商品的成熟服务。论文中少样本微调的改善也不能直接推断对物间现用模型有效。

对物间的含义：知识沉淀应包含能力、条件、来源、适用实例和状态，而非只保存一段商品简介；Skill 保存可迁移的思考方法，具体型号事实保存在可纠正的知识中。

### 2.2 Stanford STORM 值得学习怎样研究

[STORM 官方项目](https://github.com/stanford-oval/storm)主要用于互联网研究和带引用的长文写作。它从多个视角产生更好的问题，通过基于来源的模拟对话继续追问，再整理知识；不是生活用品创造力引擎。仓库本轮读取的根许可证信息为 MIT，不能凭旧印象写成 Apache。

可迁移的方法：不要只搜索完整商品名。围绕目标效果、物品能力、相近原理、可替代材料与已知失败寻找案例；读到具体内容后，再决定它是否对当前问题有帮助。

例如要把已有设备做成更个人化的展示，可以从日常信息呈现、物品故事展示和可调整软件入口等不同角度找启发。无需把整个长报告流程装进每次对话，普通问题也不必进行多角色研究。

### 2.3 SciMON 值得学习怎样借鉴并产生区别

[SciMON 论文](https://aclanthology.org/2024.acl-long.18/)由 Qingyun Wang、Doug Downey、Heng Ji、Tom Hope 提出，研究科学创意：检索历史论文中的启发，生成想法，再与已有工作比较并迭代改善新颖性。[作者代码与资源](https://github.com/eaglew/clbd)属于研究参考，不是物间可直接部署的用品创意服务；本轮核对论文，未部署该代码。

可迁移的判断是：收集案例后应提炼奏效原理，结合用户物品形成有区别的方案，而非复制表面步骤。科学创意任务的研究结果不能当成生活改造的实际有效证据；生活物理条件仍须独立验证。

### 2.4 物间可以形成的最小探索过程

1. 理解用户想要的效果；没有明确目标时，寻找其有兴趣的方向。
2. 查找获准且相关的物品、当前状态、能力和实际限制。
3. 必要时沿目标、原理和案例查资料，读取原文或可用视频内容，取得条件而不只看标题。
4. 形成少量机制不同的候选，说明各自的新价值。
5. 用户选中后，核对关键资源和条件，给出低负担的试法或说明缺口。
6. 反馈回到原方案与物品认识，条件变化后重新判断。

这是一种可弹性执行的方法，不是每次必须走六次模型调用。现有 `agent_skills/creative-use/SKILL.md` 已表达其中部分方法；需要用实际结果判断模型是否真正遵循，不能继续只往 Skill 追加口号。

案例至少应保留原链接、原案例的问题和资源、关键原理、适用条件、与当前物品的差异、未知与实际结果。它先是参考案例，不自动成为当前实物已经具备的能力。

候选例子是旧屏幕、物品照片和个人记录共同形成回忆展示窗；它必须先确认实际连接、控制入口和用户授权，不能只因有屏幕照片就宣称可执行。这里演示组合思路，不作为已验证方案。

### 2.5 外部内容取得与创造判断分开

现有百炼搜索和网页/PDF 读取先作为基线。正文或动态页面确实读不到时，才针对真实页面比较成熟提取工具。此前记录过 Trafilatura、Crawl4AI 等候选，本轮未重新运行，不将其视为已选依赖。

小红书、B站等可以提供启发，但具体内容的可访问性、正文或字幕、来源可信度和使用条件仍需实际确认。取得一个标题不等于看过教程，公开案例存在不等于适用于用户物品。无需为了借鉴内容立即建立公开社区。

## 3 理解人如何增强

### 3.1 需要分清四类内容

| 类别 | 例子 | 处理方式 |
| --- | --- | --- |
| 用户明确表达 | 不要剪这块窗帘 | 保留对象和情境，当前任务必须遵守 |
| 临时条件 | 今天很累，只想花十分钟 | 影响当前安排，不自动永久化 |
| 有依据的偏好或习惯 | 多次明确选择简洁说明 | 用于相关场景，允许例外与纠正 |
| 推测与候选解释 | 可能更在意礼物故事而非改造 | 带依据和不确定性，不冒充稳定人格 |

回忆墙保存用户主动留下的内容。系统对人的理解是另一类可更正的认识，不能把每句聊天公开成故事，也不能每条都要求用户点保存。

### 3.2 ReMe 是最值得先充分评估的已有基础

当前项目固定 `reme-ai==0.4.2.1`，已用于检索；AgentScope 固定 `2.0.11`。主 Agent 已有结构化知识与个人理解更新，现有审计仍记录情境、遗忘和结果等缺口。

本轮阅读 ReMe 当前主分支的 [Auto Memory](https://github.com/agentscope-ai/ReMe/blob/main/docs/en/auto_memory.md) 与 [Auto Dream](https://github.com/agentscope-ai/ReMe/blob/main/docs/en/auto_dream.md)：

- 从对话提取未来有用的内容，并保留来源对话依据。
- 日常记录与长期可复用理解分层。
- 长期整理包括强化已有理解、补充适用条件和纠正错误。

这与物间安静理解人、积累有效经验的目标接近。需要注意，这些文档对应当前主分支，不代表本地固定版本都具备同样能力。自动文件写入不能直接与现有 SQL 的事实更新同时生效；应在隔离环境比较后决定怎样复用，必要时替换旧职责而非长期双写。

本轮根许可证核对为 Apache-2.0。未升级、未启动 Auto Memory 或 Auto Dream。

### 3.3 Honcho 更值得研究从记住到理解的过程

[Honcho 官方仓库](https://github.com/plastic-labs/honcho)将消息和事件存入会话，后台更新对参与者的认识，再通过检索、表示或自然语言查询为主模型提供上下文。它可以建模随时间变化的人、群体和其他参与者，不限于保存一张静态用户标签表。

本轮读取了其 `src/deriver/prompts.py`：观察提炼阶段明确区分消息作者，要求保留来源和情境；其他人的话只帮助解释，不能直接拿来推断目标用户的事实。这样的主体区分对物间的礼物故事、家庭信息和分身非常重要。[源码](https://github.com/plastic-labs/honcho/blob/main/src/deriver/prompts.py)

可借鉴的问题是：用户做出某种选择时，哪些是明确事实，哪些是情境中的可能解释？下一次换情境后，解释是否仍适用？能否回到依据并接受纠正？

建议将其列为理解人的独立技术探针候选，而非直接接管所有事实。后台处理是异步的，新消息不保证立即反映在长期表示里；当前用户的明确输入仍须直接提供给主模型。

根许可证核对为 AGPL-3.0，自托管与托管服务也不是同一种接入方式。核心实现阅读到了 OpenAI、Anthropic、Gemini 等传输配置，本轮没有完成百炼适配实验，不能承诺换一个地址便全部兼容。引入前需检查具体版本、部署和许可条件；无需为了研究先开托管账户。

### 3.4 Mem0 是可比较的记忆实现 但旧介绍需要更新

[Mem0 当前 README](https://github.com/mem0ai/mem0)描述 2026 年 4 月更新后的写入方向：以单次模型提炼和新增记忆为主，结合多信号检索、实体和时间线索。不能继续把早期新增、修改、删除、不变的提示流程当作当前全部机制。

本轮核对了 [`mem0/memory/main.py`](https://github.com/mem0ai/mem0/blob/main/mem0/memory/main.py) 中的 V3 写入路径：读取近期消息与候选旧记忆，调用提炼提示，批量向量化并写入；部分旧函数说明文字仍提增改删，应以实际路径而非单个注释判断。

它适合做同输入、同模型下的记忆提炼与检索比较。当前 README 同时说明展示的托管平台基准包含开源 SDK 不具备的优化，不能把平台成绩当作接入开源库后的效果保证。根仓库元数据标识 Apache-2.0。

新增为主也不代表没有删除 API，更不代表自动满足用户遗忘、当前事实选择和物间的权限要求。本轮不安装，不同时启用 ReMe 与 Mem0 两个长期理解写入者。

### 3.5 Graphiti 对事实随时间变化有参考价值

[Graphiti 官方仓库](https://github.com/getzep/graphiti)把实体、关系、有效时间和原始事件依据组织起来，区分现在成立和历史上成立的事实。适合研究曾拥有、现借出、关系变化和偏好变化等表达。

不过它是构建和查询时间关系图的框架，需要使用者提供数据库、模型、检索及周边权限和运维。它不自动成为完整的个人理解产品。根许可证为 Apache-2.0。

物间当前可以先在已有事实中正确表达情境、时间和失效关系；只有真实关系查询与规模使现有机制明显不足时，才比较图数据库接入，不能为了世界模型这个名称先换库。

## 4 数字分身如何形成

### 4.1 四个相连的部分

| 部分 | 具体内容 | 可以复用什么 |
| --- | --- | --- |
| 身份与表达 | 对应哪件物品、名字、风格与人格倾向 | 主模型、明确角色设定及共同身份 |
| 真实经历 | 谁说过什么、谁经历过什么、允许引用什么 | 物间原经历与可纠正理解、记忆工具 |
| 可用能力 | 能解释用法、参与任务，或在授权下操作 | 原有知识、任务和工具能力 |
| 可见可听的呈现 | 形象、表情、动作、语音和配饰 | 成熟生成模型与轻量渲染、按需参考角色项目 |

一件礼物的分身不必复制赠送者整个人。可以保留对方明确提供的寄语和表达，又与接收者建立自己的新经历；赠送者未表达的想法不能由模型冒充。

### 4.2 Generative Agents 值得学习经历 反思与行为的连接

Joon Sung Park、Percy Liang、Michael Bernstein 等作者的 [Generative Agents 论文](https://arxiv.org/abs/2304.03442)与[作者代码](https://github.com/joonspk-research/generative_agents)研究可持续行为的虚拟角色，连接经历记录、较高层反思、相关回忆与计划。其目标是模拟可信行为，并未证明系统准确理解了现实用户心理。

对物间可迁移的是有依据的逐渐变化：几次真实相处之后，分身的表达可更贴近用户习惯，引用真实事件，而非每轮临时生成一个人设。无需搬入整个虚拟小镇，也不需要每句话都进行额外反思或调用多角色。

本轮同时阅读作者检索模块，看到近期性和关联记忆等组织方式。研究代码不能当作现代应用的直接生产底座，其旧环境、示例模型和依赖须独立评估。

### 4.3 AIRI 更适合参考表达层

[AIRI](https://github.com/moeru-ai/airi)提供角色交互、语音、Live2D／VRM 等方向，官方 README 列出移动浏览器与 PWA、语音输入和多提供商语音输出，包含百炼语音服务。根许可证核对为 MIT；模型资产和依赖仍应按具体选用内容分别检查。

值得参考其形象、口型、表情、语音与对话状态的配合方式。当前 README 同时把部分记忆能力列为开发中，不能把它当作已证明成熟的理解人系统。

它是完整角色应用且使用不同的前端组织，不能假设整仓复制到物间 React 界面就是低成本复用。应选需要的机制或可独立复用组件，并保留物间作为事实与任务来源。

### 4.4 Open LLM VTuber 可参考 但不要混淆组成部分

[Open-LLM-VTuber](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber)值得参考实时语音、打断和表情控制。当前 README 说明长期记忆暂时移除、聊天记录持久化仍在；不能据此称其已经解决长期理解。

本轮分别读取根仓库与前端许可证：根后端为 MIT，但[前端仓库](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber-Web/blob/main/LICENSE)采用带附加条件的许可证；样例 Live2D 模型另有条件。不能把整个组合笼统写成完全宽松的开源组件。

目前将其作为交互机制参考，不优先整套嵌入。具体商业使用条件须按拟用组件确认，本稿不作法律合规结论。

### 4.5 物品形象可以怎样长出来

物间中的杯子、石头和花不一定适合完整人形骨架。首个候选可先使用有稳定身份的二维形象，再增加少量表情或可变化配饰；是否需要 Live2D 或三维，取决于真实体验收益与手机性能。

用户选择启用分身 → 以实物照片或自选意象产生候选 → 选定基础形象与表达 → 获准真实经历影响称呼与关系表达 → 重要变化产生可检查的形象版本。

Qwen 官方的 [Qwen-Image-Edit 介绍](https://qwenlm.github.io/zh/blog/qwen-image-edit/)展示语义与外观编辑及角色一致性方向；[百炼图像编辑 API](https://help.aliyun.com/en/model-studio/qwen-image-edit-api)提供多图编辑等能力，可作为生成和编辑资产的候选。官方示例不是对任意物品形象一致性的保证，仍需以选定角色连续编辑检验。

例如与某段真实经历相连的配饰，可以成为候选成长细节；须由已知故事或用户选择支持，不自动编造旅行。以既有基础形象作参考、保留已选版本与用户回退路径，比每次从零重画更符合连续成长目标。

本轮没有生成图像或调用该 API。生成资产、角色渲染和长期行为是不同能力，不需要同时接入全部项目。

## 5 一手工程方法怎样用于物间

[Anthropic 上下文工程文章](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)强调按需组织高价值信息、清晰工具、动态读取和持久笔记，避免过度堆积上下文与脆弱提示规则。

用于物间：当前问题需要时查回型号资料、相关经历或任务，不把全库存和所有私密记录塞给模型。偏好摘要不能替代原证据；模型可以自行补查，程序维护身份、来源、权限和真实动作边界。普通问题保持轻量。

这是一种工程原则，不能把 Anthropic 自身文章当作百炼或某记忆库已经通过验证的证据。

## 6 面向物间的候选取舍

| 候选 | 最有价值的用途 | 当前取舍 |
| --- | --- | --- |
| ReMe 当前完整记忆方法 | 日常材料到长期理解、经验提炼与依据 | 优先做版本核对和隔离比较，已有基础不无故替换 |
| Honcho | 对变化中的人和关系持续形成认识 | 理解人方向的重点探针，先验证百炼和具体业务效果 |
| Mem0 | 记忆提炼、实体及多信号检索的替代基线 | 与 ReMe 比较，避免同时双写；注意主分支与旧资料差异 |
| Graphiti | 带时间的关系和事实演化 | 暂不换库，先验证现有模型是否确有不足 |
| STORM | 多视角研究、问题深化与来源组织 | 借鉴或适配研究部分，暂不整套嵌入每次请求 |
| SciMON | 案例启发与迭代检查新颖性的研究方法 | 方法参考，生活用途迁移须另验 |
| Generative Agents | 经历、反思、相关回忆与行为连续性 | 方法参考，不搬完整虚拟环境 |
| AIRI | 角色、语音和表情协同 | 按具体表达需求研究组件与适配成本 |
| Open LLM VTuber | 语音打断与 Live2D 交互 | 备选参考，当前记忆与前端许可限制需识别 |
| Qwen 图像编辑 | 基础形象和连续变化的视觉资产 | 用户启用分身后再验证，不启动生成调用 |

这些是用途不同的候选，不能用同一排名决定采用。优秀研究项目、可部署库、完整应用和托管服务的成熟度与职责也不能互换。

## 7 接入前的三个最小验证

### 理解人探针

先以现有主模型、有效业务事实和 ReMe 作为基线，再比较一种新方法。样例包含长期偏好与今天例外、朋友的经历与自己的经历、同一句话不同情境、明确纠正、遗忘和跨用户边界。检查后续行为是否更合适、能否给出依据，并记录延迟和费用。

Honcho 的后台处理与即时请求分别评测。任何候选不能靠忽略当前更正来换取长记忆命中率，也不能将用户自设偏好推断成稳定人格。

### 创造力探针

用相同物品与条件，比较现有流程、加入真实案例研究、加入原理提炼与适配后的结果。覆盖单物、多物、无目标探索和严格禁止条件。保留首次输出，独立评价新颖性、有用性、资源适配与可行性，选中后再验证实际尝试。

案例研究能增加信息时，要将信息获取的增益与推理方法的增益分别分析；不能暗中给某一方标准答案。来源、模型与成本条件一致或清楚披露。

### 分身探针

以一件有真实故事的非标物和一件有型号知识的商品比较：是否引用准确、角色连续、个性化有帮助、更正有效、接收礼物后不混淆作者。用户选择开启视觉时，再验证同一基础形象多次编辑是否仍可辨认，以及手机体验和资产许可。

体验好看、语音流畅和记忆准确分别评估，不能用其中一项代替其他项。所有能力变化应服务四栏共同体验，不能在分身项目里产生第二份私人事实系统。
