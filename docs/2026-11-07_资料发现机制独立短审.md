# 资料发现机制独立短审

范围为本轮冻结的 `source_content.py`、`knowledge.py` 及新增资料发现测试；仅离线分析和临时数据库，没有调用模型、真实设备或主库，也没有重启服务。

## 结论

未复现新增 P0/P1。wrapper、脚本和查询参数只提供候选导航，不自动执行或读取目标；空正文返回 `content_available=false` 和 `navigation_only_not_document_content`。实际网络请求仍经过公共地址检查、DNS 固定、重定向复查。词项候选保留 `query_matched=false`、`query_match_type=terms` 及原文，没有把型号相邻字符串作为准确型号适用证据。

独立找到两项 P2，首失败已用新回归复现，随后经主 Agent 授权局部修复：

1. **坏 script URL 使可读正文全丢。** `<main>Actual manual body</main><script src="http://["></script>` 原先在脚本资源标题提取的 `urlsplit` 抛 `ValueError`，未进入安全添加逻辑。现在忽略该坏声明，保留真实正文和其他有效资源；没有放松实际下载校验。
2. **无 `.js` 扩展名的 JS MIME 被标成普通正文。** `application/javascript` 响应来自 `/runtime?version=3` 时，原文虽未执行，却被 `source_content_level` 标为 `document_text`。现在从来源所在的现有 SQLAlchemy 会话读取同属来源所有者的原始 Asset MIME，统一识别新读取、缓存读取和 `read_source` 的代码读取深度。没有新增数据库字段、解析引擎或网络调用；缺少原始 MIME 的旧来源才沿用扩展名回退。

## 对抗验证

新增 `tests/test_document_discovery_adversarial.py` 共 6 项，涵盖两项 P2 反例及以下边界：

- 编码的回环/metadata地址、协议相对跨域、userinfo、换行和反斜杠不能成为 wrapper 的同源 query 候选。
- 超过 50 个参数、超过单候选长度的值，以及脚本未声明的参数不会生成 query 候选。
- iframe、script 中的内容不会冒充 wrapper 已读取正文，资源保持“未读取/未执行”说明。
- 词项匹配不会将不存在的完整查询标成 exact；`ABC100` 不会成为原文 `ABC1000` 的匹配词项，返回原文保持原样。

额外只读反例确认：网页确实声明的私网 script URL 可作为未读候选显示，但进入实际 `resolve_public_url` 时仍被拒绝，未出现 SSRF 或脚本自动执行。

## 验证记录与限制

修复前两项 P2 均红：坏 URL 抛异常、extensionless JS 深度断言失败；修复后新增 6 项及原发现 10 项合跑 **16 项通过**。来源图片、引用呈现、导航相关回归另按实际受影响范围复跑 **25 项通过**，未为两个边角重复整仓回归。修复前已另运行公共网络/来源/导航/搜索证据 **38 项通过**，此记录不冒充修复后全量结果。

新候选页匹配只是一层有限页数上的词项排序，未新增向量库、模型调用或站点专用 API 层。它仍不证明章节实际适用、用户照做后有效，或独立真实模型的资料发现任务已经验收。该真实任务的首失败、超时与后续复测继续按原验收记录表达。
