# 决定、替代方案与仍待验证的问题

日期：2026-10-29。依据第一阶段审计、当前 main 源码、本轮离线回归、真实模型原始记录及隔离 Pi 小实验。没有用框架演示例子证明物间应迁移。

## D1：先修业务契约，保留 LangGraph

已证实的库存指代、否定活动、属性裁剪、公开单回合和校验误拒都是业务实现问题。搬到 Pi 不会自动消失。本轮复用数据库与前端，新增统一物品卡和只读工具，保留权限、记忆过滤、幂等和确认写入。

比较了整体替换、继续加局部分支、统一契约三个方案。选择统一契约加小范围修复：改动可隔离验证，避免引入会话迁移和平台迁移。未知假设：统一物品卡能否在更多真实物品上稳定提高建议质量；当前有限正则仍有误拒和漏检。元数据问题可按登记直接回答，但不能用更多硬编码答案替代全部模型理解。

## D2：生成候选与验证事实分层

登记不等于认证；官方型号能力不等于实物状态；模型提出的用途不等于物理验证。模型默认给一份创意，保留多候选参数；候选失败可给明确标注的本地方案，不能以“AI 成功”展示。

不采用“只要加免责声明就放行”，也不把所有未知任务一律拒绝。有明确前置条件时可提出条件式探索；未经确认的饮食、温度、承重与设备专属能力不能作为事实。哪些场景优先追问、哪些优先条件式候选，仍应由下一轮盲评和产品选择决定。

## D3：Pi 是独立运行核心候选，尚无迁移结论

核对官方 [Pi 仓库](https://github.com/earendil-works/pi)、[Core](https://github.com/earendil-works/pi/tree/main/packages/agent)、[Durable](https://github.com/earendil-works/pi/tree/main/packages/durable) 和 [Cloudflare Pi Harness](https://developers.cloudflare.com/agents/harnesses/pi/)。本轮远端 HEAD 为 `df9275d4347f187610804c71d52e7c46bfd14848`，晚于审计报告当时的 HEAD；这是版本推进，历史记录没有改写。实际安装验证使用独立锁文件中的 **1.4.0**，不把 main 文档与 npm 发布包假定为同一份代码。

| 选择                  | 对物间的具体价值                                                      | 本轮事实与边界                                                      | 迁移难点                                                                                   |
| --------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 现有 LangGraph 1.5.1  | 已有检查点、人工中断、领域确认、记忆 epoch 与会话幂等                 | 本轮本地／公开工具循环与既有回归；现有持久化不是空白                | Graph 很大，不同生成路径策略仍不完全统一；宿主调度不等于框架自带                           |
| Pi Agent Core 1.4.0   | 较直接的工具循环、事件、执行前后钩子，可复用物品工具                  | 本机离线工具往返和撤权测试通过；未接百炼                            | 自己接现有 Provider、费用记账、会话、恢复与输出验证；Core 小实验没有自动持久化             |
| Pi Durable 1.4.0      | Node + SQLite 持久任务、提交去重、可声明安全重放工具                  | 本机正常关闭重开、已完成提交去重、撤权测试通过；官方标 experimental | 异步存储与现有同步事务边界、版本演进、重试成本、外部动作幂等；未强杀中途任务               |
| Cloudflare Pi Harness | Durable Object 生命周期、存储和运行环境接入，适合确有托管长任务需求时 | 官方 SDK 0.30+ 支持 Pi ~1.4.0；本轮未安装／部署／计费测试           | 增加 Wrangler、DO、账号和数据边界；不自动提供物间业务授权，也不要求采用 Pi 就迁 Cloudflare |

官方 Durable 明确支持 [Node SQLite](https://github.com/earendil-works/pi/tree/main/packages/durable#persist-and-resume)。安全重放工具仍需业务幂等保护；进程中断后的模型尝试可能重发，必须受物间费用台账控制。Cloudflare 版本兼容与生命周期见其官方文档，不据此声称它已解决工具审批。

最小 PoC 位于 [experiments/pi-item-loop](../../../experiments/pi-item-loop/README.md)，只用物间相同只读工具、合成库、模型替身。它证明契约可以包一层适配器供不同核心使用；不证明 Pi 比 LangGraph 更聪明、更便宜或更适合真实设备。

**允许只换运行核心**：后续可保留 Item ID、业务 SQLite、Next API／页面、知识获取、只读工具、领域写命令与确认；新增运行适配接口和独立任务库。旧 checkpoint 不直接改格式。是否整体重构，至少要有同业务故障注入收益、维护复杂度下降、费用可控、授权与幂等无退步，以及明确的长期任务产品需求。

## 下一轮优先级与三个实验

**优先物品创意质量验证。** 本轮已经打通信息和工具路径，但创意被过滤或降级仍存在；没有独立创新度证据。设备能力探索需要更具体的目标设备和授权边界；Pi 更适合在长期任务需求明确后继续比较。

1. **创意盲评与低风险实践**：冻结 24 场景的独立留出集，比较同模型直接回答与物间；匿名打乱给真人评相关性、惊喜、条件清晰、可实施性。自动查资源／约束，人工核查关键机理；选 3–5 个低风险纸笔或收纳例子实际尝试。只新增评测和少量提示实验。产品负责人需选优先人群／场景、惊喜与稳妥权重，以及是否参加实践；本轮没有代做物理验证。
2. **更可靠的物品前提契约**：在模型输出中试验结构化“所用性质—来源—必要条件—未知项”，让服务端按引用核对，减少长文本关键词误拒。沿用属性存储与授权。自动标准：新增未见过的同义句／反例，限制漏传 0、越权 0、独立假阳性集有界；不以生成模型自己打分证明质量。需要确认缺信息时追问与条件式候选的默认体验。
3. **运行核心故障对照**：沿用本轮工具，给 LangGraph 与 Pi Durable 同样的崩溃点、撤权、重复 requestId、确认暂停与模型超时；统计恢复状态、重复写回执、收费尝试、适配代码量。新增独立实验，不改生产默认；成功标准应包括撤权后 0 写、重复提交 0 外部重复动作、未知费用尝试不漏账。迁移框架／部署平台／真实设备控制仍需单独产品决定。

现有 Node、测试、Playwright／Edge、GitHub 和 Mermaid 已足够完成本轮。未新增 MCP 或安装 Understand Anything、CodeGraph、agent-browser；当前问题先由可复现契约测试定位，额外索引工具不能代替行为验证。Skills、Goals 是研发协作能力，不是物间的任务持久化方案。
