# 物间决赛升级｜第一阶段技术基线

审计日：**2026-10-29（北京时间）**。基准：[GitHub main / ea32c3f](https://github.com/Starry-Curry/ProductAgent/commit/ea32c3f4c9e18992ca267b6dd74e26e418c9e95a)。本轮仅增加审计脚本、文档与合成测试证据，未改变产品功能、框架、真实数据或部署。

## 给产品负责人的一页概要

**物间已有能运行的产品底座，但还没有可靠理解和创造新用途的通用 Agent。眼前最值得投入的是修正业务链路与质量验收；现有证据不足以决定换框架。**

它已能登记物品及型号、读取有限资料包和导入说明、保存图文故事、管理可撤回的记忆、生成创意候选、确认家庭事项、传递选中的礼物故事。上述功能共用 SQLite、物品 ID 和权限体系，已有联系。模型不会直接改数据库。

但“共用数据库”不等于每次回答都理解了全部物品条件。清单工具只给名称和状态，丢掉材质、限制和能力；复验中模型因此建议用一只食品接触和耐热条件未确认的杯子喝温水。即使选中杯子、把限制传给模型，另一条回答仍说“可安心使用”，校验放行。这是本轮明确暴露的质量缺口，不能靠免责声明补救。

不少体验是有限实现：鼠标规格可直接使用精选资料回答，**没有调用模型**；摄影出游准备是**本地规则**，不是开放任务规划；新访客物品、故事和四个创意是**合成演示**。设备控制、协议探索、动态生成控制台、成熟的物品形象交互、真实家庭账号和跨设备通知尚无成熟实现证据。

“不智能”已有具体原因：自然说“只用我已登记的物品”会被误判，创意在模型调用前退出；公开演示每轮只许一次模型请求，工具查完后无法再让模型作答；宽泛提示词与正则校验仍会漏掉不成立的物理说法。真实 Qwen 的直接回答同样出现鼠标留印、共振等无依据机制，**不能据此认为直接问千问或换 Pi 就一定解决问题**。

工程基线较稳：191/191 离线测试、类型检查、构建通过；主要页面与桌面/390px旅程可运行。两组浏览器测试默认路径错误；公开测试定位器过期。指定 Edge、在单独审计副本更新定位器后可继续通过，原失败均保留。旧基准仍有一条正确改写被拒，绿色检查不等于产品质量达标。

本轮百炼 **22/40 次尝试，21 次 HTTP 200、1 次超时**；已返回输入 31,805 / 输出 8,019 tokens，按公开原价估算这些已知用量约 **¥0.0415**；超时用量和实际账单未知。没有使用真实私人库存或操作实物。

建议下一轮先做“物品条件与工具往返修正”的小实验，再做同模型、同上下文的质量盲测，最后用模拟故障比较 LangGraph 与 Node + SQLite 的 Pi Durable。是否正式迁移、开放设备写权限、部署云端均需产品负责人另行决定。
