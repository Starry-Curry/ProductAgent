# 物间 0.2 开发验证记录

日期：2026-11-04。结论：已经形成可运行、连接四类价值的本地开发版；不等于产品智能质量正式验收通过。REA 实机操作按用户要求留到晚上。

## 知识问题观察

测试物品：索尼 WH-1000XM5，中国大陆销售型号。问题：已有旧手机配对信息，再连接新手机时，电源按多久、指示灯如何变化。

模型实际找到了并读取 [索尼中文配对指南](https://helpguide.sony.net/mdr/wh1000xm5/v1/zh-cn/contents/TP1000534976.html) 与 [指示灯指南](https://helpguide.sony.net/mdr/wh1000xm5/v1/zh-cn/contents/TP1000534895.html)。首次运行的关键答案“约 5 秒、蓝色双闪”有原文支持；也记录了适用条件和来源。

但首次回答额外展开了设备上限，并把原文的“连接时间最早”简化成“最早配对”。这说明有来源仍可能转述失真，不能据此宣布知识服务稳定可靠。另一轮创造对话也出现了未经原文核对的亮度、色温数值和过度肯定的体验效果。已调整一般性表达与证据要求，避免针对具体测试题预置答案；仍需陌生题集和人工审阅检验。

首次知识探索耗时约 131 秒；主要模型累计输入 33047、输出 564 tokens，**不含搜索和页图子调用**。该次搜索默认思考造成额外等待。随后将公开搜索子调用关闭思考、主模型思考保持可配置；复测实际完成搜索与原文获取，耗时 37.81 秒，主要模型输入 20228、输出 732 tokens。两次检索和读取路径也有差异，不能把全部时间差归因于一个配置。

复测核心操作条件仍有原文支持，但末尾仍有用户未询问的设备上限和旧手机连接建议，其中部分措辞与原文边界不够清晰。因此当前只认定真实检索/阅读链路和本题关键回答成立；不把该题整体当作知识服务质量已经验收通过。

私人理解复测约 13.34 秒，新会话检索回答约 3.98 秒，示意画描述与身份写回约 35.97 秒。这些只是本机、本次调用观察，不是性能 SLA；未给出未经核算的总费用。

## 采用与排除的实现

- AgentScope SDK 2.0.11 负责模型循环、工具事件、状态和上下文压缩；不自造第二套 Agent 调度器。
- FastAPI + SQLAlchemy 承担物间领域 API 和事务。本机缺少 PostgreSQL 服务，先用 SQLite，避免为本地切片增加部署依赖；PostgreSQL 尚未验证，后续需要迁移和驱动。
- Pydantic → OpenAPI → openapi-typescript → TypeScript，公共结构只有一个来源。没有引入自定义“模型语言”或以向量代替精确事实。
- React + Ant Design / Ant Design X Sender 复用成熟界面组件；业务界面与模型调用同一套 domain 操作。
- 百炼 Responses `web_search` 返回真实工具记录与来源。Chat Completions 搜索探针没有可核对的搜索记录，未采用为已验证路径；EnhancedSearch MCP 曾返回 Not Found，未修改用户全局配置，使用已工作的百炼路径继续。
- 原始资料保留文件，提供可追溯的片段和 PDF 页图工具；单个下载有大小和公开地址限制。原始 HTML 以附件下载，避免在应用同源执行。

参考一手资料：[AgentScope 2.0.11](https://github.com/agentscope-ai/agentscope/tree/v2.0.11)、[百炼 Responses](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-responses)、[Google 简洁性](https://sre.google/sre-book/simplicity/)、[DORA 小批交付](https://dora.dev/capabilities/working-in-small-batches/)。实际应用是先验证跨功能切片、共用领域操作、复用成熟循环与生成契约，而非将文献标题变成额外架构层。
