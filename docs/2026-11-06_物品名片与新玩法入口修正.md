# 物品名片与新玩法入口修正

依据本轮用户修正：物品列表点击后应进入完整物品名片；新玩法是入口，仍回到第一部分与阿圆聊天。继续保留四个栏目，不新增玩法页面或第五个导航。

## 最终交互

- 点击家庭或个人物品，主内容区显示完整名片：照片、身份、位置、状态、私人介绍、可选分身、经历、资料和照顾记录。列表与详情不再并排，返回时保留当前列表的筛选与滚动位置。
- 名片只显示“发现新玩法”入口。点击后回到物伴，携带当前物品与创意意图；不会在名片内自动生成或展示玩法。
- 物伴本身也保留新玩法入口，手机可直接看到。用户在同一聊天中补充目标、限制或照片，明确发送后才开始检索和生成。
- 新玩法聊天旁显示实际找到的公开资料，区分搜索线索与已读原文；手机在聊天内展开。打开历史话题可恢复同一回复及来源。

## 接口与事实来源

新增 `POST /api/creative-explorations`，输入为目标、条件、现有物品 ID 和可选照片。它复用现有 `/api/chat` 的身份检查、会话、Run、AgentScope 主循环与最终结果提交；持续追问仍用原聊天接口。方案仍保存在现有 TaskRecord，不建立第二个 Agent 或独立方案库。

工具成功执行公开搜索和原文读取时，在同一 Run.events 中保留 `research_search` 和 `research_source` 记录。前端根据这些实际结果显示来源，而不是从模型答案中猜测或合成链接。已有工具权限仍由公共业务层控制。

创意模式产生持续方案时，需要在当前会话中有真实搜索和仍可读取的公开原文；资料不足或需要澄清时可以说明情况，不伪造来源。这个检查证明取得了资料，不保证每个建议都已在现实中验证。

- 54 项离线回归通过，包含新增入口权限、空目标、来源记录在进度/最终保存后保留、无实际研究不发布持续玩法方案，以及澄清时不编造来源。
- TypeScript 检查、生产构建与契约生成通过。
- 电脑 1440×960、手机 390×844 浏览器核对完整名片、返回筛选、两处入口回到物伴、携带物品、明确发送路径与失败草稿保留；5 个布局场景无横向溢出及页面异常。

真实调用验证了连接、检索、读取与保存链路。案例与当前资源的适配、操作原理准确性、创意质量和当前响应耗时仍需后续模块改进，不把本轮界面修正或来源存在当作实物效果验收。
