# 物间交互基础版本与模块接口

本轮依据《2026-11-05_物间手机版整体产品与交互设计稿》及用户提供的六张电脑端界面参考，建立后续分工共用的交互基础版本。设计稿中的“本轮不修改代码”属于当时的设计阶段说明；本次实施依据用户随后明确的开发、验证和提交 develop 授权。原设计稿保持原文。

## 本轮形成的界面

普通版为 **物伴、物品、回忆、朋友** 四个栏目。电脑端采用左侧导航、中间操作区和右侧上下文区；手机端采用底栏、详情返回及纵向展开的事项清单。大字版保留问一问、拍给我看和家人提醒入口，普通版与大字版操作相同业务记录。

- 物伴：全局物伴、文字与照片草稿、已有 AgentScope 流式任务、历史话题、持续事项、逐步指导、准备清单、实际反馈和可编辑的售后说明。
- 物品：家庭用品与我的物品、搜索与房间筛选、当前状态、珍藏、多物关联的经历、知识来源、可选分身、家庭与单人分享、既有设备连接入口。
- 回忆：一份照片文字记录、多物关联、查看与放大、编辑、删除、明确选择好友分享、单独控制是否允许物伴参考。
- 朋友：邀请与接受、仅获准内容的主页、主动开放的想要、礼物预览、取消、婉拒与数字接收。想要不写入持有物品；数字接收不代表实物交付。

没有照片的物品使用明确的图形占位；不会为实际物品伪造照片。体验账号中的人物、持有关系、场景与进度标记为合成数据。洗衣机示例只提供核对型号、取得资料和记录检查的流程，没有预置维修结论或伪造说明书。

## 不变的共同底座

继续使用 Python/FastAPI、SQLAlchemy、AgentScope 单主循环、ReMe 可重建检索投影和现有 REA 适配。新增 `interactions.py` 负责同一业务记录的页面投影及明确界面动作；`interaction_routes.py` 暴露契约。没有新增模型供应商、独立 Agent、第二份记忆库或独立任务事实库。

物品仍是 `ItemRecord`，个人介绍与分身仍在 `Profile`，回忆仍是 `ExperienceRecord`，日常理解仍是 `Memory`，持续事项仍是 `TaskRecord`。家庭关系、心愿和选择性授权作为必要关联数据保存。

前端按 `frontend/src/features/` 拆分：

| 模块 | 职责与交接边界 |
| --- | --- |
| `App.tsx`、`navigation.ts` | 账号工作区、导航、当前话题、草稿、流式运行、显式事项接续 |
| `Conversation.tsx` | 消息与实际进度、输入、拍照、语音识别兼容与停止 |
| `TaskBoard.tsx` | 步骤、清单、邀请接手、负责人、真实反馈、售后说明 |
| `Items.tsx` | 家庭/个人列表与同一物品详情，复用知识、经历与设备入口 |
| `Memories.tsx` | 同一条回忆的墙、查看、编辑与范围管理 |
| `Friends.tsx` | 好友主页、心愿、礼物接收与结果 |
| `Care.tsx` | 提醒阅读、接手、完成、重新处理与朗读 |
| `Editors.tsx` | 基础表单；后续可按业务拆分，沿用既有接口 |
| `shared.tsx`、`styles.css` | 共同组件、照片与占位、普通版/手机/大字版样式 |

浏览物品不会重置当前对话对象。只有明确提问、另起话题或接续事项才切换上下文。未发送草稿在同一页面会话的跨栏目操作中保留；失败发送保留文字与附件。草稿未存入浏览器长期存储，刷新前请先发送或保存为记录。

## 接口映射

输入输出以 `wujian/api_models.py` 为准。运行 `python -m wujian openapi contracts/openapi.json` 后，再运行 `npm --prefix frontend run types`，不可直接改生成类型。

| 使用场景 | 接口 |
| --- | --- |
| 四栏共同数据、名字和显示版本 | `GET /api/workspace`、`GET/PUT /api/preferences` |
| 创建家庭、邀请、接受、退出/移除、明确加入用品 | `/api/households`、`/{id}/invitations`、`/{id}/accept`、`/{id}/members/{user}`、`/{id}/items` |
| 同一物品与当前展示状态 | 既有 `/api/items`，新增 `PATCH /api/items/{id}/presentation` |
| 回忆保存、版本化编辑/删除 | 既有 `GET/POST /api/experiences`，新增 `PUT/DELETE /api/experiences/{id}` |
| 回忆单独分享与撤回 | `/api/experiences/{id}/shares`、`/{user}` |
| 理解检查、更正与遗忘 | 既有 `/api/memories`，新增 `POST /api/memories/{id}/correction` |
| 照顾与反馈 | 既有 `/api/reminders`，新增 `POST /api/reminders/{id}/feedback` |
| 整理事项与呈现当前清单 | `POST /api/task-boards`、`GET /api/tasks/{id}/board` |
| 实际条目进度、分工 | `PATCH /api/tasks/{id}/entries/{entry}`、`/{entry}/assignee` |
| 事项参与、接手与撤回 | `/api/tasks/{id}/shares`、`/{id}/accept`、`/{id}/shares/{user}` |
| 同一事项继续聊 | `POST /api/tasks/{id}/conversation`，同人同事项重复调用返回同一会话 |
| 事项实际结果 | 继续使用 `/api/tasks/{id}/feedback` 和版本化 `/api/tasks` |
| 入口意图与既有模型运行 | 既有 `/api/chat` 增加可选 `entry_context`；仍用原 `/api/runs`、事件流与取消 |
| 获准好友主页与独立心愿 | `/api/friends/{id}/space`、`GET/POST /api/wishes`、`DELETE /api/wishes/{id}` |
| 礼物预览、接收与决定 | 既有 `/api/gifts`、`/{id}/accept`，新增 `/{id}/decision` |

### 事项结构与结果语义

`TaskRecord.plan` 可使用 `schema: interaction/1`，`kind` 为 `checklist`、`guidance` 或 `idea`；`entries` 保存稳定 ID、动作/需求、可选实际物品 ID、分类、条件/依据说明、负责人和实际进度。模型最终结果和界面使用相同结构，不新建另一份计划。旧 plan 保留为 legacy，原话题可继续读取。

分类 `owned/buy/borrow/confirm/step` 分别表示已有、需补充、待借用、待核对与指导步骤；未知或未拥有的需求不填写实际物品 ID。条目 `pending/ready/not_found/unchanged` 保存报告。条目准备完可以成为 `ready`，只有针对**当前目标、资源、约束及方案**的成功反馈才能将事项标为 `completed`。旧方案的成功反馈不能完成新方案。

条目修改和分工使用 `expected_version`。冲突返回 409，不覆盖别人进度；相同已保存反馈可重复读取。分享前先取得相应物品权限，受邀方接受后才可更新，只有发起者能调整负责人，并且只能分给已接受的人。邀请不转发发起者私人聊天、约束和实际结果反馈。

### 授权与失败语义

家庭成员身份和好友关系不同。家庭邀请需接受，用品需逐件加入；家庭授权是共同查看，修改物品身份与状态仍由持有人操作。单人授权与家庭授权分别管理，撤回其中一条不表示其他有效授权也被撤回。共享不附带持有人私人 Profile、回忆、记忆或设备控制权。

新回忆默认 `allow_ai=false`；主动允许参考和向朋友分享是两个动作。关联家庭用品不自动分享回忆。分享回忆时隐藏对方无权读取的物品标签，照片按同一授权读取；撤回后未来访问失效。收到的礼物原故事保留作者与原文，可修正关联、选择用途或另记自己的经历。已交付的礼物故事快照不会因删除原文而远程收回。

提醒 `pending/read/in_progress/completed` 分别表达等待、已读、接手和报告完成；只有接收者提交处理反馈。完成提醒不自动把物品从暂停使用改为正常，也不声称实物已修好。

语音识别与朗读使用浏览器能力；缺失或失败时保留文字和照片入口。断线时事件流可重连。未配置百炼时发送返回可解释失败并保留草稿，建档、回忆、清单和共享仍可使用。

## 迁移与继续分工

新增 Alembic `0006`。启动前对需要升级的已有 SQLite 库创建一致性备份，迁移保留原物品 ID、个人资料、旧任务、经历及完成提醒；旧经历延续原有 AI 使用范围，新记录默认只保存。回退应停止服务并使用验证过的迁移前数据库和媒体备份，不通过删库或不完整 downgrade 恢复。

后续协作按职责沿上述契约开展：

| 开发方向 | 接入位置 | 验证重点 |
| --- | --- | --- |
| 物理解/使用指导/来源质量 | 现有 Agent 工具、knowledge、learning、共同事项 plan | 真实型号与资料、每步适用性、反馈后分支调整 |
| personalized/情境记忆 | 现有 Profile、Memory、ReMe 与 learning | 相关性、遗忘、临时条件、私人范围，不另建记忆 writer |
| 创造与组合、真实设备 | 既有 creative-use、共同任务、REA 明确操作 | 当前资源与约束、最低试验、真实效果与未知条件 |
| 前端与体验 | 各 feature 模块和共同样式 | 手机触控、可访问性、照片布局、实际空/错/加载状态 |
| 家庭/社交进一步深化 | 共同授权、Reminder、TaskRecord、Gift | 借还闭环、责任交接、外部通知和实物交付的真实确认 |

自动照片识别建档、完整借还、系统推送、购买/支付、设备实际控制效果、智能个性化质量、响应时间仍需各模块继续实现或验收。这些是设计目标，不能把本轮界面与接口通过当作所有 F1–F12 或实物效果已通过。既有智能底座 NOT_ACCEPTED 状态继续保留。
