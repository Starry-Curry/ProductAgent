# 物间：底座缺口修复与验收状态

日期：2026-11-04。本轮继续实际开发，没有新增依赖或对外部署。结论：多项底座机制已补并得到开发验证；整个智能底座仍未验收通过，不能称缺口已全部关闭。

## 已落地的机制

| 已确认缺口 | 本轮实现 | 证据与限度 |
|---|---|---|
| 型号因资料链接不同而分裂 | 稳定身份由品牌、型号、市场、版本、固件构成；描述和来源保留在实例原始规格中 | 不再因名称/链接改变而换型号ID；仍保守区分版本，不做未验证的品牌语义别名合并 |
| 物品认识仅靠可选工具，实际没有沉淀 | 主 Agent 原生最终结果包含有类型的 knowledge_updates：能力/边界/步骤/观察/案例、条件、未知点、依据与范围 | 真实耳机测试已产生1条可复用认识；语义正确性仍需检查，不以记录数认定理解准确 |
| 记忆写入与任务写入分散 | 最终结果中表达 add/replace/forget，保留情境、当前原话与期限；与认识和持续计划同事务提交 | 旧理解替换有并发检查；当前模型有时仍合并多个主题或漏掉临时条件，不宣称完整用户模型 |
| 引用抄写失败后直接导致整轮失败 | 最终 schema 的业务校验接入 AgentScope 原生校验反馈，错误返回同一个 Agent 修正 | 没有第二个审查 Agent；不自动重新执行已完成的工具操作 |
| 抄写说明书长段文字容易出错、反复调用 | 原文按行号输出，模型提供连续范围，程序保存真实原句；旧引用只允许排版空白差异 | 不做模糊词义匹配；5秒与7秒不能互相当证据。原文选对仍不保证解释正确 |
| 家庭共享/赠礼未接续商品知识 | 公开网络来源与个人解释分开；匹配型号且有依据的公开原文可在授权共享时读取，并在赠礼时复制到接收方 | 传递原始公开证据与摘录，不复制赠送者自由解释、私人条件或失败记录；历史来源默认legacy，不自动提升为公开 |
| REA 与物品理解接续不足 | 设备探索返回并保存绑定物品的型号、状态、版本、已知认识和历史观察摘要 | 不发送回忆墙或私人记忆；工具实际输入仍按目标协议 schema。未验证实机改变或完整用户逐步引导 |
| 缺少耗时定位 | 复用原生事件记录每次主模型和工具的耗时及 token；超时与用户取消区分 | 尚未解决所有慢任务，也没有完整嵌套费用账单 |
| 分身错认故事主体 | story_refs 由程序读取原记录并按作者呈现引用 | 引用部分归属正确；自由陪伴文字仍出现虚构和错认，未关闭该质量缺口 |

原有 remember/forget_memory/learn_item_knowledge 模型写工具已移除，领域操作仍供统一提交和 API 复用。没有并行维护第二套业务记忆。新增实现采用 AgentScope 原生结构化结果及校验反馈；借鉴成熟记忆更新语义，但没有声称已集成 Mem0 或 ReMe 自动提炼引擎。

数据库迁移到0005。原有完整商品规格逐实例保留；既有数据先备份再逐条比对旧字段。备份 `var/backups/pre-v03-20261104-233504.sqlite3`：8件物品、6条经历、2用户、4附件、13会话、38消息、21运行、9档案、3记忆、3来源、1礼物、1好友关系保留。新增来源性质与记忆情境信息独立添加。

## 实际测试，成功与失败分别保留

所有人物、持有关系和生活报告为明确虚构；标准商品为大陆适用型号。实际经过应用、数据库、AgentScope 与百炼。以下均为开发测试，未执行独立18题/创造12题验收。

1. **原文抄写路径失败**：`var/evaluations/20261104-231705/results.json`，52.44秒因引用不匹配失败。接入原生校验反馈后，`232127/results.json` 虽完成，耗时148.22秒、反复校验，模型最终撤掉知识更新，知识仍为0。这说明仅要求抄准引用不够。
2. **行号机制后有真实知识沉淀**：`232808/results.json`，62.27秒，实际取得WH-CH720N官方原文，保存1条步骤认识及前提/限制/原文。仍出现“开机状态下”这类未由所引片段充分支持的条件，不能认定操作指导已严格通过。
3. **理解人与修正**：`233309/results.json`，三个新会话分别约16.44、11.73、11.73秒，正确接续租房约束、读书暖光/手工白光及石头的纪念意义，没有创建回忆墙。曾一次返回空content，由原生校验修正后完成。模型将多个主题合成一条理解，今天暂不使用石头也未可靠形成有期限的独立条件，仍需深化。
4. **真实案例取得与沉淀成立，创意未通过**：`233320/results.json`，104.41秒，实际搜索、取得教程，沉淀了有原文的案例相关认识；但是建议剪裁库存中已注明不能剪的窗帘，并对灯与布距离作未经证实的保证。原案例可行不证明适配到自有物品后可行，该项明确失败。
5. **新长旅程发生回退**：`232820/results.json` 包含空理解内容、创意240秒超时、反馈改写未通过原话校验。后续已把内容与反馈校验前移到原生 schema，并修正超时状态；未重新完成最新整条旅程，不把专项结果拼成全量通过。
6. **故事引用与自由叙述分开评估**：`231843/results.json` 中原作者引用呈现正确，但陪伴文字仍虚构交付/人物心理并错认亲历者。未以引用正确掩盖正文错误。
7. **真实公开资料的接续**：基于`232808`实际获取的资料，在应用API中验证共享与赠礼，没有新增模型调用。第一次`public_continuity.json`发现未绑定具体实例的型号资料在共享端漏读（0条），赠礼复制1条且私人记忆0条；修正共同来源访问机制后，`public_continuity_retest.json` 共享端取得原公开依据1条。对应工程回归覆盖撤权后停止访问。原失败记录保留。

原始资料与完整引用保留在各隔离测试数据库和附件中。模型工具与检索返回的长引用截取前2000字并标明截断；通过source_id和原文行号按需重读，避免每次传输整篇案例。

## 工程检查

- 34项工程回归覆盖真实 SDK 最终工具、有依据的写入、原文行号、错型号拒绝、记忆纠正与任务事务回滚、共享撤权、公开资料赠礼、私人信息不转移、REA上下文和迁移。
- Ruff、OpenAPI生成、前端类型与生产构建已执行；前端仍有约996KB分块警告，未以调大警告阈值掩盖。
- 这些检查验证程序机制，不代表模型理解质量通过。

## 必须继续解决的缺口

1. 创意方案必须遵守物品已有边界，尤其从原案例迁移到自有资源时。当前自然语言描述和同一模型自查没有达到要求；下一步需要验证按资源表达能力/禁忌/未知，并把这些条件对应到具体步骤的方案契约。不能只继续增加“请遵守限制”的提示词，也不先造通用物理仿真器。
2. 个人理解需要按可独立更新的主题组织，可靠保留临时条件；已有写入/纠正机制不等于自动抽取已成熟。可继续对照成熟提炼实现，以实际改善决定替换职责。
3. 分身自由叙述的经历归属与事实可靠性仍未解决；接收的故事不能当作接收者亲历。外观养成后置。
4. 模型回答中的每项条件应得到适用依据，不能靠合法引用把额外推断提升成事实。
5. 多步旅程的延迟与工具选择仍需改进。已能分段观测，不靠延长超时或删掉失败案例达标。
6. 家庭公共物品、责任/接手/完成、维护周期和真实通知交付的完整切片尚未开发；REA仍需具体控制入口与实机观察。

上述问题继续列为未关闭；底座负责人维护统一契约与集成。研发按照实际失败逐项验证，未达标不授予“智能底座完成”结论。
