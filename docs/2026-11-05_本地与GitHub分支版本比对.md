## 4 本地与远端的架构差异

| 方面 | 当前本地 | main 与 develop |
|---|---|---|
| 应用结构 | Python FastAPI 后端，React/TypeScript/Vite 前端 | Next.js/React/TypeScript，页面与接口同项目 |
| 主运行代码 | `wujian/agent_runtime.py` | `src/lib/agent/service.ts`、`graph.ts`、`practical.ts`、`tool-runtime.ts` 等 |
| Agent框架 | AgentScope Python 2.0.11 | AgentScope TypeScript 0.0.15；保留 LangGraph 依赖与兼容代码 |
| 检索与记忆 | ReMe 混合检索；SQL为权威；主Agent结构化提炼理解 | 自有 Context、记忆、隐私失效与召回实现 |
| 数据库 | SQLAlchemy映射，`var/wujian.sqlite3`，独立 items/products/memories 等业务表 | Node24 `node:sqlite`；主业务 `demo.sqlite` 中工作区JSON与多组领域表，另有账号库 |
| 迁移 | Alembic，当前0005 | TypeScript迁移及生活/任务等分组版本 |
| API契约 | Pydantic/OpenAPI和生成的前端类型 | TypeScript/Zod及现有Route Handlers/公共服务 |
| Skill | 两份 Markdown方法，原生 LocalSkillLoader 按需加载 | TypeScript技能/注册与服务方法；不是本地的两份 Skill 文件 |
| REA | MCP接入，显式浏览器CDP或授权JavaScript包，未验收实机改变 | CLI调用固定版本；软件实验限定自有虚拟灯测试目标，不代表实体设备通控 |
| 功能组织 | 物品、回忆、探索、家人与心意及统一侧边对话 | 生活首页、展柜、发现、故事、助手、家庭、社交等组件和兼容路径 |
| 工程协作 | 本地34项回归及生成接口机制；尚未提交 | 有CI、团队启动工具和大量历史回归/验收资料；本轮没有重新运行 |

## 7 对后续协作的影响

同一个 origin只表示连接同一远端，不会让两套本地代码自动成为一个版本。当前本地仍没有提交，也没有与远端共同的本地提交基线。

如果队友从develop开发，而我们继续改当前目录，实际上是在维护两套应用。后续需要先明确哪套作为团队主线，再评估另一套有哪些经过验证的机制、交互或测试值得迁移。不能先把文件覆盖到main，也不能仅凭本地版本号0.3或远端历史测试更多，就认定某一套智能效果更好。

本轮没有比较两套系统的真实模型质量，也没有迁移用户数据或合并代码；关于哪套应承担后续主线，需要依据实际体验、维护成本和相同条件的验证作决定。
