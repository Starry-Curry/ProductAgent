# 决策：保留 LangGraph；不把框架研究变成产品阻塞

2026-10-29，接受为本轮决定。依据固定 main、RFC、v1 修复源码，以及 [本轮可运行实验](../../../experiments/framework-evidence/README.md)。没有部署新云平台或改变全局 Node。

## 实际比较得到什么

四组读取相同合成画/纸盒与显式赠送事实，复用同一领域读取、授权和幂等写入。LangGraph 组使用当前 1.5.1、真实 Wujian SQLite checkpointer/provider 的小型宿主；**不是把 PoC 等同 main 完整产品图**。main 完整产品服务另有固定源码、同入口实测。

| 方案                                               | 可复现的能力与便利                                                                           | 对物间的实际缺口和决定                                                                                                                          |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| LangGraph 1.5.1                                    | 工具结果回合、现有 SQLite 检查点、暂停、新进程恢复、写入后崩溃重放、撤权；可复用已有业务保障 | 默认保留。已有实现无需重新接消息/回执/权限；当前创意问题不是循环库缺功能                                                                        |
| Mastra Core 1.80.0 / Memory 1.39.1 / LibSQL 1.27.1 | Agent 工具循环；资源级 working memory 跨 thread 和重开保留；Workflow suspend/resume/restart  | 记忆模板和上下文装配便利可复现，但本例是宿主显式写入，不是自动准确提取。物间仍需来源、更正、遗忘、目的/处理方权限；现在接入会增加第二套认识存储 |
| Pi Core 1.4.0                                      | 简洁的动态工具循环与事件；真实千问工具往返通过                                               | 跨进程流程状态由本实验宿主 SQLite 补写，不能归功于 Core。现有 LangGraph 已提供关键循环，未发现足以迁移的用户收益                                |
| Pi Durable 1.4.0                                   | Node + SQLite 的原生持久任务/阶段/调度；按运行隔离后的崩溃恢复、完成回执和暂停撤权通过       | **Experimental，API 可无预告变化**。具备后续长任务研究价值；共享库多任务恢复未认证，未证明比当前 LangGraph 降低整体成本                         |

Mastra 进程被强制退出后，直接 `resume` 不适用正在运行状态；应使用 `restart` 并等待旧所有权租约自然到期。本例恢复约 16 秒，包括租约等待，不是框架 P95 性能结论。Pi 共享实验库出现超时，隔离每个故障运行后通过；只能证明该隔离配置有效，不能把前者宣称为框架缺陷，也不能由后者证明共享库并发安全。原始失败与修正均保留。

Mastra 本例初始化 40 张框架表（不是 40 张物间业务表）；SQLite/libSQL 可以本地使用，无需云服务。Pi Durable 也不要求迁 Cloudflare。实验依赖在独立子包，产品 package-lock 未变；没有为了比较重建 App。[Mastra working memory](https://mastra.ai/docs/memory/working-memory)、[Workflow 恢复](https://mastra.ai/docs/workflows/suspend-and-resume)、[Pi Durable 官方实现](https://github.com/earendil-works/pi/tree/main/packages/durable)。

## 真实模型的结论

四个框架均能通过现有北京百炼 qwen-plus 配置执行工具回合。使用本地预算网关，向百炼发非流式请求，再为 SDK 适配 SSE；**未验证原生上游 SSE**。初始纸盒 ID 表达含糊时四组一起误读而拒绝；明确 ID 后四组一起成功，说明工具契约比更换框架更直接。

42 次请求、估算 ¥0.0196844；HTTP 成功不代表业务合格。不同 SDK 的提示格式、工具 schema 与回答长度不完全相同；费用差异不是框架质量/速度排名。小样本也没有独立真人盲评。

## 是否组合接入

暂不组合生产框架。Mastra 工作流可在未来出现独立长后台流程时单独评估，Pi Durable 可在多工具探索任务必须跨进程恢复时对照；都必须复用物间领域工具、预算、权限和回执，不能接管权威用户记忆。只有实测减少维护工作或改善明确用户任务，才提出接入。

现在不需要 Cloudflare Harness、新云部署、向量库、整套 Mastra Server/Studio、每物品常驻 Agent、REA/设备工具安装。框架实测约一小时内收敛，后续时间用于产品代码与验证。下一步见 [实施清单](NEXT_IMPLEMENTATION.md)，不再开 RFC。
