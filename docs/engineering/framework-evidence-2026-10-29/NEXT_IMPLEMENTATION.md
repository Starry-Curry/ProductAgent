默认继续 LangGraph；从当时最新 main 建功能分支，有选择纳入本分支已复验的 v1 修复和共享资料切片。不能把它们视为 main 已合并。本轮已可运行，但纸盒创意尚未过产品门槛。

## 第一项：关系认识的最小纵切

入口：物品详情/问物间输入“记住：朋友小夏送给我这幅画”，新会话询问来历；记忆设置中纠正、忘记和模型处理授权。

- 首改 `src/lib/context/knowledge.ts`、`builder.ts`：在当前只读资料契约旁增加**有来源的关系投影**，继续从现有 personal_memories/故事读取，保留 owner、itemId、来源、版本与 allowCloud。
- 改 `src/lib/agent/service.ts`、`memory/store.ts`：明确保存事实与模型提出候选分开；用户纠正指向原记录，不复制出两个赠送事件；沿用事务、回执和 epoch。
- 改 `skills/memory-storytelling.ts`：只用获准关系事实和原文；人物名称绑定已有记录或待确认候选，不能因“朋友”推测亲密度、日期、情绪或自动创建账号。
- 初期不建全部 V2 表、不把自然语言推断直接写成 confirmed，不把 regex 分类扩成认知系统；结构化模型提取仅提候选，ID/证据/写入由服务校验。

通过标准：三个全新会话可追溯“小夏赠送”；更正后引用新版本；私密事实不上云；另一演示主体/访客不可读；遗忘后新会话及恢复旧缓存不召回。先离线驱动真实领域服务，再真实千问，最后浏览器完整旅程。当前已证明显式文本记忆的保存/召回/遗忘，未完成上述结构化关系能力。

## 第二项：把纸盒创意的真正失败点修掉

入口：详情“从它开始找玩法”、发现页和问物间，共用已知属性与授权偏好。

- 首改 `src/lib/life/idea-audit.ts`、`planning-constraints.ts`：区分肯定动作、禁止动作、假设与想象。把“不要粘贴”识别成依赖胶水的误拒加入固定回归；不能靠删除安全检查换通过。
- 改 `life/ideas.ts`、`planning.ts`：引入最小结构化动作/条件字段，标明实际用物、原理、缺条件和观察步骤。先约束一个纸盒场景，不一次实现整套本体/搜索平台。
- 复用共享资料快照及现有偏好许可；当前材料、数量、状态未知必须显式保留。一次修补仍不合格时，告诉用户卡在哪个具体条件，并提供一个有用追问或不依赖该条件的方向，避免无关观察卡充当成功。
- 不把展示文案或 source=answered 当质量通过。事实/动作检查、独立机理审阅、用户觉得有趣分别记分。

通过标准：冻结包含旧失败文本的开发回归；至少三条不同结构/限制/偏好的纸盒情境，零未登记必需资源、零未经确认的承重/耐热保证；能产生有原理、有条件的具体候选。再用不重叠留出案例、同模型同信息的直接调用对照和独立真人盲评，不拿本轮已调试场景宣布创造力提升。

## 真实模型和浏览器关卡

下一轮预算建议：先 12 个离线情境，再最多 40 请求/¥5 的真实文字小试（包括重试），达到任一上限停止；这是**下一轮提议**，不把本轮剩余 18 次转移或重置。使用相同物品、偏好、限制与模型版本，保留原始输出、工具 trace、错误、tokens/耗时/费用。

真实模型分别测试：赠送事实提取候选/跨会话引用、更正与未知；纸盒目标/偏好/否定动作/缺资源/修补失败。浏览器至少覆盖录入 → 明确记住 → 新会话 → 纠正/遗忘，以及从物品与目标两入口得到同一事实基础。付费浏览器若需要本地供应商代理，遵守现有 HTTPS/权限策略，不为测试关闭安全检查；可先以离线浏览器 + 真实隔离服务分层记录。

每次实际实现运行 `npm test`、`npm run typecheck`、`npm run test:benchmark`、`npm run build`、相关 cloud/浏览器验收。框架与设备实验不在关键路径。需要负责人参与的只有记忆默认政策，以及创意盲评的任务/人选；本阶段默认明确保存、最小共享，不自动扩大权限。
