# 逐案审阅与失败保留

完整逐案记录在 [v3-case-reviews.json](evidence/v3-case-reviews.json)，原始问题、期待依据、回答、源码版本和调用编号可回查对应 experiment JSON 与 `model-calls.json`。这是工程人员按官方原文和冻结期待所作的复核，**不是第二个模型的自评分，也不是外部真人盲测**。没有穷尽所有句子的真值；“发现无据扩写/待核实”不能直接等同“现实事实错误率”。

历史沿用上一轮71个关键项口径。正确覆盖只计最终展示的内容，被挡住的正确草稿不算答对；开关前的本地安全回复也不能称真实模型。完全完成还要求没有已观察到的错误/无据扩写和可用操作闭环。因而“核心4/4”可能仍只是部分任务完成。留出63个关键项按用户问题与冻结rubric分解，来源不足没有被计为事实完成；有理有据的未知判断单列在注释。两集合口径不应直接相加当一个商品事实准确率。

## 真实成功与失败例子

1. **WH-CH520 短按/长按**：V3发布“短按减小音量；长按到提示音，跳到上一首或当前曲目开头”，两问都在，33.8秒、2次上游。旧有限索引场景0/2。App真实桌面也再次跑通；它又额外生成用户没问的“本质不同”子问并留未知，说明任务拆分仍膨胀。
2. **CP1500装纸**：冻结留出同时回答光面向上、最多18张、内盖关外盖开，真实成功。开发复测却又附加“纸盒插入约2cm”的未经充分依据步骤；相同核心题成功不保证任意续写都可靠。
3. **AC-M16-SC规格+水洗**：开发实测给250×250×555mm、约5.6kg、28–48m²，将滤芯水洗单独留未知。这比一项未知吞掉整题更有用，但不证明可指导维护。
4. **310g手机与OM6**：模型有宽厚范围并完成75mm/8mm必要比较，却把最重要的310g超限结论拒掉。二维/区间工具存在不等于任务成功。直接臂给出超限，但又补造夹具占重和其他型号规格。
5. **JBL Clip 5连接模式**：历史V3与直接臂都从QSG未提及，推到“不支持立体声/Auracast”，不合格。新增缺席→否定必要门禁有离线回归，但留出录音笔/键盘/打印机仍有语义外推漏网，不能宣传此类问题已普遍解决。
6. **有经验的耳机再次连接**：A经验在无关B之后仍传入C；有经验V3超时。纠正后虽然读到新报告，却虚构“用户此前未触发配对”的因果，并推荐初始化，不能算有效经验复用。忘记后Experience IDs为空，证明失效机制而非回答质量。直接臂能优先删除旧记录，也补造冲突原因。
7. **摄影再创造**：有经验V3超时，无经验V3大部分挡住；直接千问提出“光腔静帧”，却假设盒盖悬空留1–3cm、透光均匀无眩光、准确光楔等，还添加未登记静物。点子可供讨论，不能当已可执行或物理验证通过。
8. **推车承载净化器**：留出V3超时；直接臂用35×45总外框和77总高，保证25×25×55.5cm净化器任意层可稳放，遗漏净层高、支撑和重心。这是明显错误的实现条件推理，不是靠加一句“注意安全”可以通过。
