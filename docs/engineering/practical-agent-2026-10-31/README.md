## 切片1：Sony已在真实浏览器走完整条链

`sony-browser-v6.json`：浏览器真实表单录入模拟持有WH-CH520 → 真实qwen3.8-max-0902 Function Calling → 实际访问Sony配对/初始化帮助指南 → 流式自然回答及来源 → 同一会话追问10秒初始化/配对记录删除。首次2次上游、完整答案11.9秒；追问1次、4.5秒。实际截图sony-desktop/mobile.png。模型不是固定答案；持有与人物为合成，没有操作耳机。

**不把流程通过当逐句认证**：重新配对核心步骤5秒/手机选择/0000具备来源，初始化追问的10秒、关机拔USB及删除记录也有官方依据。模型仍讲了未问的初始化，“短按开机”的补充措辞含糊，不应据此理解为轻按即开机。

**原文复核纠错（接续d59b10e）**：我最初将“5分钟未建立配对后自动关机”列为模型错误，这个判断不正确。实际抓取的该型号英文指南直接写了“pairing mode is canceled, and the headset turns off”。原始模型/工具输入完整保留，不改写为更好看的样本；不得用对错误标准答案的迎合当提升。下一阶段继续Canon与经验旅程，而非围绕错误初判追加规则。

修复已实证的路由断点：普通请求“以前连过其他手机”曾被旧router直接判故事，0模型返回故事说明。原生只读对话现在不先交给该路由。显式记忆保存、各专业模式和业务按钮仍走既有确认/事务，原生工具不具备写入/设备权限。

采用现有Provider新增的OpenAI Node SDK流式接口，工具有Zod Schema、服务端权限和有限循环；没有V3 TaskFrame/强制候选JSON/第二模型审稿。官方URL元数据复用旧审阅来源，但**不读取其人工答案表作为回答**。初始工具确认后再回到模型；追问已有资料可单次完成。关闭长期记忆仍保留同一关闭记忆会话的必要追问，不带入此前长期记忆。

早期浏览器失败分开保留：v1重复测试元素；v2旧故事误路由；v3—v5 Chrome CDP无法读取已消费SSE（页面已显示真实回答），v6改在页面原生fetch的response clone旁路记录，不伪造网络响应。五项离线机制测试与生产构建通过，尚未全回归。来源取得、模型理解与浏览器测试问题分别记录。
