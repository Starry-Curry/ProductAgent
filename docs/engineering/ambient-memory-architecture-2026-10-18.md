# 静默记忆、物品故事与技术基座（2026-10-18）

## 本轮设计与落地范围

延续唯一 Next.js 工程与原五入口，以“具体物品的故事与记录”为主要窗口，聊天和业务事件作补充。用户无需填写画像。技术设计采用事件驱动的本地整理，而不是为了采集数据不断追问；不增加付费提取调用或外部记忆服务。当前规则提取能力有限，完整语义提取仍待实现。

原 ZIP 的导出记录为 f058488；仓库 main 基线为 53a4343；本轮从已完成 LangGraph 和真实百炼验证的 9c14eb1 继续，在 feat/ambient-memory-experience 分支实现。原资料留在 Wukaifeng，交接文件已导入 docs/collaboration 并重新核对。未重建、混入旧 LocalFlow 或覆盖运行数据。

UI 与业务模块保持；补充 /guide、首页示例与入口地图，固定偏好移到主要帮助入口之后。物品详情增加 story 会话模式，原时间线、直接写记忆、礼物选故事都保留。story 模式目前本地确认叙述/回忆，不能宣传为千问自由对话。可选陪伴依然需主动开启。

### 数据底座

主业务仍是 workspace 单行 JSON，事务调用 mutate；没有声称已完成 User/Household/Item 全关系迁移。v3 已有会话、请求、反馈、私人记忆、版本 epoch、persona、LangGraph checkpoint/writes。

v4 是增量迁移，升级前 VACUUM INTO 备份，保留 WAL 提交数据，幂等建表；未来版本拒绝写入。新增：

| 表 | 用途 | 内容边界 |
| --- | --- | --- |
| memory_capture_settings | 按人保存开启/暂停、恢复时间与首次观察时间 | 不修改其他人的设置；默认本机整理开启 |
| memory_source_receipts | 来源编号与摘要 hash，防止重复处理 | 不复制完整聊天；相同来源不反复生成 |
| memory_capture_slots | 归一主题与派生记忆的关系、人工覆盖/遗忘锁 | 主题键 hash，不存原文；防止原故事再扫描复活 |

故事窗口的原始叙述写入 workspace.memories，保留 author、itemId、sourceSessionId；派生记录在 personal_memories，保留 provenance(kind/sourceId/sessionId/basis/at/extractor)、版本、适用物品、期限、云端授权。礼物继续使用原始故事快照，不自动赠送派生画像、完整会话或后续私人记忆。

## 静默提取闭环

1. **发生业务动作**：用户讲述、正常问答、登记/更新物品、写原故事、保存计划、创建家庭事项、记录尝试或反馈结果。
2. **先做访问与来源约束**：只处理本人事件和当前可访问的物品；跳过默认示例物品/示例故事、他人故事与转赠导入故事。第三方故事仍可按原业务权限查看，不变成本人的亲历。
3. **本地抽取最小片段**：受限中文规则识别“我喜欢/不喜欢”“我买了”“以后请简短”等；故事入口保留完整本人叙述并提取其中清楚表达的线索。跳过若干假设、示例、引用、疑问和敏感凭证模式；这不是通用隐私识别器，普通会话原文仍有其保存规则。
4. **分层落库**：聊天自述、系统登记、行为观察、本人结果反馈分别标记；持有不等于喜欢，采购事项也不等于已完成购买。新记录默认 allowCloud=false。
5. **归一、去重和更新**：同一来源回执幂等，相同兴趣不重复插入；旧来源时间不得覆盖较新的同主题陈述，避免历史回填把用户变化改回去；新的“不再喜欢手工”更新对应主题。手工纠正与忘记设锁，不会被后来的被动扫描覆盖；明确“记住：”或手工补充仍是可选动作。
6. **按需召回**：本人 + 当前权限/所有者快照 + active/未过期 + 物品范围；当前任务要求只在来源 session 使用。相关度采用词片段与类别加权，最多 5 条，没有向量库或全局画像模型。当前意愿优先；负向兴趣不用于提升同类候选。
7. **结果回流**：“解决了”且本轮确有步骤，自动留存最后一轮方法，标记用户报告；后续“未解决”撤回该会话派生方法。失败/尝试记录归个人经历，不升级为官方知识。
8. **控制与失效**：可查看来源、纠正、忘记、暂停；恢复不回采暂停期间旧聊天/操作。忘记和人工纠正沿用 epoch、旧会话与缓存/checkpoint 清除策略；原始故事作品与备份需单独管理。

实现是**事务内同步、无界面打扰的事件处理**，不是独立守护进程或已部署的异步队列。正常写入时处理；查看记忆时，对本人非演示业务记录和最近 25 个未过期会话的有限消息再核对。尚无全量历史批处理。暂停会阻止自动派生，主动留下的原始故事与普通对话仍可保存。

### 记忆如何影响实际体验

| 类型 | 使用方式 | 禁止跨越的推断 |
| --- | --- | --- |
| 物品故事/关系 | 当前物品故事回忆、主动开启的对应陪伴 | 不变成共同经历或其他人的记忆 |
| 明确兴趣 | 当前可用物品的精选候选排序 | 不从购买或一次点击推断喜欢 |
| 指导方式 | 后续相关帮助选择简短或详细呈现；固定偏好可覆盖 | 不改变商品事实与安全条件 |
| 当前要求 | 带来源 session 与 7 天期限；本次方向优先 | 不把“今天不想做”变成永久偏好 |
| 登记持有 | 关系事实查看；物品资源仍以领域实时状态为准 | 不证明实物/订单真实性 |
| 购买自述 | 作为本人陈述保留与查看 | 无订单连接器，不自动创建所有权 |
| 尝试/反馈/方法 | 个人经历、回忆与后续复用线索 | 不宣布设备正常，不变成全球规则 |

尚未实现对所有方法、预算、行为模式的自动规划利用。比如持有、购买和尝试会被整理并可查，当前并未全部用于推荐；不把“存进表”当作完整智能。

## Harness、Skill 与 Prompt

沿用已接入的 LangGraph.js 1.5.1、@langchain/core 1.2.18、SQLite Checkpointer。prepare → 规则/来源选择 → 模型 → 工具 → validate → 等待补充/反馈，工具只读、参数有 Schema，单轮最多 3 次模型调用、6 次工具、45 秒预算。lease/revision/requestId 避免并发覆盖与重复执行。写入仍走领域授权，模型不能自行分享或写任务。

Skill 新增 item-story，更新 memory-capture 说明；原 item-help、companion、evidence-discovery、family-handoff 继续使用。Prompt 为现有 human-item-agent-v1.2；本轮的主要变化在事件提取和本地 story 路由，不假称新 Prompt 已提升真实模型准确率。百炼原生 tool calling 与 JSON mode 的兼容修复保留：有 tools 时不混用 response_format，最终对象仍服务端校验。

这套基座相对“仅说明书检索/只检查引用 ID”增加的可核实能力是：具体 Item 关系与授权、当前条件与多轮状态、已尝试步骤不重复、事实/过程的限定呈现、家庭摘要交接、原作者故事与私人记忆、结果反馈与遗忘失效。已有离线反例比较能显示部分误放/误拒差异；**没有竞品对比实验，也不能声称全面优于所有产品**。

开源取舍：继续直接复用已运行的 LangGraph，不再叠加一个外部记忆服务。设计参考 [LangGraph 官方 Memory overview](https://docs.langchain.com/oss/javascript/concepts/memory) 对线程记忆、长期记忆与应用逻辑/后台更新的区分；本工程选择事务内本地提取是针对隐私、费用和现有 SQLite 一致性的工程取舍。该官方文档并不证明本工程的提取质量。

## 测试、回滚与后续顺序

新增 tests/ambient.test.ts 覆盖提取反例、否定更新、原始故事与派生记忆、按人隔离、暂停恢复、临时提问、遗忘/人工覆盖、防复活、方法反馈撤回、事务回滚、v3→v4 备份与未来版本保护。浏览器从原“填表存兴趣”改为物品故事真实录入、时间线→静默兴趣→发现→当前方向→物品陪伴→忘记；仍检查桌面/390px/长辈版和旧业务。API 与浏览器使用隔离数据库、费用关闭。

回滚：停止本机服务，备份当前 data 与迁移备份；需要旧代码时同时使用其兼容的升级前副本，不能把 v4 库直接交给旧程序。不要覆盖或删除现有备份。临时停用自动整理可在 UI 按人暂停，不需要回滚代码。

下一阶段优先级：

1. 为有限本地提取补充更丰富、可回放的中文故事数据集，加入间接偏好、变化、否定、时间与第三方归属评测；再设计可选语义提取器。历史私人原文上云或新增费用前另行授权。
2. 将 Item/PersonItemRelation/Story/Grant 从 JSON 逐步关系化，先兼容读写与迁移对比，再完善家庭账号、真实权限和附件管理。
3. 在已选真实物品上扩充可执行 Product Pack 与验证步骤，并串联能力/条件/资源规划；把当前有限候选扩展为可核实方案。
4. 再接入视觉/OCR、订单、IoT；分别核对模型能力、授权、来源和费用。自动改 Skill/Prompt 应先离线评测和人工审核，不把一次成功反馈直接发布。
