# 统一家庭连续开发：流程改善，智能质量未达标

本轮沿 `codex/wujian-unified-home-beta` / `0c6851a61e81834a65920db13ca5a0e968595318` 继续，没有创建重复项目、替换框架或合并 main。工作区为 `D:/ProductAgent-LifeContext/.runtime/unified-home-app`。日期：2026-10-30（北京时间）。LangGraph + SQLite + Next.js 保持不变。

## 用户能感受到的变化

- 首页自由提问提前到八件物品清单之前，不再把上一段对话自动填成新问题。
- 物品详情的“让它多一种可能”围绕当前这一件开始；可选择也考虑其他家庭物品，仍不要求全部使用。隐藏与该物品无关的测试商品导入入口。
- 创意的用途、原理、条件、步骤、收藏、否定与反馈留在物品体验内。单件探索也能读取已获准的家庭偏好，不能顺便读取原空间的全局私人偏好。
- 每张已有创意都有“带这个想法继续”。从详情返回已有生活任务时，实际带回方案 ID 和经过单独同意的反馈，保持原会话。
- 修复前端在旧会话中删除 `planContext` 的问题；修复仅改变 URL hash 时页面没有跟随的导航问题。桌面及 390px 手机实测。
- 普通任务按各子问题交错检索；无关物品不附带整段说明书。模型使用本轮临时短引用，服务端严格还原真实 ID；拼错的相似 ID 不模糊匹配。

## 先看结论，而不是测试数量

**流程连通不等于聪明。当前生成内容仍未通过实用性和物理机制验收。**

真实浏览器已跑通：提出目标 → 修改目标 → 物品详情 → 生成候选 → 收藏 → 记录反馈 → 明确同意带反馈 → 回到原会话。它能正确收到“这个方案不采用”的反馈。但它随后仍给出了错误替代方案，不能称为可靠的连续任务完成。

典型问题：

1. 把 73cm 桌面上 51cm 宽的两个盒子说成只占右半边；假设 A5 本子、空余桌面或插座状态。
2. 把 HomeKit 设置码流程混入米家 App 配网；编造护眼档、旋转方向或已通电状态。
3. SAMLA“轻抬回弹让纸片越过盒口”的机制没有依据。模型输出带有效引用、结构校验通过，仍不代表物理成立。
4. 在明确否定该创意后，模型承认不采用，却又建议用外尺寸 23×16cm 的 KNAGGLIG 搬走 28×20cm 的 SAMLA，未证明可容纳，还把未知弹性说成“无弹性”。

该创意已通过真实页面标为“不感兴趣”，备注说明研发复核不采用、未实物试验。**不是一个推荐尝试的成功创意。**

## 如何体验

独立工作区运行：

```powershell
npm ci
npm run build
node scripts/unified-home/preview.mjs --port=3204
```

打开 http://127.0.0.1:3204/#home 。本机交付预览保留合成数据库及真实模型历史，结束测试后以关闭付费调用的模式运行；浏览、收藏、反馈、故事等本地功能可用。干净克隆没有测试 SQLite，需先明确加载模拟家庭；数据库不提交。

云端复现命令（仅既有安全配置，不复制密钥）：

```powershell
node scripts/unified-home/preview.mjs --cloud --config=D:/ProductAgent-LifeContext/.env.local --port=3204
```

**本轮已用98次请求，共用100次的保守上限；剩余不足一轮正常的三次调用，因此已停止新增付费测试。不要删除或重置 `.runtime` 外侧的既有调用台账来续测。** 后续应明确新一轮实验范围与额度，再建立接续账目。

所有持有、位置、偏好、赠画经历及反馈来自隔离模拟空间，不是真实私人历史。无真实设备控制、无人执行固件或逆向操作。官方原文缓存与用户报告独立；可能性及方案均未实物验证。
