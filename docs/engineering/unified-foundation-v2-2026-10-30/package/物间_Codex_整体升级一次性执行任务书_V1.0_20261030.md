## 1. 成功定义——必须是用户真的能完成的任务

完成以下可演示的端到端连续体验：

**A. 陌生真型号 → 物品帮助 → 家庭交接。** 用户在个人空间录入 Sony WH-CH520 这类未预置商品，确认实物身份/地区，取得可追溯厂家知识，正确回答配对、按键问题，准确表达资料未覆盖的 ANC/保修信息；创建家庭求助，另一独立账号在授权范围内接手、回报，反馈可以在该物品后续服务中被引用（不得误作设备硬件事实）。

**B. 现实目标 → 多物品组合与新用途 → 约束核查 → 可实施计划。** 用户选 Sony/JBL/Canon/DJI/IKEA/小米等**真实型号但模拟持有**的物品，提出出游、摄影、整理、个性化等目标，AI 有能力发现有用组合和新的价值，保留真正的开放创造力；必须明确识别 DJI 手机云台与相机不匹配、食品接触风险、当前未知物品状态。不要把所有创意退化成固定模板。建议须能继续为下一步任务，用户反馈可修正。

**C. 物品/生活故事 → 个人化分身 → 选择性赠礼 → 关系延续。** 用户记录物品故事、个人偏好与经历，编辑或遗忘；分身应在授权范围内以此个性化回应，但不能幻想用户历史或把语气当智慧；送礼时选择传递的故事，接收者得到自己独立的物品实例、获准文字与新的私人 Context，原主人不能回看其新私人故事。

**D. 软件逆向与授权执行。** 继承本分支真实 REA CLI 对自有 JS 软件灯的分析→只读确认→明确授权→写入→读回→撤权→中断恢复/重复请求的测试；不把软件模拟当作真实小米台灯/其他硬件控制。

这些旅程必须复用同一 `Task/TaskRun/Context` 核心，而不是给每个演示另外写一个特判脚本。*简单问答可以不持久保存 TaskSpec，但必须遵循统一安全与证据契约。*

## 2. 已确定的产品与架构边界

- 产品北极星：**释放人与物的价值**；认知链 **理解物→物与物→物与人→人与人**；四种价值 **兑现、创造、延续、传递**。这些是固定设计依据，不能改回三类、五类或由模型重新发明。
- Agent：一个用户感知的物间 Agent；背后为统一协调/任务层 + 专业执行器，不强制所有请求走完整 LangGraph 长图，更不能让一个大 Prompt 同时承担所有业务。
- 基座实体：`ProductModel`（通用型号）≠`ItemInstance`（私人实物）；`Person/Relation` ≠ `Grant`；`TaskSpec` ≠ `TaskRun`；`SourceDocument` ≠ `EvidenceClaim`；`CapabilityCandidate` ≠ `ExecutedCapability`；`ToolReceipt` ≠ `Outcome`。
- 所有读取与执行遵循当前账号授权，任务引用不复制私密信息；写入、授权变更、赠礼和设备动作采用确定性事务与显式确认。
- 先保留 Next.js / SQLite / 必要的 LangGraph，使用新服务接口和旧数据适配；**除非明确测试证明替换框架的增益，禁止为了追新技术重写整个 runtime**。
- 导航 3/4/原方案均为候选。可先保留可访问所有功能的可逆布局、让 Agent 全局可用，真实用户测试之前**不能把四入口当已确认**；不要因为待定导航而阻塞后端统一。
- 真实商品是可核对的厂家型号，不意味着团队真的持有。测试人物、故事、家庭全部用合成数据并在 UI/日志显式标记。

## 3. 先完成架构冻结，再连续实施（同一任务可做大范围升级）

**G0 设计冻结（可快速完成，不要在此无限写文档）**

核对当前代码，形成精简 `ARCHITECTURE_ADR.md` / 结构及字段对照 / 保存旧数据与回滚方案。具体写明迁移顺序、旧 `domain.ts` 与 `accounts.ts/collaboration.ts/agent/graph.ts` 如何复用、当前 `WUJIAN_EXPERIMENTAL_FACT_QA` 为什么不能直接打开。若发现上位文件与源码冲突，给出明确选择及其理由，优先使用兼容性方案，不应改写产品理念。

**G1 领域、安全与真实身份**

增量实现 `ProductModel/ItemInstance/Relation/Grant` 边界及 `authorize`；共享后查看最小必要内容，成员撤权可立即影响未来请求和运行中任务。旧演示角色保留为显式 fixture，真实账户不再使用演示权限捷径。保护原 `workspace.body`、私人故事、现有用户库，迁移采用可回滚和版本化，不能破坏性改表；并发创建/修改不丢数据。

**G2 商品资料与事实回答**

建立 EvidenceService 的四态 Claim：正面支持、明确不支持、资料不足、来源冲突，包含精确适用版本和引用片段。**不能把某页未提到 ANC 当作厂家明确证伪**，不能补造维修价格/保修政策；必须保证关键否定、数字、安全、操作事实有可核对的证据。快速事实问答路径只有通过质量门禁后才能取代当前实验开关；高风险操作步骤沿用或强化现有原文校验。记录首个有意义、已核验的响应时间与正确完成时间，不能用流式首字代替。

**G3 统一任务与 Context**

实现统一的 `TaskSpec/TaskRun/ContextResolver/OutcomeStore`，并将原长图、家庭事项、目标计划、创造力和分身接入同一任务引用与授权规则。支持跨页面刷新接续、撤权失效、幂等写入、失败/未知状态与安全恢复。**不要求所有简单问答创建持久任务或把全量个人经历发到模型**。用户关于故事的记录是结果，不能混淆为客观外部事实。

**G4 专业能力统一接入**

打通基础问答、单物品指导、开放创造、多物品组合、数字分身、故事、家庭长辈协作、赠礼、维护和 REA 软件实验。重用原有真实功能，不做功能列表缩减；每一项真实关联物品实例与用户 Context。专业执行器输出结构化结果与来源，统一任务继续、反馈和权限。

**G5 交互与验收**

在桌面与390px移动端持续可用的基础上完成整体验证。可改信息架构与组件，但导航数量是可逆候选，要根据原型任务查找与真实体验选择；没有真实受试者则明确未定案。保留物品详情、任务继续、故事、家庭、赠礼等自然入口。逐案执行 85 测试，**按测试模式分层**：34 `live_model`、23 `browser`、16 `integration`、9 `prototype`、3 `software_lab`。记录未执行、被预算阻断和确实失败，不把编译通过/HTTP200/模型返回的 `answered` 冒充目标达成。复跑原有371项离线基线和新增回归（原基线应先核验）。

## 4. 阻断条件与可安全降级

不允许未经授权：合并 main、公开部署、真实外部发送、真实设备风险控制、删除/覆盖私人数据库、修改项目级 Instructions。可以进行常规非破坏性文件改动、隔离迁移和自动化修复。

## 5. 进度、变更和完成标准

- 在独立 `codex/wujian-unified-foundation-v2` 或其他新分支、独立 worktree 开发；保留原工作树/数据库。每一 Gate 完成后提交可恢复 commit + 原始测试报告；工作不中途由于“完成第一版代码”而结束。
- 每次执行阶段开始前阅读上一阶段的真实产出。修复本次变更造成的回归。除重大授权/无法解决的阻断外，不因为某一测试失败而反复问用户是否继续：先诊断和修复。
- 不在 UI/交付报告宣称真实家庭公网部署、任意硬件控制或真人体验已通过，除非真的有证据。
- 最终提交 `DELIVERY_REPORT.md`、`TEST_EVIDENCE.md`、`REMAINING_GAPS.md`：逐项列出真实用户价值、测试样本数与状态、模型正确性/性能、权限/迁移结果、已知缺陷和可恢复的 commit 与运行命令。
- 正式完成定义：所有 P0/P1 无未处理回归；合同/权限/数据迁移/关键用户旅程有可复现证据；全部85案例状态有记录（未运行不得隐匿）；端到端性能与人工评价只报告实测口径。未达到关键质量门禁时保留可用旧路径、发布为实验分支并明确阻断，**不伪报交付完成**。
