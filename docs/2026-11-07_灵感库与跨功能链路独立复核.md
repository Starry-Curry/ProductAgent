# 灵感库与跨功能链路独立复核

本记录是对本轮编者灵感库、实际演示数据库和真实浏览器入口的独立复核，不是实物玩法或主模型智能验收。复核未调用付费模型、未控制设备、未提交回忆、提醒或礼物；浏览器打开编辑器时拦截所有非读取请求，最终没有发生被拦截的写入请求。

## 灵感库

人工通读原 104 条，资源与机制覆盖电视、摄影、音乐、游戏、办公、厨房、灯光、清洁、阅读、收纳、露营、园艺等 12 类，范围没有缩成废物利用。来源读取等级、作者与编者解释、当前实物未验证的边界均已写入每条正文。

独立审查发现两条应撤回的弱项，并与库维护者协调修复：

- `fridge-visible-leftovers` 与 `fridge-use-first` 都依赖可见区域集中与日期优先处理，机制区别不足。
- `vacuum-find-small-part` 的第一步实际依赖灯光，吸尘器仅为可选附件，普通吸尘器评测与该玩法的关联过弱。

维护者保留旧正文及退役原因，将两条已有 SQL 来源标为 `curated_reference_retired`，排除后续检索；没有删除证据，也没有临时编造替换条目凑数。独立复核实际 SQL 得到 **102 条有效、2 条退役**；有效条目为 41 条官方文档机制迁移、61 条视频元数据方向上的编者设计。

独立再次 dry-run 校验 86 个原始来源的所有者、ID、URL、标题、正文摘要，结果为 0 new、102 reused、2 already retired。两条退役正文摘要与清单一致，均不在 `authorized_documents` 中；旧来源读回明确标为退役且不应用于新推荐。原始 `public_web` 和旧编者正文保持原样。

同时核对最终回答引用呈现：编者玩法标题不再直接链接到原视频，回答分别展示“整理的灵感（待试）”与真实原页标题/链接，并声明原页不是该玩法教程；读取原始标题前再次校验权限。退役条目旧引用标为“已撤回，仅供历史回查”。对应测试覆盖普通编者引用、跨所有者来源与退役历史引用。

相关导入、来源、权限测试首轮 24 项通过；新增退役与旧引用标注后，`tests.test_creative_catalog` 和 `tests.test_answer_sources` 独立复测 19 项通过，包括已有 ReMe 实例中清除退役投影的生命周期验证。这些测试验证软件契约，不能证明玩法已实机适配。

私有复核回执：`tmp/final-round/catalog-independent-retirement-check.json`。服务进程加载退役过滤代码仍以最终重启后的实际状态为准。

## 实际演示数据与共用对象

通过运行中的 HTTP 接口只读核对：小林有 43 个活跃物品，全部带图；12 条回忆全部带图；8 个任务引用的物品均可达，全部任务看板读取成功。新实拍唱片机、按摩椅、茶吧机仍在描述、版本与 `identity_basis` 中标注参考型号/铭牌待核对，未把照片当作型号确认。

妈妈、姥爷各可读 38 个家庭物品，全部带图；姥爷偏好为大字版。6 条家庭提醒中 5 条引用相同业务实物 ID，阳台浇水提醒没有强行建立花盆档案。两人的回忆列表均为空，共享实物没有顺带公开小林的私人故事。小林两条赠后旧回忆仍保留原物品标签，物品不再由发送者持有属于正常历史语义。

以同一台真实实拍的 illy 咖啡机做 Chrome 入口贯通核验：

1. 打开实物名片，显示对应实拍。
2. 从名片进入“发现新玩法”，草稿保留该咖啡机名称与当前资源语境。
3. 从同一名片进入分身对话。
4. 打开“记一段”，可见当前物品关联、独立可见范围与 AI 参考开关。
5. 打开送礼编辑器，候选故事正是该咖啡机的“厨房里的红色角落”，分身沿用该物品形象。
6. “照顾与历史”显示该咖啡机的清理胶囊提醒。
7. 按该物品筛选回忆墙并打开对应故事。

这 7 项真实浏览器读取检查通过，未见浏览器脚本错误或损坏图片。截图与回执在 `tmp/final-round/independent-journey-ui/`；只读 API 关系摘要在 `tmp/final-round/journey-independent-api-read.json`。入口互通和共用 ID 已核对；没有发送对话或执行写入，故不据此声称主 Agent 能完成这些动作或实物效果成立。
