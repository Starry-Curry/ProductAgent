# 自然教学与自动视觉辅助

本轮在 `feat/a-natural-guidance` 迭代，基于已有 A review；没有更新 develop/main，也没有创建 PR。使用现有百炼账号，没有新增付费服务。

## 交互与状态

普通文字回答是主入口；有当前教学任务时，回答后提供「3D 图解」「相机辅助」。图解按需打开弹窗，不常驻大卡片。教学侧栏移除「实际尝试后」表格，没有来源时隐藏空资料区。

直接说「我有一个装不上」「做了但没有变化」「这一步已经完成」。主 Agent 用同一 task_id 和版本更新当前步骤，保存本轮原话；新增步骤仍 pending。计划支持只回传变化的条目，历史步骤由 SQL 合并。仅作简短解释而没有计划变化时，用户原话也保留到原任务，结果记 unknown，不能仅凭提到某动作就算完成。建议、软件标注和实物已完成分别记录。

重复回复根因是 `commit_result` 把真实模型 answer 强制换成旧的 `render_current_step`。已移除，并修正运行中/消息历史交接时的重复气泡；未校验的临时生成文字不作为最终回答发布。

## 问答与搜索链路

保持一个 AgentScope 2.0.11 ReAct 主 Agent，现有 qwen3.6-plus。不是把所有问题匹配到固定答案，也没有新增一个平行的 Agent 或事实库。

当前用户问题/照片 → SQL 中获准的物品、同一任务、有效记忆和 ReMe 检索投影 → 有界的最近 12 条实际聊天 → 主 Agent 按需选工具 → 原生结构化结果 → 权限/引用/版本/实际报告校验 → 同一 SQL 事务写入知识、记忆与任务 → 回答。

常见初步排查先结合已有信息回答，不要求先找齐手册。需要型号专用按钮组合、参数、拆卸或用户明确查资料时，再搜索与读取原文。搜索通过百炼 Responses web_search，返回的搜索调用收据与实际获取原文分别记录；摘要不冒充读过手册。单轮外部检索最多 3 次，每次有 14 秒预算；工具失败返回 unavailable，Agent 应停止无效重试，先给通用建议。

截图中的台灯失败确实调用了搜索。搜索耗时约 33 秒，之后有一次原文连接错误，随后取得官方 FAQ；最终结构化输出重试及旧上下文膨胀导致约 240 秒总超时。已压缩旧 SDK 工具轨迹、移除重复计划展示并允许简短 answer。85 秒主循环预算耗尽后，使用同一千问模型作一次无工具回答恢复，另有 22 秒预算；这条恢复路径不宣称已更新计划或取得资料。用户主动停止不会触发恢复。

通用初步建议可用 basis=general；已核验原文用 document。保留对无依据型号参数、接口与具体控件的检查，避免为了尽快回答而编造 USB-C、触摸开关或复位秒数。这不是完整事实校验，回答质量和耗时仍需继续改进。

## 通用 3D 示意

当前步骤 + 实物照片（本轮最多两张，或物品照片）+ 有权限的原说明书页图 → qwen3-vl-plus → 有界 schematic/1 JSON → 引用、权限和步骤版本复核 → Three.js/Bygga 渲染。

复用 MIT 的 Bygga 渲染器，未使用它的商品目录或固定桌子答案。支持 box/cyl/sphere/arc/cone、塑料材质，细杆可用两个端点生成朝向；没有执行模型生成的 JavaScript。零件编号和可点击名称用于高亮，避免长名称互相遮挡。默认视角保留 Y 向上。

已实际用官方 TERTIAL 台灯照片和 Sony WH-CH720N 外观图调用视觉模型生成。成功返回/渲染不等于几何正确：耳机结构可读；台灯关节/比例仍有偏差，属于粗略外观示意，不能当成照片到精确 CAD 或可靠装配位置。没有预存这两类的坐标模板。生成约 21–26 秒，之前的结构校验失败也保留在隔离评测记录。

接口 `POST /api/tasks/{id}/diagram` 接受 expected_version、step_id、photo_ids。外部照片不可越权，异步调用期间任务变更会拒绝发布旧图；生成图解不改变实际步骤完成状态。

## 自动相机与追踪

打开相机辅助 → 浏览器权限许可 → 自动拍摄一帧 → qwen3-vl-plus 根据当前目标语义返回边界框和候选 → 本地追踪器初始化 → 对云端等待期间的有限帧缓冲对齐 → 浏览器持续画框。丢失/低可信时先清框，再自动重新定位；没有「定位当前帧」「开始跟随」按钮。相似物品不擅自选第一个，保留可折叠圈选校准。

本地首选 OpenCV Zoo 的 ViTTrack，模型约 715 KB，Apache-2.0，固定 revision/SHA-256，随源码提供许可证。ONNX Runtime Web 1.31.1 WASM CPU 单线程执行。参考 OpenCV 的模板/搜索裁剪、归一化、Hann window、置信图与框解码，并限制异常 ROI。加载失败时回退现有 OpenCV LK 光流。不是 SAM2，也不是每帧上传大模型；云端最多每分钟 6 次且间隔至少 8 秒，追踪稳定时约 20 秒作语义复核。

本地视频可替代相机；原视频留在浏览器，仅必要定位帧上传。关闭窗口停止媒体轨道、取消网络与追踪。Windows 的 .mjs MIME 错误已修复，避免学习式追踪器被悄悄回退。追踪不把教学状态标为完成。

## 验证与边界

- 90 项 unittest 全部通过；契约从 Pydantic 生成，前端类型和生产构建通过。测试不调用付费 API。
- 用真实 API 复测截图中的台灯首答、自然负反馈和 LACK 装不上。首答约 29 秒，负反馈约 70 秒，LACK 约 23 秒；原重复模板被消除，但负反馈仍可能建议过于保守或重复检查，不能宣称所有智能质量已验收。
- 原始 OTB Car4：旧 LK 在第 31 帧跟丢（约 1.2 秒）。ViTTrack 只给第一个人工标注框，连续处理后续 658 帧（约 26 秒），框 IoU 中位数 0.797，均值 0.758，94.8% 帧 IoU≥0.5；单帧中位 26.6 ms、P95 29.8 ms。未用后续真实标注重置追踪。
- 同一真实片段通过虚拟摄像头走完整链路：真实千问自动定位约 8.9 秒出现标注，随后可见框的 IoU 中位约 0.749；片段循环到开头时出现丢失，需自动重新定位。
- 台灯用真实官方照片合成了抖动、平面透视、模糊与全遮挡片段。不是手持实拍，也不证明真实 3D 视角泛化。遮挡后自动找回，但本次从约 10 秒丢失到约 25 秒重现，恢复仍慢。
- 没有开启用户的物理摄像头。家电真实手持视角、相同零件混淆、长时间遮挡及更多独立对象仍需验收；不把一个车辆基准当作全场景通过。

可复现实验：准备合法取得的 OTB 帧与 XYWH 标注，构建并启动项目，安装可选开发工具 @playwright/test/Chromium，然后执行：

```powershell
node scripts/benchmark_vittrack.mjs http://localhost:8000 C:/data/Car4/img C:/data/Car4/groundtruth_rect.txt tmp/car4-results.json
```

可设 BROWSER_PATH 使用本机 Edge。脚本只在浏览器本地推理，不访问摄像头、不调用云端，只以第一帧标注初始化。完整视频、私人数据库、真实 API 原始运行日志不提交 Git。
