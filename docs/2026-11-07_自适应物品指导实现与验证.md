# 自适应物品指导：实现、真实失败与验收状态

日期：2026-11-07。分支 `codex/adaptive-product-guidance`，基线 `666e758`。状态：**工程检查通过，通用冷启动教学仍未验收**。本轮不合入 main、不对外部署。`experiments/` 与其他已有未提交文档未修改、未暂存。

## 已实现

- 保留 AgentScope 2.0.11 单主循环。`assistance.py` 统一当前物品、任务绑定、相关上下文、来源适用性和已有照片选择；不再默认注入用户最近四个不相关任务。明确否定另一型号不会触发错误切换。
- 修复当前 SDK 的工具适配：FunctionTool 将 ToolResponse 转为字符串，图片块和错误状态因此没有正确传递。统一返回 ToolChunk，保留原始 JSON、DataBlock 与错误状态；新增经真实 Toolkit.call_tool 的回归，不能仅用模拟模型验证适配。
- 最终结构化结果与实际计划写入检查物品范围；用户要求带做时必须建立 guidance。未收到结构化结果、超时和上游异常不能悄悄跳过检查或冒充实际成功。明确请求带做时，超时可保存仅观察现状的 pending 准备步骤。
- 已登记物品照片及用户自己对该物品提交的照片可进入主模型，也可经 `inspect_item_photos` 按需查看。新增 0007 迁移保存消息发送时的 item_ids，避免同一对话后来换物就将旧照片重新归属。历史消息不臆测回填；封面照片仍可复用。
- 图文和 3D 辅助统一使用后端当前物品的照片关联；去掉前端跨整个话题取最后一张照片的入口。优先本物品最近的照片报告，再用封面。
- `research_product` 复用适用原文和明确来源 URL、生成型号变体查询、保留收据、搜索摘要及候选原文。不匹配时有限核对其他来源，不把重复域名或 PDF 当权威。照片识读写入与依赖新型号的检索须先后执行，暂定型号优先搜索铭牌与商业版本对应；新物品先经过研究工具，不能只看搜索摘要。
- 视觉推断的 edition 不直接写成正式版本，只保留 candidate_product；document_match 要求实际原文包含型号。未知版本保持空值，不用外观推测确认代际。
- 联网搜索、原文下载与真实性/型号适用性分别表达。失败收据保留查询、URL、HTTP 状态及原因；预算耗尽、超时不等于网上没有资料。
- 公开资料下载适配已有系统代理；保持独立公网解析、逐跳检查、连接已验证公网 IP、正确 TLS 域名与证书验证。增加国内公共 DoH 后备及有限的已验证 CDN 地址切换。`source_transport.py` 解决已安装 httpcore 在代理 CONNECT 后忽略原域名 SNI 的实际问题；没有修改第三方包、关闭证书检查或放开私网。
- 保留 `product-guidance`，新增 `product-research`，技能负责研究和带做方法；业务约束由程序执行。两者通过技能格式检查。
- 首次教学支持简短总览、当前一步、观察信号、真实反馈和按需图文/3D/相机辅助。原 AS2 教学包、审核图示和状态控制保留。
- 依据检查覆盖 instruction、success_signal、caution 和失败分支；精确温度、时间、电气、负载参数和电池规格不能藏在“通用建议”或成功信号里。商业名称与型号对应仅在明确的来源身份匹配后用于该来源。
- 带做正文由本轮校验后的当前步骤呈现，不再额外生成操作文章；普通解释仍可直接回答。负反馈须提交同一任务的观察检查变化，网络/模型中断时保留同一步。支持手册常见中英文控件、时间单位及 AA/5号电池等价，不因合法翻译反复阻断；未经引用的细节仍检查。错误引用提示只列当前用户当前物品已读原文 ID，不泄露他人来源。
- PDF 文字提取复用现有 PDFium，与原页渲染共用原生调用锁，关闭页和文字句柄；解决真实 CFF 字体手册解析问题，不增加字体解析依赖。实际重新解析的 13 页罗技 PDF 约 0.05 秒、76 页米家 PDF 约 0.13 秒；这些是本机文件解析记录，不是网络或模型响应时间。

## 验证与原始失败

最终完整离线回归 **132 项通过**（113.363 秒），包括 SDK JSON/图片/错误状态、来源修复权限、AS2 与现有业务。前端生产构建通过，现存大分块警告保留。OpenAPI 形状未改变，因步骤依据字段说明更新已重新导出契约并生成类型。桌面与手机浏览器使用合成档案验证总览、任务恢复、无页面异常和无水平溢出，截图不能当作真实模型验收。两份应用 Skill 通过格式检查。

真实调用使用现有百炼账号与隔离测试库：天猫精灵 TG_C1（文字模式）、罗技 M330、米家 MJTD01SYL；都没有专用教学包。档案和拥有关系是模拟的，没有实际操作实物。首答和复测均保留，运行 completed 不计为教学通过。

已实际取得罗技原厂 PDF（约 564 KB，独立下载探针约 13.36 秒）。复用首次取得的原文后，真实主 Agent 读取原文并生成了绑定 M330 的可接续计划，耗时约 125.58 秒。此轮还发现未来步骤的成功信号有未被所引句子支持的数字，已扩展证据检查；不能把该计划整体当作已验收教程。

冷启动真实测试仍出现搜索 API 超时、网页下载失败和约 143 秒后降级为准备步骤，尚不满足“好用、快速、稳定完成带做”。没有观察到回答切换为 AS2，但少量开发样本不能证明所有物品与问法都正确。

用户随后明确允许 `data/realdemo/tianmao/1.jpg`、`2.jpg` 仅用于本次验证，已使用现有百炼服务完成真实照片调用。首轮读出 TG_C1，也出现了未证实的环形灯、蓝白灯与长按分支，已据此修复。后续已实际读取我爱音频网方糖 R 拆解原文（https://www.52audio.com/archives/34632.html）；它指出不同商业版本共用 TG_C1，并列铭牌及外观。该资料用于辨版本，不能当作蓝牙教程；自动商业版本核对仍不稳定。原始照片和所有失败记录仅保留本地，不提交。

最后一轮三物品冷启动仍约 143 秒后回退观察步骤，没有 AS2 串入和虚构完成；不能计为完整教学成功。最后的引用修复复核中，**M330 冷启动实际搜索、读取罗技原厂 PDF 并建立带引用的三步任务，约 95.89 秒**，当前只展开插入接收器一步。它证明冷启动链路可运行，响应时间与跨物品稳定性仍不足。

另以实际下载的原厂 PDF 在新隔离档案复用，未预置答案、知识结论或教学包：M330 约 28.27 秒生成 USB 接收器当前步骤；MJTD01SYL 约 37.42 秒生成按压旋钮开灯及后续旋转调光步骤。均待用户反馈，未执行实物。两次开发记录不是严格性能对照实验或通用成功率证据。

米家手册第 5 页图文接口约 7.49 秒回显原页，定位未知时保留 unannotated_source_image；3D 约 13.42 秒生成 schematic/1、press 动作，明确旋钮高度/行程未知，没有推进步骤。未验收真实视频动作追踪，也没有实现任意物品高精度重建。

## 数据与并行协作

启动已有库时，原有迁移机制先生成 SQLite 备份再升级到 0007；本轮没有删除或重建用户 var 数据。新增列默认空数组，保留旧消息原文、照片引用和所有任务。不为历史照片捏造物品关联。

`httpcore` 原锁定版本 1.0.9 不变，只补充直接依赖声明与项目锁元数据。没有开通新收费服务或修改全局 Codex 配置。运行日志、测试库和真实调用原始记录保留本地，不提交源码仓库。

另一工作线可继续维护 `experiments/` 的 3D 实验，沿既有 diagram 端点和 schematic/1 接入。本轮未重写 3D 引擎或提交实验目录。仓库内协作入口见同日《自适应教学协作记录》。

## 下一验收点

继续完成天猫精灵商业版本自动交叉核对与持续带做，降低资料筛选和引用修复的无效轮次；在新物品、模糊照片、不同问法、共享/撤权、换物纠正和网络失败场景冻结独立验收集。观察回退不计教学成功，实物观察和真正完成须有实际报告或可靠设备证据。外部模型、网络延迟及未知实物状态不能由离线回归替代验收。

可复用的技术价值在于把物品身份、来源证据、计划进度和视觉辅助接成同一反馈闭环；当前证据还不足以宣称任意物品适配、完整实时动作理解或对比 benchmark 领先。
