# 物品智能服务｜完整产品说明书 V1.1

**副标题：以真实物品为中心的 AI 生活服务与家庭协作平台**  
**文档性质：** 团队产品定义基准稿（V1.1，产品方向已基本确认；交互和技术细节仍待验证）  
**所属项目：** 天猫 AI 黑客松 · 智能日常｜Product Agent（与 AI WORKS 独立）  
**版本日期：** 2026 年 10 月 15 日  
**适用范围：** 产品共识、体验设计、需求拆解与后续 Demo 设计；不等于已实现功能、工程排期或最终商业承诺。

> **产品定位：** 面向购买、拥有或使用实体物品的人，建立低负担的物品数字身份与个人/家庭物品空间。AI 在用户需要时帮助理解、使用、管理和组合已有物品，也支持主动发现生活妙用、记录故事、共同照料和将数字心意随礼物传递。  
> **核心目标：** 从物品的价值出发，理解人与物品的关系，最终让物品更好地服务人的生活以及人与人之间的关系；以尽可能低的管理成本，帮助用户发现、获得、延续和分享实际价值与情感价值。  
> **基本原则：** 有事时可靠，没事时可探索，长期使用时省心；人格化和游戏化是可选体验，不能干扰真实任务。

## 一、产品为什么存在，以及我们希望它成为什么

### 1.1 问题起点：买到物品，不代表真正获得了价值

物品到了用户手中之后，仍可能面临不会使用、说明书丢失、功能被忽略、其他用途想不到、配件无法匹配、家里已有却忘记、维护与保修中断、家人需要帮助却无法迅速解释、赠送后知识与故事无法延续等问题。

电商能够提供交易线索，照片与扫码能够提供实物线索，说明书能够提供商品知识，家庭成员又有各自的经历。但这些信息分散、时效不同，也缺少一个围绕**具体物品及其与人关系**持续工作的服务入口。

本产品希望减少从「我有这件东西」到「我知道怎么用、还能怎样用、如何照顾它、怎样与家人共享」之间的摩擦。

**价值递进原则：从物品出发，理解人与物品的关系，最终回到人与人。** 商品知识和物品状态是起点，人的目标、能力、习惯和意愿决定服务方式；家庭协作、老人关怀、赠送与记忆传递进一步把物品服务转化为独立生活、相互照料、合作与情感表达。AI 不应只优化物品的使用频次，也应关注人与人是否因此少了负担、多了便利与连接。

### 1.2 产品是什么，不是什么

**它是：** 围绕真实物品组织知识、用户关系、生活任务、创意和持续服务的 AI 产品。用户可先直接询问物品，也可将其纳入长期物品空间；个人与家庭共享同一套物品服务能力，但拥有不同的信息边界。

**它不是：** 强制盘点家庭资产的库存软件；只能读说明书的 AI；每件商品必须运行一个独立模型的多 Agent 系统；单纯的智能家居控制台；通用生活聊天助手；以购买转化为首要目标的导购工具；需要用户每天喂养角色的虚拟宠物应用。

「让物品活起来」可以是有趣的创意表达，但**不是要求所有物品都人格化**。人对物品的真实需求、故事和生活目标，始终比拟人形式更重要。

### 1.3 用户范围与产品边界

产品面向**所有购买、拥有、使用或接触实体物品的人**，不把某个年龄群体作为唯一目标用户。年轻人、家庭管理者、老年人、兴趣爱好者和复杂设备用户可以在同一系统内使用不同能力。

原则上涵盖家电、数码、工具、厨具、家具、服饰、玩具、手工材料、食品、消耗品、收藏品、礼物、旧物及自制作品。不同类型物品的服务深度不同：复杂耐用品适合深度指导和维修记录；消耗品适合轻量使用与补货；有情感意义的物品可附加故事与角色；自制作品不要求有品牌 SKU。

系统不需要接管用户所有生活目标。只有当某个任务与真实物品、家庭物品关系或相关服务有关时，才应发挥自身优势。

### 1.4 我们说的「有效价值」

暂定定义：**在用户认可的生活情境中，产品以合理的时间、注意力、隐私与管理成本，帮助用户更好地使用、发现、保存或分享物品所带来的实际利益、积极体验，以及人与人之间的协作、照料与情感连接。**

| 价值维度 | 可能的用户收益 | 不应混淆为 |
|---|---|---|
| 使用与解决问题 | 学会操作、完成任务、减少错误 | AI 回答很多字 |
| 创造与发现 | 看到新用途、实际尝试有趣组合 | 随机生成许多妙招 |
| 管理与持续性 | 找得到、管得住、少操心 | 录入物品数量最多 |
| 家庭与关怀 | 家人协作更省力、长辈更自主、关怀更及时且不过度干扰 | 家庭群消息更多、未经核实的异常报警 |
| 情感与传递 | 留住回忆、表达心意、收到独特礼物 | 对话轮数、虚拟角色活跃度 |

这是价值框架而非一套已经确定的 KPI；具体衡量需要真实用户任务与主观体验验证。

## 二、产品体验总图：从一次提问到长期物品关系

### 2.1 两种进入方式，一个物品世界

**A. 生态自动导入（有条件的未来能力）：** 在真实接口和用户授权存在的前提下，购物记录、到货与商品资料可以形成候选物品，减少手工录入。特别是淘宝/天猫生态有潜在优势，但目前不应宣传已取得真实订单接口。

**B. 主动识物（不限制购买渠道）：** 拍照、扫码、输入型号、上传订单截图或手动建立物品；覆盖其他平台、线下、赠送、旧物、自制作品。条码/二维码并不一定能直接获得精确型号或完整说明书，必要时要补充确认。

**先问再存：** 用户首次打开 App，可以不注册、不建档，直接拍照或输入问题获得临时的物品服务。长期保存、跨端同步、家庭共享、赠送及认领再引导建立持续身份与必要授权。免注册的具体会话保存范围待设计。

### 2.2 五个自然的使用入口（候选导航，不是固定页面结构）

| 入口 | 用户的自然意图 | 典型动作 |
|---|---|---|
| **直接问 / 扫一扫** | 这件东西是什么、怎么用、怎么修 | 拍照、查说明、逐步操作 |
| **发现** | 家里东西还有什么玩法 | 生活妙招、跨物品组合、收藏与尝试 |
| **我的物品** | 找到、管理、照料某件东西 | 查看档案、状态、维护、保修 |
| **家庭空间** | 我们家有什么事要一起处理 | 共享物品、安排任务、协助家人 |
| **礼物与记忆** | 保存故事、传递心意 | 角色、影音、赠送、认领 |

此外，用户可直接提出「我想做什么」，系统从物品与相关条件中生成方案。上述入口能互相跳转，不将一次任务锁死在一个独立小程序里。

### 2.3 一件物品的完整关系链

**商品资料 / 订单或实物线索 → 具体物品数字身份 → 个人或家庭使用与服务 → 维护、探索、协作与记忆 → 归档、借用、出售或赠送 → 经授权的关系与知识延续。**

这里至少需要区分：商品型号、购买记录、具体物品、谁购买、谁拥有、谁使用、谁代管、哪些是官方知识、哪些是用户故事及什么已得到确认。它们可以关联，但不应被混为同一条事实。

## 三、完整功能体系（F1—F12）

**说明：** 下列 F 编号是业务功能分类，不代表开发先后、独立 Agent 数量或已实现状态。「核心」表示在完整产品定位中不可缺少；「支撑」表示为核心体验提供必要条件；「扩展」表示可在后续合作或技术验证后深入。

### F1｜识物、录入与低门槛开始（支撑 · 核心入口）

**用户目标：** 让系统认得眼前物品，不要求先手动维护完整清单。

- 拍照识物、扫描商品码/包装码、识别铭牌文字、按名称/型号查找；必要时让用户从候选型号中确认。
- 允许从购物记录、订单截图、商品链接或已有凭证形成候选物品；淘宝/天猫真实订单同步为待确认的生态接入方向。
- 支持线下、其他平台、二手物品、他人赠送以及自制作品手动录入；自制物品允许只填写名称、图片、描述与制作人。
- 临时识物与提问不强制注册；愿意长期保存时才将临时物品升格为具体物品档案。
- 自动分类、同款多件识别、去重、批量处理、错误纠正；允许只录入少量值得关注的物品。
- 购买订单只说明曾经发生交易；不自动断言物品已经收到、仍在家里或者属于订单购买者。

**输出体验：** 用户能够从一件真实物品立即进入知识与服务，并可一键选择「留在我的物品」。

### F2｜物品数字身份与个人物品空间（支撑 · 核心底座）

**用户目标：** 让每件具体物品有可查、可更新、可流转的记录，管理负担尽可能低。

- 基础档案：名称、照片、品牌/型号（如有）、来源、数量、购买/取得时间、凭证、使用说明、保修与相关附件。
- 关系与状态：所有者、购买者、实际使用者、代管者、个人/家庭空间、位置、在用/闲置/借出/送出/售出/报废/待确认等；维度可组合，不以一种状态代替全部。
- 分类、搜索、筛选、房间/场景视图、收藏与高频物品快捷入口；按需录入备注、配件、位置与维护偏好。
- 生命周期可回溯：创建、确认、共享、维修、转移、归档；及时修正过时数据。
- 消耗品支持「可能还有 / 已用完 / 待确认」等轻量状态，不强制精确逐件扣减。
- 用户可导出、删除、纠错或转移相关记录；删除/退出家庭空间的权限和数据保留规则需要明确。

**输出体验：** 系统知道「这台具体咖啡机」而不只是「某款咖啡机」，但不会为了完整档案反复打扰用户。

### F3｜单物品 AI 服务与现实操作帮助（核心 · 解决实际问题）

**用户目标：** 不翻多份资料，就能弄明白具体物品并把事情做成。

- 可信商品介绍与问答：准确型号、官方功能、不同版本、保养、适用配件、参数与限制，展示依据。
- 首次使用与深度使用：开箱验收、组装、配置、安装、隐藏或少用的官方功能、进阶设置。
- 多模态辅助：文字、语音、图片、截图、OCR、说明书图示与实物按键/接口定位；实时摄像头指导可按技术可行性逐步加入，非强制入口。
- 分步执行：步骤卡、上一/下一步、暂停、关键状态确认；出现「我这里没有这个按钮」时重新核对型号/版本而不是继续猜。
- 故障诊断：优先低风险、可观察的排查；用户可以选择「还是没解决」并获得回退和人工售后衔接。
- 结果分级：已给出建议、用户执行操作、用户确认成功、客观证据证实结果是不同状态；没有可靠传感或接口时不得声称自动修复成功。
- 维护与售后资料：记录已尝试步骤、生成问题摘要，经确认后分享给家人或官方客服。
- 不同能力用户的适配：简化语言、大字、朗读、短步骤、求助家人；无障碍是实际任务的必要条件，不是附加装饰。

**输出体验：** 物品知识被转化为可执行的帮助；不确定时知道该问什么、何时退出或交给专业人员。

### F4｜物品妙用发现与轻游戏化探索（核心 · 主动吸引力）

**用户目标：** 主动看看「这个东西还能这样用」「我已有的两件东西还能这么搭」。

- 「发现」入口由用户主动打开，展示基于已录入物品或用户选择的临时物品生成的用法、创意和搭配；不依赖大量推送。
- 区分三类灵感：用户不熟悉的现有功能、由已有能力重新组合的用途、超出典型用法的候选生活小妙招。
- AI 可结合可靠的商品知识、经过核验的实际案例和创意推理提出方案；外部创作者内容的获取、使用、引用与版权需另行核实。
- 每条玩法说明适用的物品、所需材料、具体做法、时间成本、限制、风险和还需确认的条件；不能把未验证的创意表述成已实测成功。
- 支持「收藏 / 换一个 / 我想试试 / 已尝试 / 分享成果」，真实成果照片可在授权下成为私人记录。
- 允许用探索地图、组合卡、成就记录等轻量游戏化形式增加趣味；奖励真实探索和创造，不设置强制签到、喂养或消费任务。
- 对加热、电气、承重、食品接触等非典型用途，优先核实材料与安全条件，不适合时说明原因或提供保守替代。

**输出体验：** 有「原来还可以这样」的惊喜，同时尽量可做、值得做。**核心验证点**不只是觉得有趣，而是实际采纳和真实体验。

### F5｜目标驱动的多物品组合与任务规划（核心 · 解决实际问题）

**用户目标：** 我已经想做某件事，AI 帮我优先利用已有物品，而不是默认让我再买一套。

- 从用户目标出发解析人数、时段、地点、预算、技能、设备条件与限制；只追问最关键的未知事项。
- 查询本人有权限使用的个人物品及家庭共享物品，按实际功能、状态、数量和兼容关系组织候选资源。
- 区分 **能力协同**（例如接口/尺寸/协议需要匹配）和 **任务协同**（多件日常物品分别承担准备与执行角色）。
- 输出「已确认可用 / 待确认 / 可能缺少」与步骤化的方案；指出替代选项，允许不同偏好下的省钱、省步骤或效果优先方案。
- 生活场景可以是手工制作、野餐出行、房间整理、家电更新后的旧配件沿用等；不预设烧烤、直播等示例一定是高频真实需求。
- 方案可生成清单、任务及相关物品卡片，一键转入家庭协作空间；从具体操作步骤可跳转到 F3 的单物品服务。
- 缺口必须经确认后再建议补充商品或服务；**「无需购买」是完全正确的结果**。

**输出体验：** 用户把「已有的东西」变成完成目标的资源，不需要自己逐件翻说明书、重复解释。

### F6｜家庭协作空间：围绕物品共同做事（核心 · 重点深化）

**定位：** 借鉴飞书式协作产品的**共享空间、任务分工、状态跟进、信息复用和权限机制**，但面向家庭，围绕具体物品与生活事务展开；不把家庭变成一个复杂的企业管理系统。

#### A. 家庭空间与视图

- 用户可创建或加入家庭空间；每个人保留自己的个人物品库，主动将指定物品、资料或任务共享给家庭。
- 家庭首页建议呈现「我们共享的物品」「需要处理的事项」「近期协助与提醒」「家庭活动清单」，而不是默认展示每个成员的购物历史。
- 家庭可设常用区域、设备及共同资产分类；一件物品可显示主要使用者、当前负责照料的人和维护资料。

#### B. 以物品为中心的协作单元

- **共享物品卡片**：型号、必要说明、状态、耗材、保修、共享附件与记录。每次协作围绕同一张卡片展开，避免消息散落在群聊。
- **物品关联讨论 / 留言**：针对某件物品留言、@相关家庭成员、附照片和说明，后来的人仍能看见问题上下文；消息与资料按授权可见。
- **任务与责任人**：例如「给净水器换滤芯」「帮外婆设置电视」「修理书房台灯」可指定负责人、截止提醒（可选）、处理状态与补充说明。
- **处理状态与交接**：待确认、待处理、进行中、已处理、未解决/转售后；对未解决事项保留已尝试步骤与下一责任人。
- **家庭清单与活动协同**：例如一家人出游，使用已有物品生成准备清单，分配谁负责哪些东西，完成状态共同可见；无需形成企业级审批流程。
- **家庭知识沉淀**：把一次真实解决方案、说明书、常见故障、重要维修资料关联在物品下，之后换人处理仍能继续使用。

#### C. 家庭角色与权限边界

- 区分物品所有者、使用者、代管者、家庭空间维护者、被邀请协助者；权限按对象与操作细分为查看、编辑、执行、分享、转移。
- 家庭管理员不等于所有人的所有物品和订单都可见；私人物品必须明确分享。敏感物品、聊天与赠送记录尤其需要独立授权。
- 可邀请家庭成员或临时协助者，通过限定范围的链接/二维码获取单个物品的帮助；协作不以所有人都熟练使用完整 App 为前提。
- 家庭成员退出、物品所有权转移、撤销链接、删除信息时，应有清楚的数据权限规则。

#### D. 家庭 Agent 的角色

- 在得到授权的范围内，AI 可以汇总「这周家里哪些物品事项需要处理」、帮成员理解某件设备、生成任务和清单、提醒相关负责人、整理处理记录。
- AI 负责组织信息与建议，成员决定是否执行或转交；不对家庭成员实施持续监控，不自动分享个人数据。
- 对老年用户优先提供简化界面、语音、大字、按物品直接求助，以及「请家人帮我处理」；家人收到的应是**具体问题与相关物品**，而不是老人全部活动轨迹。

#### E. 两类家庭照料与主动提醒（已确认均纳入产品方向）

- **A｜物品照料：** 根据有依据的安装/维护时间、耗材期限、用户确认或授权设备数据，形成滤芯更换、清洁保养、长期闲置检查等提醒；可指派家人协助，支持推迟、合并和关闭。维护周期推算不等于实时检测到设备状态。
- **B｜家人关怀：** 在长辈本人知情同意、确有可靠使用信号和适当习惯基线的情况下，针对某件平时常用设备较长时间未出现使用记录等情况，向预先约定的家人发出**需要温和确认的线索**。这不意味着系统能据此判断长辈健康、安全或是否发生意外。
- **信号和授权边界：** 普通非联网物品不能凭购买记录推算实际使用。需明确数据来源、监测的具体设备与时间范围、提醒对象和规则；长辈可调整、暂停或撤回授权，异常提示需要考虑设备离线、外出、习惯变化等误报因素。
- **人与人的目标：** A 帮助家人分担家务照料与维护责任；B 帮助子女适度关心长辈，同时保留长辈的自主权、尊严与隐私，而不是制造持续监控和焦虑。

**一个代表性闭环：** 父亲说「净水器提醒灯亮了」→ 从共享物品卡片发起协助 → AI 匹配型号、判断需核实的滤芯/状态 → 家庭任务交给女儿 → 女儿查已购买耗材与说明 → 用户确认更换 → 记录日期与用户确认结果 → 下次维护时可复用。没有设备接口时，不能宣称自动检测滤芯已经换好。

**输出体验：** 家庭物品事务有人接手，处理过程可见，知识不因家庭成员变化而中断；既保留协同便利，也尊重个人空间。

### F7｜从购买到使用的生命周期管理（核心 · 持续服务）

**用户目标：** 不再因为包装丢失、保养遗忘、找不到售后或重复购买而麻烦。

- 物流与签收（需真实接口）；到货后关联准确型号、开箱检查、使用说明和凭证。
- 保修、售后、维修记录、退换货、二手出售与归档；异常时由用户确认后整理并发送售后资料。
- 维护计划、过滤件或耗材适配、保质期/保修期等提醒；可推迟、关闭、合并，只在有用时通知。
- 消耗品余量和补货时机原则上只作估计，除非有明确用户确认或可靠数据，不能称作实时库存。
- 家庭共同照料的物品可自动生成待办候选，**是否创建任务、分给谁由有权限的人决定**。
- 深度管理可选：有人愿意精确管理，也有人只需要在出现问题时找得到这件物品。

**输出体验：** 围绕物品的购后记录与服务连续，不需要用户把 App 当日常记账任务。

### F8｜赠送、收礼、分享与物品流转（核心 · 关系连接）

**用户目标：** 任何渠道的实体礼物，都可以先进入系统，再把实物与一份独特的数字心意一起传递。

- **已确认业务前提：赠送前先录入系统。** 不限渠道：淘宝/天猫、其他平台、线下、手工作品、珍藏旧物都可建立物品数字身份。
- 从已录入物品发起赠送，选择文字祝福、语音、照片、视频、共同故事、独特的开场或带特定性格的可选 AI 角色。
- 可制作数字礼物链接、二维码或卡片。实物交付可以在线下、现有电商订单或未来授权的 App 内送礼流程中完成，不依赖自有交易系统。
- 收礼人可无需注册先打开数字内容；选择保留物品、角色和长期记忆时再完成认领与权限设置。
- 礼物可以携带授权的使用说明、必要保修信息及送礼故事；**不得直接转交赠送者的私人订单、聊天或不相关个人信息**。
- 认领后形成新的拥有/使用关系。赠送者保留自己的赠送纪念；收礼人后来新增的记录归其自己管理，不默认向赠送者同步。
- 借用、代管、家庭内部转让、售出、捐赠、归档也可以采用同一套物品身份与关系变更机制，但不强迫每次流转都制作礼物体验。
- App 可支持围绕赠礼的定向消息、回复与纪念内容，**不必因此变为通用社交聊天平台**。

**输出体验：** 礼物不仅是一件商品，还能携带由真人设计的心意，并允许物品在新关系中继续留下经历。

### F9｜物品记忆、个性化角色与可选陪伴（核心中的可选体验）

**用户目标：** 为有意义的物品保存真实经历，以喜欢的方式与其互动；不被强迫进入养成游戏。

- 每件具体物品可以保存真实故事、照片、时间、地点（用户主动授权）、修复经历、重要时刻与赠送记录；用户决定记录深度。
- 可以为喜欢的物品添加昵称、头像、角色风格、声音或开场故事。一个可爱的虚拟小宠物、小黄人式卡通角色或虚拟形象只是表现形式，而非产品中心。
- 角色可以基于用户授权的实际物品知识和故事交流，也允许清楚标注的想象性对话；不能把虚构回忆写成真实物品事实。
- 用户可以让特定物品拥有个性，也可完全关闭拟人化。刚需指导、售后、安全场景始终优先清楚准确的操作信息。
- 情感体验的长期价值优先来自用户真实记忆与人际关系；不通过角色抱怨、情感绑架、签到喂养等机制制造留存。
- 物品被赠送时，原拥有者选择哪些故事和角色设定可以传递；收礼人的私人对话与后续记忆受独立权限保护。

**输出体验：** 物品能成为记忆的载体；AI 帮用户表达、检索、讲述和传递这些经历，而不是虚构人与物品的情感事实。

### F10｜用户 Context、个性化与自主控制（支撑 · 横向）

- **懂人与懂物品同等重要：** 在用户明确表达或授权范围内理解兴趣、技能水平、生活习惯、家庭角色、时间与预算偏好，区分已确认、系统推测与未知；不以固定年龄标签决定一个人的全部需求。
- **理解关系和当下情境：** 区分购买者、使用者、照料者、赠送者和被照料者，结合用户当下想解决的问题、实际操作能力、希望得到的帮助程度与家人之间的分工，决定该提供何种服务、何时请求确认、何时转交协助。
- **动态、可纠正的 Context：** 物品使用习惯和个人偏好可能随时间变化；来源、更新时间和置信边界应可追溯。涉及长辈的设备活动或家庭协作时，只使用被明确授权的必要信息，不从单一设备信号推断人的健康或安全。
- 买过摄影器材不等于喜欢拍照；子女买的电饭煲不等于子女自己使用；允许更正角色关系。
- 同一用户在实用问答、创意发现和礼物创作中可使用不同交互语气，不默认让 AI 为所有场景持续套人格。
- 可查看、修改或删除长期记忆和推断；跨家庭或跨成员调用信息需取得相应权限。
- 给用户管理消息与通知的主动权：按物品、空间、事项类型设置关注程度。

### F11｜商品知识、Agent 与可信结果（支撑 · 核心基础设施）

- 可维护商品知识能力包（Product Pack 候选抽象）：Identity、官方说明/图示、FAQ、功能与参数、限制与兼容、操作步骤、证据来源和验证方法。
- AI 理解用户所说的物品及目标，按需检索知识、物品档案、历史与家庭授权信息，再调用图像、搜索、任务或外部业务工具；不要求每个物品运行一个模型。
- 多物品规划应结合功能与约束、所需材料、数量和状态，不只按商品名称自由联想。
- 输出说明来源与适用型号，区分官方资料、用户确认、经验案例及模型候选推断；危险建议需拒绝或转向专业人员。
- 结果记录区分「建议已给出」「人已执行」「用户确认完成」「外部证据验证」「尚未解决」，并支持失败回退或转交家庭成员。
- 对家庭图片、私密故事、订单、设备序列号等使用最小必要数据与清晰授权；云端、本地或混合模型路线仍待技术验证。

### F12｜平台与生态的长期延伸（扩展 · 非当前成立前提）

- 淘宝/天猫等生态的真实自动订单接入、商品服务链接、物流、售后与必要补充购买，依赖实际授权和合作。
- 品牌可维护的 AI-ready 商品资料或 Product Pack Builder，形成跨型号的可信能力与售后知识。
- 已授权设备的数据接口、可选择的端侧视觉理解、多用户经验经授权脱敏和交叉验证后的知识迁移。
- 已确认的物品能力缺口可连接相容配件、维修或替换建议；「不需要购买」必须始终是允许的结果。
- 好友互动、跨家庭协作与礼物传播可以适度演进，但不假设一定需要建立完整社交网络或商业闭环。

## 四、家庭空间：需要统一的一项关键产品认知

我们将**家庭空间视为产品核心之一**，而不只是 F3 的附属功能。它既承接物品长期管理，也让单物品服务、目标规划、礼物与家庭照料进入多人使用的真实场景。

### 4.1 我对「像飞书」的产品解释（待团队确认）

借鉴的是**协作结构**而不是把飞书的企业 OA 原样搬进家庭：

1. **共享工作空间：** 家里共同使用的物品与事，可以放到一个共同可见的地方；个人空间默认独立。
2. **对象化协作：** 类似围绕文档或任务协作，家庭成员围绕某件物品及其关联事项进行留言、更新、交接。
3. **责任与状态：** 谁来处理、处理到哪一步、下一步需要谁确认，不再淹没在家庭微信群记录里。
4. **信息复用：** 型号、说明书、保修、已尝试操作、解决办法沉淀在物品卡片上，后来的人无需从头问。
5. **多角色与权限：** 只共享应当共享的物品和信息，不让「家庭管理员」自动变成所有人的私人数据管理员。

**不建议照搬：** 层层审批、复杂 OKR、频繁会议、刚性打卡、密集催办或全员在线的企业文化；家庭空间应该比工作软件更轻、更温和。

### 4.2 典型家庭协作对象

| 协作对象 | 可以保存什么 | 例子 |
|---|---|---|
| 共享物品 | 型号、说明书、状态、责任、附件 | 客厅投影仪 |
| 待办任务 | 负责人、关联物品、步骤、状态 | 更换净水器滤芯 |
| 求助事项 | 问题、照片、尝试记录、回复 | 外婆找不到电视输入源 |
| 家庭计划 | 目标、准备清单、分工与确认 | 周末野餐准备 |
| 家庭知识 | 有依据的操作经验与维护记录 | 扫地机地图重设方法 |
| 礼物/流转 | 授权的故事、赠送信息与认领 | 手工礼物转赠 |

一件物品可以同时被多个任务引用；同一个任务也可以调用多件物品。**真正的协作核心是关系与持续上下文，而不是建一个家庭群聊。**

### 4.3 老年人与家庭关怀的深层要求

不要把老人场景等同于大字模式。需要进一步研究：老人是否愿意安装 App；能否通过二维码、快捷链接或家人辅助自然进入；步骤是否能对照真实按钮；如何处理失败与升级；家人是否看得到必要信息而不过度监控；不同家庭成员能否尊重长辈的自主决定。两类已确认的关怀方向分别是「物品维护与闲置提醒」和「基于知情授权、可信设备信号的家庭关怀提示」；其准确性、误报、隐私边界及长辈是否感到安心，都需要分别验证。若要把适老作为后续重点赛道，还需要独立的用户测试与无障碍设计。

## 五、关键用户旅程：检验功能是不是一个整体

### 旅程 A｜免注册的陌生物品求助

用户在朋友家看到某款咖啡机 → 拍照识别候选型号 → 询问某个按钮作用 → 看到有依据的步骤 → 临时使用后离开；仅在用户希望保留时再加入自己的物品空间。**价值：立即可用，不迫使建档。**

### 旅程 B｜购买后自然进入个人物品空间

用户新买空气净化器 → 生态授权存在时自动出现候选档案，否则扫码/订单截图进入 → 用户确认已经收到、正在使用 → 查看滤芯型号、保修和设置 → 后续按需维护。**价值：越来越少的重复解释和管理成本。**

### 旅程 C｜发现物品新玩法

用户主动点「发现」 → 从已拥有的拼豆、相框、收纳盒中探索创意 → 系统提出可执行组合并标注需要确认的材料 → 用户尝试、上传成果、收藏经验。**价值：惊喜 + 实际创造，且无需强制游戏化。**

### 旅程 D｜家庭协作与父母用家电

子女将家中的电饭煲卡片共享给父母 → 母亲通过简单入口查看预约步骤，遇到缺失按钮 → 生成协助事项交给子女 → 子女在物品卡片看到型号、照片和已尝试步骤 → 二人确认完成 → 共用知识记录保留。**价值：问题不再靠反复打电话从头讲。**

### 旅程 E｜家庭任务持续交接

净水器需要换滤芯 → 家庭空间生成待处理事项 → 成员查看型号和已购滤芯 → 指定负责人，确认是否需要采购 → 更换时按说明操作，记录用户确认日期 → 下一次可复用历史。**价值：管理、任务、知识在同一对象下闭环。**

### 旅程 F｜一件自制礼物的数字心意

用户把手工拼豆挂件拍照录入 → 选择「赠送」 → 附上自己的视频祝福、共同故事与可选角色 → 生成二维码 → 收礼人免注册打开体验 → 自愿认领物品并保留后续故事。**价值：实体礼物承载可传递的人际记忆。**

### 旅程 G｜任务型物品组合

用户明确说「周末四个人去野餐」 → AI 使用已授权物品记录，找出可用餐具、保温杯、坐垫等 → 询问哪些未确认的状态和目的地条件 → 给出准备清单，用户可分给家人协作 → 必要时补充采购。**价值：利用已有资源，减少遗漏，不凭空盘点库存。**

以上均为**待验证的用户旅程**，不是已经发生的用户案例。特别是场景是否高频、是否愿意打开独立 App，需要测试而非依据逻辑推断。

## 六、跨功能的逻辑与数据边界

### 6.1 数据对象与关系（产品语义，不预设数据库）

- **Product / Product Pack：** 商品型号与版本、来源、能力、限制、说明与兼容关系。
- **Owned Item / Item：** 一件具体物品及其状态、位置、归属和历史；手工物品可能没有对应 SKU。
- **Person / Family Space：** 人员、家庭角色、明确偏好、使用习惯（如有授权）、空间成员关系与权限；购买者、使用者、所有者、照料者不一定相同，个人情境与共享范围可以变化。
- **Task / Case：** 用户目标、家庭待办、求助事项、执行步骤、负责人、状态及结果证据。
- **Idea / Creation：** 单物品妙用、跨物品玩法、现实尝试成果与适用条件。
- **Memory / Gift：** 物品故事、祝福、影音、可选角色设定、转移授权与接收记录。
- **Evidence / Permission：** 资料来源、用户确认与推断、权限范围、更新时间和保留条件。

### 6.2 共享 Agent 的任务处理逻辑

**入口：** 扫描/文字/语音提问，主动探索，物品生命周期事件，家庭协作请求或赠送操作。  
**理解：** 识别任务、用户权限、相关物品与关键未知条件。  
**调用：** 商品知识、具体物品状态、用户明确偏好、家庭事项、内容与工具。  
**交付：** 答案、逐步指导、创意候选、任务清单、协作事项或礼物体验。  
**反馈：** 用户采纳、实际执行、用户确认与可观测证据分别记录；失败时回退或请求其他人帮助。  
**更新：** 仅以适当证据更新物品状态、共享任务、个人记录与记忆，不从一段对话推断出未经确认的家庭事实。

这是一套**业务逻辑**，不意味着后台必须部署一个或多个独立 Agent；LangGraph、Neo4j、云端/端侧千问模型等都是可评估技术方案，不在产品说明中锁定。

### 6.3 关键可信与隐私约束

1. 下单 ≠ 已拥有；已拥有 ≠ 在身边；理论功能 ≠ 当前能用；用户说成功 ≠ 设备客观验证成功。
2. 官方资料需要匹配具体型号、版本与适用条件；社区妙招与 AI 创意必须标明不确定性，必要时验证安全。
3. 家庭共享按物品、任务、记录和操作授权，不默认共享私有订单、消息和所有物品。
4. 赠送者设计的礼物内容与收礼者后续私人记忆分属不同权限范围；AI 角色不冒充真人、不得编造未经授权的私人经历。
5. 相机、家庭照片、语音、设备序列号等只做必要处理；高风险电气、燃气和危险维修应停止不安全指导。
6. 平台接口、设备实时状态、售后履约和 AI 自动购买等能力，未实际接入或验证前不得对外宣称已实现。

## 七、产品成熟度、优先级与后续验证

### 7.1 产品层面优先级（不是开发排期）

| 类型 | 功能 | 判断 |
|---|---|---|
| **核心用户能力** | F3 单物品服务、F4 发现、F5 目标组合、F6 家庭协作 | 共同表达产品既可靠、又有趣、能协作的完整体验 |
| **长期关系基础** | F1 录入、F2 数字身份、F7 持续管理、F8 赠送、F9 记忆 | 让用户和家庭的物品关系能够持续、流转和积累 |
| **横向可信支撑** | F10 Context、F11 知识/权限/结果机制 | 确保每项能力不误用个人信息和错误事实 |
| **可选生态方向** | F12 商家、平台、外部设备与经验网络 | 需要真实接口、合作和使用验证 |

**注意：** 家庭协作是核心，不是以后有空才添加的管理插件；物品妙用是独立的主动探索体验；人格角色不是所有物品必须具备的能力。功能角色不等于所有功能都在一轮 Demo 中实现。

### 7.2 设计与技术验证的主要断点

| 断点 | 要验证的问题 |
|---|---|
| 低门槛进入 | 扫一扫后能否匹配准确商品；找不到说明书怎么办；访客会不会愿意保留物品 |
| 自动导入与状态真实性 | 订单数据能取得什么；怎样低负担纠正赠送、退货、用完等真实状态 |
| 商品知识可信度 | 不同型号/版本的功能、限制、配件能否被正确检索和提取 |
| 真实妙用价值 | 新颖性、可执行性、安全性、用户实际尝试及愿意重复探索的动机 |
| 家庭协作易用性 | 家人会否真的建立共享空间和处理任务；是否比现有微信群沟通更省事 |
| 老年人独立完成 | 不熟悉 App 的人能否从物品问题进入并完成操作；求助路径是否足够短 |
| 家庭 A/B 关怀提醒 | 维护/闲置提醒是否准确且有用；授权使用信号是否可靠；长辈与子女是否接受关怀规则及误报 |
| 情感与礼物体验 | 数字祝福制作负担、收礼感受、后续保存动机和隐私分界 |
| 长期管理与留存 | 多久需要维护一次状态；提醒的误报率；用户是否真正主动回来 |
| 和通用 AI 的增量差异 | 对同一真实物品/任务，产品是否节省了重复解释、降低错误或创造独特体验 |

### 7.3 候选评价方式

**实际任务价值：** 完成率、耗时、出错与反复解释次数、家人协作完成率。  
**人与人之间的价值：** 家庭照料负担是否减少、协作交接是否更清楚、长辈能否更独立自主、关怀提醒是否及时且不过度打扰、赠礼心意是否被真实接收与理解。  
**探索价值：** 有用且新颖的玩法比例、用户自愿尝试率、真正完成的成果与负面体验。  
**管理价值：** 获得一次帮助所需的额外录入/确认成本、状态错误率、无效提醒率。  
**情感价值：** 自愿保存故事、送出与认领礼物、日后回访记忆的意愿及收礼人主观评价。  
**竞争验证：** 分别比较不用产品、使用普通搜索/AI、使用本产品的真实过程；不能以打开次数、生成内容数量或订单转化单独证明价值。

### 7.4 当前仍开放的决策

- 家庭空间的「飞书式协作」深度：以共享物品与任务为主，还是需要更强的家庭计划板、成员消息及文档协作？本稿暂以**轻量、对象化协作**为推荐解释。
- 家庭空间与个人空间之间的默认权限、临时来访者入口、老人无账号使用方式。
- 「发现」内容来源、适用性验证和游戏化表现；是否需要用户投稿与分享社区。
- 物品故事与角色具体表现方式、收礼后的角色与记忆归属。
- 真实淘宝/天猫接口、第三方商品数据库、品牌说明书与售后接口的实际可用性。
- 现阶段 Demo 范围、真实 AI/模拟能力划分、工程技术选型及团队分工；这些在产品概念确认后另行定案。

## 八、版本状态与团队共识核对

**已由对话明确的方向：** 从物品价值出发、理解人及人与物品的关系，最终关注人与人之间的价值；广泛实体物品覆盖；淘宝/天猫生态授权导入与不限渠道主动录入并存；免注册临时识物提问；低负担管理；单物品实际服务和用户目标驱动组合；主动打开的妙用探索及适度游戏化；刚需任务不得强制游戏化；长期物品记忆与可选角色陪伴；赠礼先录入物品且不限制购买渠道，可附带个性数字心意；家庭空间为核心之一，明确包含 A「物品照料/闲置提醒」与 B「获长辈授权、依据可靠设备活动线索的关怀提醒」，强调家人协作、长辈自主权及隐私边界。

**本版为便于设计而提出的结构化建议：** F1—F12 功能划分、五个首页入口、家庭空间的协作对象和任务处理状态、个人与家庭权限模型、具体用户旅程和候选评价方法。这些尚不能视为全部经过用户确认的界面或流程定案。

**明确不作为已实现或已获授权的事实：** 真实平台历史订单自动导入、跨品牌售后直接操作、全面实时实物识别与状态读取、可靠的新玩法自动验证、家庭账户同步、端侧模型、公共经验网络、自动购买或完整社交网络。

**文档依据：** 本项目产品 Chat 已确认的多轮产品讨论；《物品智能服务｜产品说明书 V0.3》；同学《产品功能与项目说明书 V1.0》及《ItemOS / 物伴》讨论稿；Agent 全景流程图 V0.2 的功能与断点说明。引用这些材料的功能是归纳团队探索，不等于认可其中尚未实测的技术或市场结论。
