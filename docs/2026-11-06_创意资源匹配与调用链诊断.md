# 创意资源匹配与调用链诊断

本次范围按用户最新要求收敛：优先已有物品驱动的生活创意，补充模拟家庭库存，修复任务进度和系统性重复生成。普通摆放、角度、轻微不稳可边做边调；不再以几何细节完美为门槛。照片关联和分身深入成长暂停，通知位置不在本轮范围。物品、人物、拥有关系和口头试用均须区分真实与模拟。

## 判断

1. 库存少会限制候选，不足以解释所有错误。确实缺剪刀、胶带时可以补录或只问关键工具；把已明确不透光的杯子当作投影胶片，或继续让大接头穿小圈，属于理解/迁移错误，增加物品不能自动修好。
2. 顺序应为当前资源与目标 → 可承担的角色/性质 → 检索相近分享 → 比较必要条件 → 用户能开始的一步。不能选好固定创意，再把物品名称填进去。
3. 已有 Agent + SQL + ReMe + 来源读取足以承载该流程。本轮不加入额外 critic、不新增图数据库、创意 Agent 或另一套知识事实库。

## 已落地的小改动

`agent_skills/creative-use/SKILL.md` 直接使用现有 `known_resource_index` 和 `focused_items`；资源已足够时不强制语义搜索。需要找旧尝试或索引外物品才调用 `search_world`。公开查询按现有性质和场景组织，一条实质可用分享已够就交付，不为凑来源堆搜索。知识沉淀只保存真正值得复用的新案例，不把读网页等同于必须增加知识。

这不是将安全检查全部去掉。明显危险、破坏纪念物、缺不可替代的关键工具、实际动作根本无法完成，仍须核实或换方案；普通的摆放细节允许先尝试。

新增 `fixtures/acceptance/2026-11-06_creative_home_inventory.json`：18 件模拟家庭物品，包含真实国内型号米家台灯 1S MJTD01SYL、华为 P50 ABR-AL00、小米插线板 XMCXB01QM，以及白纸、夹子、杯子、书、胶带、剪刀、笔、纸箱、布、绳、布袋、桌垫、线缆、桌椅。三组自然聊天覆盖拍照、理线、室友短时游戏；Agent 自己取得来源，未预置答案或原文。它们是开发样本，不能冒充独立验收。

可以确认：不只是模型正常思考，结构校验错误确实造成长答案重复生成；搜索失败与过多轮检索也增加等待。不能据此把所有主模型耗时称为“思考”：现有事件同时包含网络、隐藏推理和输出，尚无三者独立计时。各工具可以并发，工具时长之和不能当互斥阶段相加。

当前实现已正确使用 AgentScope 的单一主调用重试机制（主模型 max_retries=1、嵌套 SDK max_retries=0）、原生可并发只读工具批次，以及 `search_public_web(read_limit=1/2)` 的原文并发取得。不要再造重试循环或并发调度器。上述慢案例没有调用 `search_world`，因此不能把 ReMe 当作这些记录的主因。ReMe 索引必须在异步调用后按当前 SQL 权限和版本复查，不以加缓存为由取消检查。

## B站创意知识库：可增量实现，但抓到不等于学会

已有接法：`community_search.py` 调用可选 MediaCrawler 只读客户端，或公开 yt-dlp 搜索；`community_sources.py` 取得公开详情；现有来源读取、图片观察、有界视频抽帧保留原始证据。MediaCrawler 解决采集入口，不会自动生成可靠的步骤、原理、材料表或适配结论。

后续建议循序扩大：

1. 先围绕实际家庭资源选择少量领域：灯/纸/手机摄影，夹子/容器/绳收纳，普通物件的游戏、布置与声音玩法。检索词从资源性质、组合与目标生成，不只有“废物利用”。
2. 有界批量取得标题、作者、原链、时间、描述；按 BV/原链接去重，保留读取状态。正文、字幕、画面分别标深度；标题线索不能伪装完整教程。遇到需要登录使用明确临时会话，不导出账号 Cookie。
3. 对确实读到步骤的条目，沿已有知识 claim 保存玩法价值、物品角色、必需工具和连接、条件、步骤/时间点、迁移差异与未知，关联原 SourceRecord。资料只是候选证据，不是额定能力或用户成功记录。
4. 用已有 ReMe 的关键词 + 向量检索筛资源/目标相近案例，Agent 只读少数相关原文或关键帧后给方案。不要把所有视频全文和全部帧塞进每次上下文。
5. 先证明比即时搜索更容易取得实质做法、少重复下载、迁移更合适，再决定规模与调度工具。大规模跨用户公共语料要另行明确共享范围；不能把当前某用户的私有 Source/Knowledge 自动公开。第一版试验可在隔离的开发知识库完成，不强迫业务库立即升级。

本轮没有启动大规模爬取，没有另建生产知识数据库、另添收费服务或学习循环。

## 借鉴的一手方法及采用方式

- [Anthropic：Building effective agents](https://www.anthropic.com/research/building-effective-agents)：保持简单可组合，优先改善工具接口。对应本项目：沿主 Agent 修正资源查询和输出契约，避免额外评审 Agent。
- [Anthropic：Effective context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)：用高效用上下文与按需检索。对应本项目：优先已给出的资源索引，来源保存原文并按需读取，不重复注入工具历史。
- [AgentScope 官方源代码 ReActConfig](https://github.com/agentscope-ai/agentscope/blob/main/src/agentscope/agent/_config.py)：使用成熟的迭代和结构输出机制。当前安装的 2.0.11 源码 `_agent.py` 已有并发批次执行，不能照旧版示例再叠调度层。
- [MediaCrawler 官方仓库](https://github.com/NanmiCoder/MediaCrawler)：复用采集客户端，保持其与可信知识整理的职责分开。

后续真实测试结果与新独立审查须追加在此，不能用源码阅读替代效果证明。

## 丰富库存的第一轮真实开发测试

运行标签 `resource-first-skill`，新隔离数据库，18 件模拟拥有的物品；沿现有 API 创建用户与物品，由物间 Agent 自主搜索读取。报告保留在本地 `tmp/acceptance/2026-11-06_two-hour-round/creative-*-home-inventory-resource-first-skill-*/results.json`。本组三场、五次已完成或失败的用户轮共计 **24 次本进程 HTTP 尝试**；共享 ledger 包含其他并行任务，不能把共享总数算作本组三场。

| 场景 | 首答 / 跟进 | 实际来源及交付 | 仍存在的问题 |
| --- | --- | --- | --- |
| 理线 | 90.9 秒 / 99.2 秒；4+5 HTTP | 首答取得 Lifehacker 原分享；反馈夹不上、大接头穿不过后自行取得 Instructables 与 ManMadeDIY，给出纸箱剪 V/U 开口、胶带或书固定的替代；现有库存包含所有所需材料；同一 Task 有更新 | 首答仍没交代长尾夹铁把的打开/装回方式；跟进已避开这个问题。实际固定强度未观察，不作为本轮阻止交付的普通调整细节 |
| 室友十分钟游戏 | 104.6 秒 / 23.8 秒；6+2 HTTP | 自行取得触乐正文与 B站页面；纸笔现在确实存在，跟进给出点格棋的准备、轮次、额外回合和胜负规则，能开始 | 两轮均未调用 creative-use Skill；两轮 continuation=null，没有 Task，违反已有方案可接续约定。这里是明确入口未稳定加载既有领域规则的问题 |
| 给手绘杯拍照 | 首答 240.4 秒超时；7 HTTP | 自行取得两篇摄影原文；已生成完整方案但未通过提交 | 把白纸物品 ID 写错，3 次最终结构校验均返回通用“没有找到或无权访问”，模型重复保留错误 ID、重写长答案，最后超时；不是物品太少，不是单纯隐藏思考过长 |

结论：丰富库存确实改善了材料闭合，例如纸笔游戏不再缺笔、理线替代方案可以使用已知剪刀和纸箱。但库存增加不能修复标识符传输、领域 Skill 漏加载和错误反馈缺少字段定位。这些应由共同底座负责人按真实失败修正，再用新标签复测，不能靠继续加工具掩盖。

## 更有趣/实用的 B站案例开发验证

用户随后明确指出理线、纸笔棋的吸引力不足。本轮再加入 `fixtures/acceptance/2026-11-06_creative_bilibili_worthwhile.json`：在前述库存上补家用卷尺、乒乓球、纸杯、纸袋、小衣物与抽屉。所有拥有关系仍为模拟；没有给 Agent 预置 BV 号、步骤或案例知识。

### 三角杯阵定点入杯挑战：已交付并接续

- App 自主用 `community=bilibili` 搜索并读到[乒乓球杯子游戏开始啦](https://www.bilibili.com/video/BV1MdZpB4EYf/)，实际下载受限大小的视频并取得 8.75、16.25、23.75、31.25 秒的四张画面。复核可见三角杯阵、球、玩家位置及计分；不是只有标题。
- 首答 83.6 秒 / 4 HTTP，给出 10 个纸杯组成 4-3-2-1 三角阵、乒乓球、纸箱挡球、卷尺调整距离及双方得分玩法；可开始，Task 已保存。
- 跟进 67.6 秒 / 3 HTTP，针对“两人、不计时”给出轮流投球、先入杯过关、连续未进缩短距离的规则，并明确“这是建议的简化版，不是原作者做过的规则”。同一 Task 更新。
- 这证明有实际画面的生活玩法检索与适配可运行，不证明真实玩家已试玩或喜欢。首答的盲投、连击等扩展是模型提案，未在原视频观察到；第一轮不需要全部加入。

### 纸袋变抽屉分格：已取实质画面，首答交付失败保留

- App 自主读了 B站多条线索，最后取得[瑞幸收纳袋教程：改造纸袋](https://www.bilibili.com/video/BV1aR4y1t7pG/)，实际采样 13.75、21.25、28.75、36.25 秒四帧。复核可见折成浅托盘的纸袋、手工拆取提手及沿折痕往里折的画面。
- App 已生成纸袋改浅收纳格的方案，但把画面解释填成 `basis=document` 且没有原文行号，可选知识写入校验失败，引起重写；首答最终 240.4 秒超时 / 12 HTTP，没有向用户交付完整答案。不能把内部草稿或取得画面冒充已通过。
- 同轮还有一次 60 秒抽帧窗口被工具正确拒绝，改为不超过 30 秒后成功；未绕过工具边界。平台访问成功，无需为了这一失败再让用户扫码。
- 建议共同底座在字段层说明“原文/用户报告/视觉推断”的语义，继续保留真实校验；修复后复用已有来源续接，不重新大面积搜索。

以上两个报告标签为 `worthwhile-bilibili-first`；共享本轮 ledger 中，本组单独进程合计 19 次 HTTP（游戏 4+3，收纳 12）。图片和原报告留在本地评测目录，不提交视频或运行日志。

### 共同机制修复后的纸袋续接

`canonical-source-recovery` 从原失败的隔离数据库克隆，保留原失败证据。修复后的入口保持为 creative，成功来源指针允许来自失败轮，引用画面的解释保留为 provisional inference。

同一自然用户请求“继续用已找到资料、先不剪、试好大小”在 **50.2 秒 / 2 HTTP** 后完成。轨迹为预载 creative-use → 两次 `read_source` → 最终结构生成，没有重新搜索、没有重新下载。回答引用已留存的瑞幸纸袋抽帧，并区分画面中折出的盒形与建议的整袋试摆。它证明失败后的来源复用和任务交付修复起效，不证明用户已经完成整理。此前旧机制下的 `storage-recovery` 为 142.8 秒 / 6 HTTP，重新搜索了别的视频；两条记录都保留。

## 可本地复用的 17 条 B站资料包

本地私有交付目录为 `tmp/fixtures/2026-11-06_bilibili_inspiration/`，`bundle.json` 是机器可读入口，`index.csv` 便于浏览。包含 17 个不同视频、24 个来源记录、50 份公开原始资产，约 41.4 MB。新增采集沿现有公开只读搜索和资料读取工具进行：8 次有界搜索、12 个原页、2 个视频的有界抽帧，**没有调用付费模型**。5 个此前由物间 Agent 取得的实际抽帧来源直接复用，不重复收费。

领域覆盖互动游戏、摄影、收纳、丝巾/包的穿搭替代、毛巾造型和胶带插花。7 条有实际画面与逐帧人工复核的 provisional case 候选；10 条只有原页/简介线索，`claim_candidate=null`，没有由标题补教程。7 条有画面也不都等于完整教程：柔光箱只取得画线准备，卡纸盒只取得模板折装，未知前置条件仍保留。

两个较容易开始的额外方向：毛巾卷折成可拆回的小熊造型；透明胶带跨花瓶口形成五角星支架，让花枝有定位孔。后者在 3.75、11.25、18.75、26.25 秒的实际画面中可见贴胶、支架和插花，不只来自标题。

`scripts/import_inspiration_bundle.py` 默认只做 dry-run；明确 `--apply` 后先用 SQLite backup API 备份，再复用现有 SourceRecord、Asset 与 `foundation.save_claim` 导入。重新分配当前用户的来源/资产 ID、重写视频 manifest 指针、按实际存在的相关库存绑定 7 条 inference/item/case；没有匹配物品时只导来源，不创建物品。原文保持，writer 生成 import_origin，重复导入不新增记录，10 条线索不升级为教程。公开媒体、数据库与采集日志都在被忽略的 `tmp/` 下，不作为源码提交。

独立审查发现的“案例作者原页可能错配另一视频的抽帧”已补明确血缘校验与回归。7 项离线导入契约测试通过，另 3 项 eval resume 入口测试和 10 项请求预算测试通过。

实际媒体验证位于 `tmp/acceptance/2026-11-06_two-hour-round/bundle-local-import-real-media/`：隔离库导入 50 Assets、24 Sources、7 claims；禁用 HTTP 发送后，现有 `retained_video_frames` 成功重开 7 个来源的 27 张真实 PNG，并通过图像完整性检查。第二次导入计数和映射不变。现有 ReMe 在不设 API key 的 keyword_only 模式下，对“透明胶带 花瓶”“台灯”“纸袋”“毛巾”都命中本地知识/来源。CLI 的 SQLite 备份在同一隔离库实测 `integrity_check=ok`；实际用户库由负责人另行明确执行。
