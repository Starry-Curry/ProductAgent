# 型号操作指导证据边界修复

独立首轮失败与原始资料见 `2026-11-07_独立生活旅程真实模型验收.md`，错误首答未改写。本修复不为 Epson 或任一测试型号写入固定操作答案，不给运行 Agent 注入事后查得的正确手册。真实复测由原独立验收者以原题和隔离 SQLite 进行，复测结果另记；以下离线通过不代表型号操作或实物效果已通过。

## 先复现的机制失败

新增离线合成反例 `tests/test_guidance_evidence_boundary.py`。修复前的实际运行中，`interaction/1` 的 `checklist`、`idea` 展示均能将 `basis=document` 而无 `evidence` 的操作写入，原生 `grounded_turn_schema` 同样放行；邻接型号文本也随展示类型绕过型号检验。四项预期拒绝没有发生。原有 `guidance` 展示会拒绝无证据操作，说明不是缺少校验器，而是业务路径提前返回。

## 同一业务路径的修复

- 所有带 `entry.guidance` 的互动计划均复用原证据、原句/行号、PDF页码、型号与参数校验，展示 `kind` 不再控制是否校验。`basis=document` 必须有证据。普通清单继续沿用共同的实际反馈与进度路径，未变成教学状态机。
- 型号匹配复用现有 `learning.model_mentioned`，检查来源正文，允许排版差异和实际包含型号的多型号手册；不能靠URL、标题、关联item_id或较长邻接SKU证明适用。型号出现仍不代表章节理解或操作时序正确。
- `fetch_document`、`read_source` 和原PDF页图输出增加 `applicability`：向模型列出本轮已读物品的准确型号、市场及型号是否出现在正文中，并明确过程兼容性尚未被证明。不传fetch的item_id也可利用本轮read_item目标核验；这些信号不写第二份业务事实。
- 指导证据ID进入现有 `referenced_sources`，复用实际已读来源检查与引用呈现，不另建验证模型。通用初步建议仍可无手册；结构中的未核按键组合、松键时序不能通过改成general继续保留。
- `product-guidance` Skill要求具体控件与时序优先寻找适用市场官方手册及面板图，泛FAQ只能支持其实际适用的通用判断；缺少原文时先给有用的通用帮助，保留未核定部分。

本次没有新增Pydantic字段、数据库迁移、收费服务、grader Agent或逐句多模型审查；没有重启8000或操作主库。

## 后续真实结果与资料发现修复

独立 `041933` 同题复测用了166.4秒。原错误进/退纸按键消失，回答保留具体机身操作未核实，只给电脑驱动路径；这能证明没有继续肯定错用旧FAQ，却不能验收准确型号操作能力。其计划条目没有guidance，不能称为本次结构校验已检查了每一句操作。

随后自然接续“没有电脑、只有手机，请带我在打印机按一步”的 `042419` 在240.6秒后超时空答。模型未找到适用型号手册，最终结构尝试还生成了用户未报告的“打出来了、网格有断线”反馈；非法状态被拒绝，SQL任务和经历均未改变。用户任务仍失败，维持NOT_ACCEPTED；防住一次伪造写入不等于已解题。

只读根因材料在该目录 `discovery-audit.json` 与 `discovery-readonly/`。冻结的1748字节在线手册wrapper有空正文、noscript目录与URL指定静态页面，但fetch因空正文422，把已解析导航一并丢掉。准确型号支持页正文由JS加载，原工具未显示其声明的脚本入口。另已取得PDF全文后，查询 `nozzle check pattern buttons` 整短语没有命中，工具只返回开头目录，没有第134页实际相关章节的候选提示。

第二轮修改共同的 `source_content.py` 与 `knowledge.py`：

- 空正文但有实际导航时保留原响应与链接，明确 `navigation_only_not_document_content`、`content_available=false`，继续读取目标才能取得正文证据。无正文也无导航仍拒绝。
- BeautifulSoup提取页面明确声明的frame/iframe/object/embed与公开script资源；旧frameset中URL参数引用的同源HTML/PDF只列为未执行、未读取的候选。全部目标仍需原有公开网络校验。没有执行JavaScript、浏览器会话、自动调用API或新增站点分支。
- 支持JavaScript MIME原文读取，标为代码而非脚本运行结果；只从明确返回的声明寻找后续入口。支持页中较晚的script链接也随 `declared_resources` 可见，不被前12条导航截断藏掉。
- PDF查询整句未命中时以普通词项与中文相邻字检索现有页，返回候选页、实际原文及原始行号，保留 `query_matched=false` 和词项匹配边界。冻结原错PDF的相同查询现可选到第134页，但其L3256型号不适用信号仍为false；发现章节不会把错误机型资料变成适用说明书。
- 搜索归一化保留上游实际存在的title/snippet/description；未返回的字段保持缺失。现有trace没有捕获Responses原始响应，无法据此认定本次无标题全部来自归一化丢失，也没有从模型生成正文补造标题或摘要。

实际冻结wrapper修前/修后工具证据另存忽略目录 `tmp/document-discovery-before.json`、`tmp/document-discovery-after.json`。新增10项离线发现回归通过，覆盖wrapper/资源导航、拒绝危险与未声明参数、原文代码读取、英文词项与中文页检索、真实行号以及搜索元数据不编造。公开源22项、搜索链9项、来源相关44项通过。来源页图测试保留真实PNG、原生模型直传与撤权断言，并增加新applicability字段核验。原指导边界10项和嵌套StepEvidence结构1项也通过。

该轮运行时已交原独立验收者冻结后再复测；未预置正确手册、增大timeout、启动收费grader、操作主库或重启8000。真实自主资料发现与用户任务结果仍以新的独立记录为准。

## 搜索推荐标签与原文证据分开

独立创意验收 `043850/search-provider-trace.jsonl` 后续实际捕获了Responses响应：completed search call的sources只有URL，annotations为空；普通output_text则以“标签换行URL”的形式推荐了其中若干结果。旧归一化丢掉这些发现标签和次序，`read_limit=1`便按visited source次序读取了不同型号YouTube或手机clock抖音。这次有原始响应支持，能够确认缺口；不能把此前缺少该trace的猜测当作已证实。

`search_web`现保留 `provider_discovery_label`、`provider_discovery_rank`，并标 `provider_discovery_kind=provider_output_not_page`。只有URL在completed search call实际sources集合中完整出现，才可接收这些普通文本标签与推荐次序；无法匹配的生成URL不加入搜索结果。实际来源已有的title/snippet优先，生成标签不覆盖它们。原citation annotations接口保留，普通output_text不变成页面原文。

自动读取先取供应商推荐的已观测来源，其余继续保持原来源次序。完整 `observed_source_urls` 保留供应商原次序与URL集合，compact results超过15条明确标记截断；实际query和queries也保留。推荐排序既不保证当前型号适用，也不授予权限或证明页面中的功能；仍须fetch/read原文。指令样式的标签仅是带明确来源类别的数据，不能冒充页面标题、正文或规则。

冻结的公开真实响应形状保留在 `tests/fixtures/bailian_url_only_search_response.json`，仅供离线回归，不注入产品Agent。新增8项测试先复现失败再通过，覆盖真实无title形状、无标签、未知URL、已有title优先、指令样式标签、URL前缀攻击、完整来源集合以及实际工具 `read_limit=1` 读取推荐来源。原搜索9项与资料发现10项也通过。Skill仅补一处：具体菜单链与内置功能同样需要本型号证据，general用于观察和寻找方向，不能包装未核型号动作；没有加菜单词正则或额外semantic grader。

该版本再次冻结交独立打印和电视原题复测；新标签保留或读到了官方页面仍不能直接验收用户任务通过。

## 正式复测后的剩余问题与元数据深度

正式 `printer-045256` 的工具已经将准确国内型号手册下载页排在首条，保留了L3256标题以及明确“立即下载”链接。主Agent没有跟随已取得的链接，反而转向旧全球型号wrapper与静态页面，多次结构修复后仍失败。因此当前失败不能继续归因于导航拿不到，也不需要为该站点再写专用解析；存在已得证据选择与旧相近资料锚定的模型能力问题。

正式 `television-045308` 得到了官网“投屏指南”页面，但其33,175字节原始HTML在现有去除script/style/noscript/nav/footer/header/title后，DOM文字严格为空。body内是空div、无src的img和Nuxt脚本，保存内容仅为元数据header及description。此前工具把这段简介标为document_text、content_available=true，构成可确定的通用读取深度错误，而非按字数猜测的“短正文”。

最后一批有界修复：当metadata存在、DOM和已抽取supportJSON正文为空、且没有明确的JSON-LD articleBody、acceptedAnswer或HowTo步骤时，解析器加仅元数据marker；新解析及能够确证空body的旧保存header都返回 `public_page_metadata_only_not_document_body`、`content_available=false`、`evidence_kind=retrieved_page_metadata`。标题/简介仍可查看，提示没有正文；最终引用也注明尚未读取正文。短FAQ与实际结构化文章保持原来的正文语义，未引入长度阈值或品牌分支。

学习复用已有来源类型归类：仅元数据的document建议变为item范围inference、provisional，清除原文行/型号确定性，并保存实际reading_scope，不能获得source_backed教程身份。操作指导的文档证据直接拒绝仅元数据来源。Skill仅整理读取顺序：已得到准确型号下载页就先沿明确链接取得正文；目录、元数据和脚本壳不算手册，新适用原文优先于旧相近资料，缺信息先观察，不预写用户操作或结果。

只读原始哈希、DOM清洗证明、新旧source输出保留在 `tmp/metadata-reading-depth-proof.json`，未修改验收SQL。新增6项离线回归先失败后通过，涵盖真空DOM、短正文、结构化正文、旧header、fetch/缓存/read_source/引用一致，以及知识与指导身份边界；受影响公开源22项、学习12项、引用9项、指导10项、观察依据4项、AS2旅程20项、资料发现16项均通过。没有增加模型/API调用，没有修改连续对话的source_index。本批冻结后只进行用户自然纠正的有界恢复，仍由独立验收保留实际结果；整体NOT_ACCEPTED不因这些工程回归转绿而改变。
