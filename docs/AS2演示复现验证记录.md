从 GitHub 通过 SSH 克隆 `feat/as2-adaptive-lessons` 到新的独立目录，未复制原数据库、`.env`、Python 虚拟环境或 node_modules。首次资产提交为 `96d68e3`；镜像安装修复后在 `4550be8` 完成全新启动，通用计划触发修复 `37eddea` 另行复测。

本机实际为 Python 3.12.2、Node 24.20.0、npm 12.2.1、uv 0.13.7。依赖下载缓存有复用，Python/Node 环境重新创建；实际 `sys.prefix` 和 `wujian.__file__` 都指向新克隆目录。应用及资产没有引用旧 `D:\Project\Tianmao` 私有媒体。测试自己的 API Key 只通过进程环境传入，没有写入下载副本或提交 Git。

默认 PyPI 和 npm 下载出现 TLS 连接失败，保留为首次安装失败。使用以下已发布参数安装成功，未关闭证书校验或改动两个锁文件：

```powershell
.\demo.ps1 -PythonIndex https://mirrors.aliyun.com/pypi/simple -NpmRegistry https://registry.npmmirror.com -Port 8024
```

Python 运行时依赖由 uv.lock 导出并校验 SHA256；npm ci 校验 package-lock integrity。项目本身从当前克隆源码构建安装。不要把此处的包源连接故障误诊为缺少演示图片或模型。

## 非脚本输入和其他物品

真实 Qwen 调用检查了 AS2 的“A 键是电源键吗”，回答区分了自动熨压键与左侧电源键，进度仍停在 power，没有凭问题自动完成操作。

另建罗技 K120 有线 USB 键盘的**模拟开发情境**，要求逐步排查无法输入。首答曾仅给解释、没有保存任务；该失败保留，并补强了明确 guidance 请求的计划生成要求。修复后的两轮结果：

| 用户报告 | 数据状态 |
|---|---|
| 要求一步一步排查键盘无法输入 | 创建通用 guidance 任务，当前“检查USB连接”为 pending；没有套 AS2 lesson 或图示 |
| 报告重新插紧仍无输入，另一只鼠标正常 | 接续同一个任务；原检查记录 unchanged，新增“换一个USB口”为 pending；任务仍 in_progress，没有误判问题解决 |

这证明其他物品能进入通用回答与计划接续链路，不证明答案均已经过型号资料校核。该回答仍有质量问题：模型把另一只鼠标正常工作推断为键盘所在端口供电正常，证据不足；对键盘端线缆是否可拆也应更谨慎。它们是待优化的通用诊断问题，不能用状态链路通过来掩盖。

完整私人 Run/数据库和安装失败日志只保留在本地评测目录，未提交 Git。本记录只发布复现条件、结果和已知问题；没有实际连接、拔插键盘或操作烫印机。

## 尚未涵盖

没有完成比赛 Intel 机器 NPU 验收、真实压烫、通用物品 3D 几何准确率或复杂遮挡追踪验收。MiniLM 是可选下载项，核心包不包含约 480 MB 权重。默认云问答与 AS2 展示不依赖该权重；需要本地 NPU 模式时按复现指南另行准备和检查实际执行设备。
