# 工作台通用 smoke 与控制台专项边界修复

## 首失败与判断

只读取 `read_volume.state.muted` 的合法小游戏不需要展示数值音量；只读取降噪模式的作品也不必展示三处电量。原检查器却从“调用过某项读取”推导出全部字段必须出现在页面，并要求错误逐字显示 `check-device-offline`。这把完整耳机控制台的业务要求误用成所有工作台的发布门槛。

新增真实 Chrome 离线反例首先复现：muted-only 页面没有运行错误、非法参数、网络请求或自动写，仍因 `volume_rendered=false` 与 `failure_visible=false` 被拒绝。正常降级为“静音未知”也会被后一个字面要求误伤。

## 最小改动

生产只改 `workbench_check.py`。通用 `smoke_assertions` 保留可见内容、运行错误/未处理 Promise、出站阻断、操作白名单、严格参数及 load 阶段自动写请求的门控；unknown/failure 仍用模拟桥执行并保留文本与请求观测。通用 passed 不再声称特定电量、音量或业务错误文案渲染正确。

完整控制台的数值电量、数值音量、未知值清除、未知单位和失败显示要求移入独立 `tests/browser/workbench_console_acceptance.py`，明确属于全控制台专项。正确合成控制台通过；“未知%”合成反例虽可通过通用 smoke，仍被控制台专项拒绝。脚本可用 `--document` 只读检查已导出的控制台 HTML；未手改任何 Agent 生成作品或原控制台证据。

专项使用通用回执的有界观测：前 20 条请求、交互后 1,200 字及 unknown/failure 各 1,000 字。复杂长页面可能需要另做聚焦 UI 验收，不能把快照截断误说成作品确定失败。

## 独立审查补充与边界

独立 reviewer 复现了预存的 900ms 定时写误归为 click 阶段问题。经负责人授权，加入独立 **1,500ms load-only 观察窗口**，回执输出 `load_observation_ms`，在该窗口内不点击控件，900ms 反例现在被拒绝。它不分析 AST，不持续监控任意未来 timer；不能宣称所有延迟自动请求均已检测。生产真正设备写仍由外层真实用户点击确认，这项权威边界未改，检查器处理的只是模拟请求。

网络验证区分“CSP 在请求前拒绝”与“已出站”：最终 Chrome 反例使用实际 `document_html` 的 `connect-src 'none'`，确认 console 出现该策略拒绝、页面进入 catch 且 routed requests 为 0。不能仅因 `blocked_requests` 为空推断网络已经放行。拦截回调改为普通函数显式记录后 abort，公共网络策略、iframe 隔离、Cookie/应用身份边界均未扩大。

没有改 CLIENT、外层 UI、设备权限、业务写入、源码 hash 与版本检查。过去的检查回执保留其原版本和原条件意义，本修改没有自动重新验收所有既有作品；通用绿灯也不替代真实控制台专项或小游戏目标验收。

## 验证

- `workbench_generic_smoke.py`：真实 Chrome 八例全部符合预期，muted-only 与 mode-only 通过；非法参数、立即/900ms 自动写、JS 错误、未处理桥拒绝失败；CSP 网络拒绝被实际观察。
- `workbench_console_acceptance.py`：正确控制台专项通过、错误未知单位专项失败，两例均符合预期。
- `workbench_argument_contract.py`：五例符合预期，非法参数仍不能通过通用门控。
- `workbench_sdk_receipts.py`：七种生产 SDK 结果合同通过。
- 工作台、对抗与已有独立边界单测合跑 **27 项通过**；`git diff --check` 无错误。

冻结后，另一名只读 reviewer 独立复跑 generic 八例，8/8 符合预期，并核对 1,500ms 时间窗、源码 hash/版本、CSP 与外层真实确认边界；本轮没有剩余新 P1/P2 发现。

全部为离线合成样本、真实 Chrome 和模拟桥；没有调用模型、真实设备或主库，也没有编辑 Agent 作品。生产文件已冻结供负责人统一回归与后续真实草稿修复，不将这些软件测试称为实际游戏体验或设备效果通过。
