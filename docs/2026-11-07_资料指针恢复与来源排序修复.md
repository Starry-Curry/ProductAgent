# 资料指针恢复与来源排序修复

## 首失败与根因

独立真实旅程 `printer-045256` 恢复前发现：`search_public_web(read_limit=1)` 已实际下载并在 SQL 留存准确 CN 指南入口，工具 trace 也已保存 `evidence.original_reads` 中的真实 `source_id`，但对话恢复只识别显式 `fetch_document/read_source/view_*` 等工具的顶层来源 ID，因此漏掉搜索内实际取得的原文。显式取得的另一份全球版页面反而能恢复。该真实旅程先前结果不因本修复追记为通过。

离线回归在修改前重现三个失败断言：搜索内实际读取的来源恢复为空；同一次搜索的十个真实来源完全未进入八条指针窗口；拥有 102 条来源时 `list_sources` 返回最早插入的旧记录，新来源被无排序的 `limit(60)` 挤出。

## 局部修改

- `_source_index` 仅新增识别已注册 `search_public_web` 工具的 `state=success` 结果中、结构化 `original_reads` 里 `read_state=retrieved` 的来源 ID。每个 ID 均重新通过 `readable_source` 检查当前权限和实际 SQL 存在性。
- 只恢复来源指针。标题、URL 和来源类型重新取自 SQL；不回放正文、搜索摘要、trace 标题/URL或任意字符串。provider labels、未读/不可读结果、失败工具、未知工具、无 ID 线索、已撤权来源均不进入指针。
- 原有同一用户、同一对话、reset 时间边界、当前消息时间上界、最近八次有效 run 和合计最多八条来源指针的范围保持不变。后续生成失败的 run 中，已成功实际读取的来源仍可保留指针。
- `list_sources` 仍先按当前用户和可选 item 过滤，只增加 `fetched_at DESC, id DESC` 稳定排序，再取 60 条；没有新增检索层或扩大可读对象。

本轮只改 `conversation_context.py`、`agent_runtime.py` 中 `list_sources` 的排序行以及相应离线测试。未修改主库、调用模型/设备或重启服务；未取消正在进行的独立恢复。

## 验证与最窄保证

新增测试既使用合成结构化 trace，也调用真实 `search_public_web` 工具，在 mock provider/download、真实临时 SQL 留存的条件下取得其真实 `ToolChunk.metadata`，模拟后续 run 失败，再验证恢复出的来源指针。还检查错误/未读/不存在/私人或撤权来源不会恢复、reset/未来时间/其他用户和其他对话被排除，以及 102 条来源库中的最新来源、同时间稳定排序和 item 过滤。

修复后 `test_conversation_context`、`test_search_read_chain`、`test_real_eval_resume_context` 合跑 **31 项通过**；`git diff --check` 无错误。

保证仅为：符合上述条件的已读取 SQL 来源不会再因“读取发生在搜索工具内部”而被恢复器遗漏；列表展示最新的 60 条当前用户来源。它不会把旧指针自动加入本轮 `evidence_sources`，Agent 仍需实际重读才能作为当前回答证据；也不保证模型一定选择正确来源、理解操作时序或完成现实打印机任务。当前已开始的独立模型恢复不计入本次修复的验证结果。

## 后续断点：默认重开原文保留导航

独立 `051214` 已证明来源指针能够恢复，但模型对准确 CN 指南入口调用默认 `read_source(query=...)` 时只拿到正文和“立即下载”文字，没有原先 `fetch_document` 已取得的 href，随后又搜索全球旧手册。这是读取机制不一致：只有显式 `link_query/link_offset` 才返回导航。该轮首失败保留，新修复不追记给已经启动的验收。

本次仅调整 `agent_runtime.read_source`，复用已有 `source_navigation`：重开 `public_web` HTML 默认附上留存原始响应解析出的首 12 条导航及分页信息；显式查询和 offset 继续按原方式过滤分页。不拼 URL，不自动读取链接目标，也不新增网络或模型调用。默认导航不覆盖原文的 `evidence_kind/content_level`。当前来源权限仍先检查，原始 Asset 的归属由同一导航 helper 复核；原始文件缺失、不可读或归属不符时，保留实际 SQL 正文并返回明确 `navigation_error/reading_note`，未知导航总数用 null，不能伪称链接不存在，也不再读取该不可用原件的图片线索。curated 和无原件来源不会因默认导航使可用正文丢失；显式请求失败仍可返回原错误。

新增四项离线测试先红，分别复现默认重开缺 links、默认分页缺 links、导航缺失无说明及原件归属变化后仍尝试读取图片线索。修复后验证真实临时 SQL 中的 `fetch含href → 默认reopen保留同href → failed-run恢复指针 → 当前read仍含同href`，同时覆盖首 12 条、显式筛选/下一页、curated 与 public 无 asset、文件缺失、原件归属和来源权限撤销。没有使用 Epson 型号答案或手工拼接目标 URL。

`test_source_navigation`、`test_document_discovery`、`test_source_page_observation`、`test_native_tool_contract`、`test_search_read_chain` 定向合跑 **39 项通过**；`git diff --check` 无错误。保证仅为默认 HTML 重开与既有 fetch 导航机制一致，仍不等于模型已自行取得最终适用手册或完成真实任务。
