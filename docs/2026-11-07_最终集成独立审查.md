## P2：同一请求的待确认工具重试失败（已修复）

首次复现：在隔离测试中，对同一个用户消息连续两次调用 `butler_actions.propose(..., "reminder", same_payload, ...)`。第二次进入 `foundation.save_task`，被“专用确认/取消或工作台操作维护”的正确保护以 409 拒绝。首次签名卡仍能确认。赠礼走同一分支，存在相同问题。

影响：主 Agent 在同轮重试相同工具调用时拿不到成功回执；没有越权执行、重复发送或业务记录丢失。

修复：专用 `propose` 对同一消息、同一类型、同一规范化 payload 返回原签名预览，不增加版本、不执行动作。相同消息提交不同 payload 仍以 409 明确拒绝，要求取消旧草稿后用新请求说明变更；不静默改写用户待确认的卡片。通用 `foundation.save_task` 的专用操作保护保持原样。

证据：新增回归先复现第二次调用失败，修复后三项回归通过：提醒同请求幂等、赠礼同请求幂等、不同 payload 不改原卡。首次卡片修复后仍可通过实际确认接口正常确认。

## P2：浏览器模拟桥接收真实桥会拒绝的参数（已修复）

首次复现：生成按钮执行 `window.wujian.request('set_noise_mode', {mode:'transparent'})`，捕获失败并展示错误。修复前 `run_checks` 返回 `passed: true`，模拟状态显示 `transparent`；真实前端桥和后端只接受 `off/light/balanced`，会拒绝此按钮。

影响：检查器可能允许发布实际不能工作的按钮；真实设备权限和参数边界没有被绕过。

修复：检查器按实际四项桥合同校验参数。读取仅接受空对象；降噪仅接受单个合法字符串 `mode`；音量仅接受单个 0–100 数字 `level`，拒绝布尔、非有限值、额外字段、数组和 null。模拟桥不再给非法请求返回成功，检查结果保留 `invalid_arguments` 并使整体失败，附带修复提示。处理非法 null 参数也不会使检查器自身崩溃。

证据：生产检查器的独立浏览器回归中，非法降噪与 null 音量均失败并保留非法参数回执；合法轻度降噪与 35.5 音量通过。另根据实际 UI 复核的明确问题，加上 `unknown/未知/—/--` 紧接百分号的失败断言；专门的电量读取样本显示“未知%”时检查失败。未对全页面 0% 做模式匹配，以免误伤独立滑块目标值。仅使用模拟桥，没有真实设备变化。

## 边界核对

- 工作台复用 SQL `TaskRecord` 与私有 `Asset`；通用任务不能伪造工作台 schema、检查回执或覆盖专用源码。
- 编辑源码撤销发布和旧检查；检查绑定实际源码 hash；浏览器检查后重新核对任务版本和当前物品权限。
- 工作台代码在 opaque-origin sandbox iframe 内执行；真实写入由外层确认按钮的真实用户点击触发。读取失败、写入未回读确认不会作为 SDK 成功结果。`write_verified: 1` 也被拒绝。
- 赠礼后原工作台既不授予接收者私有源码，也不保留赠送者设备控制权。礼物分身不隐式携带原主人的私聊、私人成长或未选中的故事。
- 家庭回忆与物品分享分开；撤回共享、家庭成员变化、物品移出家庭仍重新检查读取范围。收到故事保留作者，接收者控制后续 AI 许可。
- 个人理解原话引用只容忍同类引号和连续空白差异，返回实际原文连续片段；不以词间空白删除来匹配。学习与最终任务/故事显示维持同一事务。

此前已知的“合法 memory 加非法 source 引用导致整轮回滚”P2未升级为 P1，也未为容错放松来源引用原子性。耳机 off 一手协议修复未改动。
