# 编者灵感参考库交付与检索核对

本轮独立审查后，小林 SQL 中保留 **102 条活跃编者候选应用、2 条撤回历史档案**，不是 102 份已观看教程或 102 次成功试用。覆盖 12 类场景：摄影 17、收纳 13、办公 12、厨房 10、音乐 10、出门露营 8、灯光 7、游戏 7、电视 6、阅读 6、清洁 4、园艺 2。没有以更换标题生成同一类 100 条 URL。

41 条活跃应用从公开项目/官方文档的机制迁移，61 条只借用 B 站真实标题与简介的方向。活跃条目引用 85 条已经存在的原始 SQL 来源（29 条官方正文、56 条 B 站元数据），连同撤回档案共保留 86 条来源。文档包括 WLED 分段/预设/音频响应、Hyperion、Moonlight、Home Assistant、AutoEq、Grocy、Mealie、scrcpy、KDE Connect、Deskreen、OBS、KOReader、Calibre、Anki、Syncthing、Immich、OpenTracks、digiKam、Inkscape、Mixxx 等维护者原文。未让百炼生成种子库，采集/编写/本轮工具链探测均无模型 RPC。

所有应用都有独立的场景、物品角色、机制、必要资源、可开始的第一步、观察点、未知、来源支持范围和 `evidence_level`。玩法包括客厅串流、临时家庭看板、灯带分区、清扫时机、冰箱优先食用区、耳机预听、手机俯拍、纸上游戏、标签归位、露营桌面和定格动画。部分涉及软件/附件，只有条件真实具备时才能迁移；不声称小林已经拥有全部条件。

## SQL 与权限

- 公开、可审查的清单：`fixtures/inspiration/catalog.json`；说明见同目录 README。
- 导入器：`scripts/import_creative_catalog.py`，默认 dry-run，应用前 SQLite 在线备份。
- 每条编者内容写为 `SourceRecord(origin="curated_reference")`；不建立第二事实库，不创建物品、KnowledgeClaim、经历或私人记忆。
- 原始 `public_web` 记录不修改。逐一验证原始来源所有者、ID、URL、标题和正文 SHA256；B 站元数据不能升级成原教程正文/观看记录。
- 同一个 key 稳定幂等。初稿第二次实际应用为 104 reused、0 new；独立审查撤回两条后再次应用为 102 reused、0 new、already_retired 2，未重新激活旧行。不同内容不能覆盖既有 key，必须明确审查新版本。
- 第一份应用前备份：`var/backups/before-creative-catalog-20261106T192834326469Z.sqlite3`。原始公开响应及应用回执留在 `var/`、`tmp/`，不提交媒体、私人数据库或运行日志。
- `source_excerpt` 对编者条目返回单独的 `content_level` 与 `evidence_scope`，正文首行也标明非原作者步骤、非用户经历、非实物成功。该标识先于 URL 类型判断，即使 URL 指向 B 站也不会标成视频观察。
- 主 Agent 沿用 `search_world` / `read_source`；已有 ReMe `authorized_documents` 读取获准 SQL，102 条活跃正文均能放入其既有 1200 字检索摘录，不需另建索引事实 writer。

## 独立审查与撤回

独立审查通读初稿 104 条，指出两处实质问题：`fridge-visible-leftovers` 与 `fridge-use-first` 同为可见分区加日期优先处理，机制重复；`vacuum-find-small-part` 的第一步实际是用灯寻物，吸尘器可选且原始评测支持太弱。接受审查意见，撤回这两条，保留 102 条，不添加弱来源凑数量。

`retired_entries` 记录撤回原因及旧正文 SHA256。导入前备份，再把这两条自己的编者行 origin 改为 `curated_reference_retired`；旧正文和所有原始 `public_web` 资料均不修改。旧引用仍可回查，但 `read_source` 明确已撤回、不得用于新推荐；自动引用标“已撤回的整理灵感，仅供历史回查”。ReMe 的授权 SQL 投影过滤退役行，检索现有实例也会删除旧投影。新增离线实测先索引、后撤回、再检索的完整生命周期，证明不是只改统计。

回执分别为 `tmp/final-round/catalog-retirement-dry-run.json`、`catalog-retirement-apply.json`、`catalog-retirement-idempotent.json`。运行中的服务需在 root 最终统一重启后加载新增退役过滤；不把尚未重启的旧进程描述为已经应用新代码。

## 一轮真实主模型开发探测

使用现有授权百炼主模型，在隔离临时 app 中注册模拟账号，虚构其拥有实际国内型号 **华为 FreeBuds 4E**。仅复制以上 86 条公开来源并按同一导入器导入 104 条编者参考，没有复制生产私聊、经历、私人媒体，也没有连接或改变实物。ReMe 使用既有 keyword-only 模式，未调用 embedding 服务。模型本身没有参与构造库。

自然请求为：耳机已连电脑，想和朋友玩不用盯屏幕的声音小游戏，不改耳机/电脑设置、不重新上 B 站找视频、不买一堆东西，先给一个小试。

实际结果：54.88 秒、4 次模型 HTTP 请求。模型读取 creative-use 并检索库，从编者的“生活声音猜谜”条目迁移到耳机，提出录一小段无私人谈话的生活声音、低负担试听并轮流猜谜；未重新联网搜视频、未调用设备写入工具。候选保存在同一 TaskRecord（interaction/1、idea、ready），两条步骤均 pending。学习条目为 item 范围 inference，未写成实物成功。

首次 `GenerateStructuredOutput` 引用了尚未 `read_source` 的来源，被现有证据门槛拒绝。模型随后真实读回条目，再次结构化输出成功。保留这次内部失败与修复，不能称为无修复首答通过。原始结果：`tmp/final-round/catalog-real-agent/033323/results.json`。这是开发样本，不是独立验收。

该轮暴露了真实的呈现问题：自动引用把编者“声音猜谜”标题直接链接到原始 B 站音箱评测，可能让人误以为原视频教授该游戏。现已在 `turns.py` 的来源引用分支修复为“整理的灵感《…》（待试；原始线索：[真实原页标题](URL)，原页不等于本玩法教程）”，并再次检查原始来源权限；不是借编者字段授予跨账号读取权。该呈现修复经离线回归验证，没有把旧真实回答改写成已重新跑过的模型结果。
