AS2 连续教学修复与审阅说明

2026-11-06 · feat/as2-adaptive-lessons。保留原版展示；新修复独立运行和审阅，不合入 develop/main，不发 PR。

AS2 是经过手册与实拍校核的示范物品。软件可以记录用户报告、展示指引和跟随可见部位；目前没有机器遥测，不能认定按键实际按下、温度已到或压烫成功。所有测试完成反馈都是模拟输入。

这次实际修复了什么

用户那句“衣服和塑料的片片，具体参数我不是很清楚”的原始运行记录显示：模型最初已经解释未知材料，却提交了缺少依据的材料状态建议。旧结构把回答与状态字段一起反复校验，最终模型为了满足“保留原话”的要求，把回答改成用户原话。现在模型只提交回答和小型意图，任务身份、版本、当前步骤与本轮原话由服务器绑定；非法状态建议单独拒绝，保留有用回答。原样复读有明确回退校核，错误细节记录到 run 事件。

3D 变差是另一处问题：从普通会话提交的 continuation 可以覆盖另一教学任务的 plan，使 lesson 定义丢失、缓存失效，随后触发 Qwen 重生简图。原始几何文件没有被删除。现在跨会话不能整表覆盖已校核教学，图解缓存损坏会从原审核几何修复；默认展示完整机器，可以主动切换细节。恢复分支为 fix/as2-reviewed-demo-restore。

不是固定 12 轮，也不要求照模板输入

AS2 的 12 个基础动作来自审核教程，作为可追溯的主流程；不是所有产品固定 12 步。任意自然语言问题继续进入同一个 AgentScope 主 Agent。未知材料可以分轮记录，不强迫背出三项参数；已知耗材类别可使用手册推荐预置，明确区分手册推荐值与用户实际报告值。

主 Agent 可以用 adapt 插入一个识别、观察或核对步骤；处于补充步骤时再调整它，不反复增加同类步骤。核对完成后回到原主步骤，旧完成记录保留。实际复测中基础 12 步变为 13 步；未确认材料时仍只完成开机一步。不会凭模型猜测跳过主流程的操作确认。

非预置包装参数按用户报告保存，例如 140℃ / 20秒 / 30kg；数值与原话中的字段、单位绑定，不套 145℃ 预置。当前步骤改为核对屏幕，箭头与审核 3D 同时指向显示屏。条件尚不完整时保留模型的解释；条件齐备后的操作交接由控制器输出当前核对步骤，避免文字另起一个没有记入计划的动作。用户报告包装参数不代表材料适用性已独立确认，也不代表机器屏幕已经设置正确。

临时问其他物品时保留当前教学；另一物品的“好了”不能推进 AS2。暂停、负反馈、没找到、疑问、视频定位都不代表完成。所有确认使用同一个任务、版本和幂等回执。

数据放在哪里

恢复版展示：D:\Project\Tianmao\ProductAgent\tmp\as2-showcase\wujian.sqlite3。新版开发复测与展示使用单独数据目录，运行时以各自 runtime.json 中的 data_dir 为准，绝不通过删除旧库回到第一步。SQLite 是本地文件，可以用 DB Browser for SQLite、DBeaver 等按文件打开；不是一个已经开放的远程数据库端口。

可以审阅 users、items、conversations、messages、runs、tasks、sources、assets 及认识/记忆等业务表。任务 plan 保存当前步骤、材料输入、原话证据、调整历史、图示缓存；Run 保留真实模型调用/错误事件。文件引用的照片/PDF/视频在相邻 assets 目录。ReMe 只作可重建检索投影，权限与事实仍由 SQL 库裁定。不要把私人库、密钥和未授权实拍提交 Git；用户明确授权发布的 AS2 演示资源见 demo/as2。

NPU 与本地小模型：当前事实及部署路线

现网页 ORB/RANSAC、LK 是 CPU 传统视觉；ViTTrack 是 OpenCV Zoo 的小神经网络（714,726 字节，约 0.68MiB），但当前 ONNX Runtime Web 使用 WASM，仍是 CPU。Three.js 使用 GPU 绘图不算 AI 推理。硬件换成 NPU 不会自动使相同模型识别更准。

新增 scripts/probe_vittrack_openvino.py 直接读取现有 ONNX，静态 template [1,3,128,128]、search [1,3,256,256]，在明确指定的 OpenVINO 设备上推理，检查 EXECUTION_DEVICES，不自动回退 CPU。本机实际 GPU.0 为 RTX 4060；AS2 实拍控制面板测试共 116 次，推理中位数约 2.61ms，但 7.67 秒处跟丢。可视检查也看到了框从按键区漂到显示区，因此它不是连续 18 秒成功跟踪，更不是有独立真值的精度评测。此脚本是部署实验，还未改成网页的 NPU 追踪后端。

本机没有 Intel NPU；NPU 试验明确返回 device_unavailable、0 次推理。不能把 GPU 结果或任务管理器截图当作比赛电脑的 NPU 验收。

建议比赛先用已有 MiniLM 本地语义检索路径满足真实 NPU 使用：模型在 NPU 编码问题与资料 → 排序选出的内容进入 Qwen 回答上下文，实际影响最终 AI 输出。该路径已有固定 [1,128] 输入、真实推理回执与严格设备校验，比临时把整个相机链路搬到 NPU 风险小。视觉再验证“云端定位＋本地模型跟踪整个控制面板＋平面映射到小按键＋丢失重找”，不能仅追一个十几像素的小按钮并长期沿用旧框。

uv sync --extra intel
.venv\Scripts\python.exe scripts/local_ai.py download
.venv\Scripts\python.exe scripts/local_ai.py probe --device NPU --require-accelerator --seconds 30 --output tmp/npu-proof.json

$env:WUJIAN_LOCAL_EMBEDDING_DIR=(Resolve-Path var/models/multilingual-minilm).Path
$env:WUJIAN_LOCAL_AI_DEVICE='NPU'
$env:WUJIAN_LOCAL_AI_REQUIRED='true'
.venv\Scripts\python.exe -m wujian serve --port 8020

上述命令应在比赛 Intel 机器运行，并检查任务管理器 NPU 图与 GET /api/local-ai、Run 的 local_ai_context 回执。设备缺失或编译失败必须报告，不能悄悄切 CPU。ViTTrack 也可在同一机器用脚本 --device NPU --video 实拍.mp4 --box x1 y1 x2 y2 --output tmp/vittrack-npu.json 验证；框使用首帧 405×720 坐标，不能拿别的分辨率直接复用。

验证与仍存在的边界

112 项离线测试通过，覆盖复读修复、非法状态不毁回答、补充步骤插入/修订/返回、未知材料、非预置参数、单位绑定、其他物品不推进、跨会话覆盖、审核模型恢复、权限和幂等。前端生产构建通过；重新导出 OpenAPI 和前端类型，公共契约无变化。浏览器验证第一步仍未完成、审核模型未触发重生成、未知耗材正常回复，未见页面脚本错误。真实 Qwen 复测保留首答及后续复测，耗时约 7–20 秒的材料解释仍存在等待，不应承诺实时。

原版完整 MP4 为约 1分58秒的连续软件交互录像，包含文字、实拍箭头、原始说明书页、3D、实拍视频自动定位和 12 步完成。全过程明确标为模拟用户完成反馈，没有实际开机或压烫。真实 API 成功不等于材料识别准确；未知材料外观判断仍有泛化风险，需要进一步做带标签耗材照片与独立评审。不能只凭一张照片推荐热压参数。
